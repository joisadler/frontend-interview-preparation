## Ментальная модель

Представьте, что другой разработчик будет вызывать вашу функцию без доступа к исходнику. Что он может ей передать? Как отличит успех от ошибки? Увидит ли изменение своего объекта? Ответы на эти вопросы образуют **договор функции (contract)**.

Например, требование «скопировать объект» оставляет выбор. Если у двух полей исходника одно общее значение, должны ли поля копии указывать на один новый объект? Чтобы проверить ответ, понадобятся две проверки на идентичность. Одна сравнит поля копии между собой, вторая сравнит их с исходным объектом.

На интервью полезно провести один крайний пример вручную до реализации. Затем назовите, что остаётся верным на каждом шаге алгоритма. Такое правило называют **инвариантом (invariant)**. В комбинаторе обещаний это может быть соответствие каждой позиции результата её позиции во входе. В копировании это соответствие исходного объекта одной уже выделенной копии.

## Связное объяснение в формате вопросов и ответов

### 🎯 1. Что уточнить перед реализацией полифила?

**Полифил (polyfill)** восполняет отсутствующий API в целевой среде. У задачи на интервью часто более узкий договор. Например, можно принимать обычные массивы и возвращать обычный массив, оставив за рамками выбор конструктора результата для подклассов. Произнесите это до кода.

В этой главе методы массива реализуются как отдельные функции. Они принимают массив и обработчик и показывают механику обхода. Для реальной поддержки старой среды нужны проверка целевых возможностей и совместимая реализация. Учебный код использует современные средства JavaScript.

### 🎯 2. Что `map` должен сохранить у разреженного массива?

`map` сохраняет длину и позиции. Обработчик запускается для существующих индексов. Пропущенный индекс остаётся пропущенным, а индекс со значением `undefined` существует и посещается.

```js
const input = [, undefined, 3];
const visited = [];
const output = input.map((value, index) => {
  visited.push(index);
  return String(value);
});
console.log(visited, output.length, 0 in output, output[1]);
// [1, 2], 3, false, "undefined"
```

Сохраните исходную длину перед циклом. При каждом посещении проверяйте существование позиции заново через `index in array`. Это учитывает удаление будущего элемента и свойства в цепочке прототипов. Если обработчик добавит элемент за исходной длиной, цикл до него не дойдёт. Аргументы обработчика идут в порядке «значение, индекс, исходный массив».

### 🎯 3. Чем обход для `filter` отличается от `map`?

Посещение индексов устроено одинаково. `filter` помещает прошедшие проверку значения подряд. Он сохраняет само значение, которое передал предикату. Это заметно, когда предикат меняет текущий элемент массива.

```js
const input = [2, , 5];
const output = input.filter((value, index, array) => {
  array[index] = 100;
  return value > 2;
});
console.log(output, input[2]);
// [5], 100
```

Считайте значение один раз до вызова предиката и используйте его же при добавлении. Для `map` и `filter` передайте согласованный `thisArg` обычному обработчику. Стрелочная функция сохранит свой лексический `this`. Контекст вызова разобран подробнее в [разделе 1.4](04-this-invocation-and-object-model.md).

### 🎯 4. Как `reduce` отличает отсутствие начального значения от `undefined`?

По числу переданных аргументов. При явном начальном значении обработчик получает его на первом существующем индексе. Если начальное значение опущено, первый существующий элемент становится аккумулятором, а обработка продолжается со следующей позиции.

```js
const input = [, 7];
let calls = 0;
const withoutInitial = input.reduce(() => { calls++; });
const withInitial = input.reduce((acc, value) => {
  calls++;
  return [acc, value];
}, undefined);
console.log(withoutInitial, withInitial, calls);
// 7, [undefined, 7], 1
```

Пустой или целиком разреженный массив без начального значения даёт `TypeError`. С явным начальным значением он возвращает это значение без вызова обработчика. Проверка `initial === undefined` смешивает эти две ветки.

### 🎯 5. Что должна запомнить простая реализация `bind`?

Для обычного вызова достаточно сохранить целевую функцию, получателя и заранее переданные аргументы. Когда обёртку вызовут, добавьте новые аргументы после сохранённых и верните результат вызова цели.

```js
function label(prefix, value) {
  return prefix + this.name + value;
}
const run = label.bind({ name: "Tea" }, "[");
console.log(run.call({ name: "Coffee" }, "]"));
// "[Tea]"
```

В учебной задаче для обычного вызова удобно применить `Reflect.apply`. Он получает функцию, получателя и массив аргументов. Вызов обёртки через `.call` меняет получателя самой обёртки. Она по-прежнему передаёт сохранённого получателя целевой функции.

### 🔬 6. Что добавляет встроенный `bind` для вызова через `new`?

Если цель можно вызвать как конструктор, связанную функцию тоже можно вызвать через `new`. Заранее переданные аргументы сохраняются, а сохранённый получатель уступает место создаваемому экземпляру. Нативная связанная функция использует специальное внутреннее поведение языка.

```js
function Point(x, y) {
  this.x = x;
  this.y = y;
}
const receiver = {};
const FixedX = Point.bind(receiver, 4);
const point = new FixedX(9);
console.log(point.x, point.y, point instanceof Point,
  point instanceof FixedX, Object.hasOwn(receiver, "x"));
// 4, 9, true, true, false
```

Наш договор для `bindCall` ограничен обычным вызовом. Стрелочная обёртка под этот договор подходит и при попытке `new` выдаёт `TypeError`. Поддержка `new.target`, наследования, `name` и `length` потребовала бы отдельно расширить задачу.

### 🎯 7. Что получают комбинаторы обещаний?

Они обходят синхронный итерируемый объект. Каждый полученный элемент проходит через `Promise.resolve`, поэтому обычное значение становится выполненным обещанием, а объект с вызываемым `then` обрабатывается по правилам обещаний. Такой объект называют **thenable**. Функции, которые запускают работу по вызову, остаются обычными значениями. Для управления запуском нужен отдельный ограничитель. См. [раздел 1.11](11-async-coordination-patterns.md).

Учебные реализации используют стандартный `Promise` и его штатные методы. Входом может быть генератор или `Set`. Поддержка собственного конструктора обещаний через `this` относится к более широкому договору встроенных статических методов.

### 🎯 8. Как `all` и `allSettled` удерживают порядок?

Запишите индекс при чтении элемента. В обработчике завершения заполняйте соответствующую ячейку. Счётчик показывает, сколько исходов осталось дождаться. Дополнительная единица в начале счётчика обозначает сам обход входа. Уберите её после цикла, чтобы обработать и пустой вход.

```js
let finishFirst;
const first = new Promise(resolve => { finishFirst = resolve; });
const second = Promise.resolve("second");
const report = Promise.all([first, second]);
await second;
finishFirst("first");
console.log(await report);
// ["first", "second"]
```

У `all` первый наблюдённый отказ отклоняет общий результат. `allSettled` сохраняет исход каждого элемента. Для успеха в записи есть `status` и `value`, для отказа есть `status` и `reason`. На пустом входе оба выполняются с пустым массивом.

### 🎯 9. Чем `race` отличается от `any`?

`race` принимает первый наблюдённый исход любого вида. `any` принимает первый успех. Когда все элементы отклонены, `any` отклоняется с `AggregateError`. Массив причин `errors` идёт в порядке входа.

```js
const inputs = [Promise.reject("denied"), Promise.resolve("allowed")];
const raced = Promise.race(inputs).catch(reason => reason);
const accepted = Promise.any(inputs);
console.log(await raced, await accepted);
// "denied", "allowed"
```

У пустого `race` ни один обработчик результата не зарегистрирован, поэтому обещание остаётся ожидающим. Пустой `any` сразу отклоняется с пустым списком причин. Завершение общего результата оставляет исходные операции работать по их собственному договору.

### 🔬 10. Почему отказ самого итератора важен?

Итератор может выдать элемент, а при следующем шаге выбросить исключение. Регистрируйте обработчики по мере чтения. Тогда ранее полученное обещание уже наблюдается к моменту отказа обхода. В учебной реализации синхронное исключение из цикла попадает в исполнитель `new Promise`, который отклоняет результат.

```js
function* inputs() {
  yield Promise.reject("item failed");
  throw new Error("iterator failed");
}
const result = await Promise.all(inputs()).catch(error => error.message);
console.log(result);
// "iterator failed"
```

Здесь исключение итератора случается при синхронном обходе. Реакция на отказ элемента выполняется позднее. Предварительный сбор всех элементов в массив отложил бы регистрацию обработчиков и мог оставить первый отказ без наблюдателя. Отличия произвольных конструкторов и переопределённых методов выходят за границы упражнения.

### 🎯 11. Как договориться о подписке на событие?

Распределитель событий (**EventEmitter**) хранит обработчики по именам событий. Уточните, что считается подпиской, в каком порядке выполняются обработчики и кто отвечает за удаление.

В нашей задаче каждый вызов `on` создаёт отдельную запись, даже если функцию передали дважды. Он возвращает функцию отписки, которая удаляет только эту запись. Повторное снятие подписки безопасно. Когда группа пустеет, удалите её из таблицы. Так долгоживущий распределитель перестаёт держать снятый обработчик через группу.

### 🎯 12. Что произойдёт при отписке или вложенной рассылке?

В начале `emit` зафиксируйте порядок текущих записей. Перед каждым вызовом проверьте, что запись ещё в группе. В нашем договоре удалённый до своей очереди обработчик пропускается. Добавленный обработчик сможет выполниться при следующем `emit`. Вложенный вызов `emit` делает новый снимок.

Подписка `once` удаляется **до** вызова обработчика. Если этот обработчик сам вызовет `emit`, вложенная рассылка уже не найдёт одноразовую запись. Синхронная ошибка обработчика выходит к вызывающему коду и останавливает текущую рассылку.

При совместимости с Node.js сверяйте его отдельный договор. В Node.js снятие подписки во время рассылки влияет на последующие рассылки, а начатая продолжает работать со своим набором обработчиков. Для события `error` у Node.js есть особое правило. [Документация Node.js 22.13.1](https://nodejs.org/download/release/v22.13.1/docs/api/events.html#emitterremovelistenereventname-listener).

### 🎯 13. Что именно хранит мемоизация?

**Мемоизация (memoization)** сохраняет результат вычисления по ключу, чтобы повторно его использовать. Проверяйте наличие через `cache.has(key)`. Значения `undefined`, `false` и `0` могут быть валидными результатами.

```js
const cache = new Map([["missing-description", undefined]]);
console.log(cache.has("missing-description"), cache.get("missing-description"));
// true, undefined
```

В упражнении функция выбора ключа и исходное вычисление получают те же аргументы и получателя, что и обёртка. Запись добавляется после успешного возврата. Синхронный выброс оставляет ключ свободным. Владелец может очистить кеш через `clear`.

### 🎯 14. Когда два вызова вправе разделить кеш?

Когда они обязаны дать одинаковый результат в пределах времени жизни записи. Для вычисления цены ключ может зависеть от товара, валюты и версии прайс-листа. Если метод читает `this`, в договоре нужен способ разделить разные экземпляры.

Для объектов `Map` сравнивает идентичность. Новый массив из тех же аргументов при каждом вызове даст новый ключ. Для строк и чисел можно использовать проверенную составную запись, например сериализовать кортеж из заранее согласованных строк и целых чисел. Универсальный `JSON.stringify` теряет различия между некоторыми входами, зависит от порядка свойств и не принимает циклы.

Отдельно обсудите время жизни кеша. Для удалённых данных обычно нужна политика обновления. Если результатом вычисления является `Promise`, обёртка из упражнения сохранит его как значение, включая отклонённое обещание. Политику удаления отказов и совместного ожидания стоит оговорить отдельно.

### 🎯 15. Как развернуть вложенные массивы?

Договор нашего `flattenArrays` — пройти массивы слева направо на всю глубину. Пустые позиции пропускаются, а явное `undefined` попадает в результат. Значения, которые сами не являются массивами, остаются целыми.

```js
const nested = [, [undefined, [4]], { id: "note" }];
console.log(nested.flat(Infinity));
// [undefined, 4, { id: "note" }]
```

Для циклов храните набор массивов в **текущей ветке** обхода. Если массив уже находится в этой ветке, вернуться к нему можно только по циклу. Если он повторится в другой ветке после выхода из первой, разворачивайте его снова. Это отличается от задачи копирования, где общую ссылку нужно сохранить.

### 🎯 16. Как выбрать результат для группировки?

Если группы задаются объектами, символами или значениями разных типов, удобно вернуть `Map`. Каждая запись хранит массив исходных элементов в порядке обхода. Ключ вычисляется один раз на элемент. Получив ключ, найдите его группу или создайте её, затем добавьте значение.

```js
const rows = [{ key: 1 }, { key: "1" }, { key: 1 }];
const groups = Map.groupBy(rows, row => row.key);
console.log(groups.size, groups.get(1).length, groups.get("1").length);
// 2, 2, 1
```

`Object.groupBy` подходит для ключей свойств. Он приводит результаты функции выбора к ключам свойств и возвращает объект без прототипа. В примере выше число и строка после такого преобразования попали бы в одну группу. В упражнении перебираем элементы через `for...of`. Пропущенная позиция обычного массива при таком обходе даёт `undefined`.

### 🎯 17. Что считать допустимым путём для `get` и `set`?

Договоритесь о формате до обхода. В этой задаче путь — массив непустых строк, например `["delivery", "region"]`. Ключ `"delivery.region"` в одном сегменте читается целиком. Благодаря этому точка внутри имени свойства не требует отдельного синтаксиса.

Обе функции читают только собственные свойства данных обычных объектов. Для отсутствующего пути `getPath` возвращает запасное значение. Существующее свойство со значением `undefined` возвращает `undefined`. Свойство с геттером обнаруживается через дескриптор и вызывает ошибку до чтения значения.

`setPath` меняет исходный объект и создаёт недостающие промежуточные записи без прототипа. Он проверяет все сегменты перед записью и отклоняет `__proto__`, `constructor` и `prototype`. Договор запрещает проход через массивы, экземпляры классов и геттеры. Для произвольных прокси, разметки путей и пользовательских схем потребуется отдельное решение.

### 🎯 18. Как копировать циклы и общие ссылки?

Смотрите на данные как на граф. Объекты — его узлы, ссылки в свойствах — связи между ними. При первом посещении объекта создайте пустую копию и сразу запишите соответствие в `WeakMap`. Затем копируйте значения свойств. Если исходный объект встретится снова, используйте уже созданную копию.

```js
const delivery = { region: "north" };
const source = { first: delivery, second: delivery };
source.self = source;
const copy = structuredClone(source);
console.log(copy !== source, copy.first === copy.second,
  copy.first !== delivery, copy.self === copy);
// true, true, true, true
```

В задаче поддерживаются примитивы, обычные объекты с прототипом `Object.prototype` или `null` и обычные массивы текущей среды. Свойства данных, включая символы и неперечисляемые свойства, переносятся с их атрибутами. Пустые позиции массива остаются пустыми. У массива сохраняются длина и её доступность для записи. Закрытый для расширения объект остаётся закрытым. Функции, геттеры, сеттеры и стандартные экземпляры вроде `Date` отклоняются. Прокси и подмена прототипа встроенного объекта находятся за границей входного договора.

### 🔬 19. Когда выбрать `structuredClone`?

Используйте встроенное структурное копирование, когда его правила совпадают с задачей. Оно умеет сохранять связи графа и поддерживает ряд встроенных типов, включая `Map` и `Date`. Договор учебного `cloneGraph` другой. Он сохраняет собственные свойства данных и их атрибуты для ограниченного набора объектов. Структурное копирование обычного объекта создаёт свойства по правилам платформы.

```js
const source = {};
Object.defineProperty(source, "visible", { value: 4, enumerable: true });
Object.defineProperty(source, "hidden", { value: 9 });
const copy = structuredClone(source);
console.log(Object.hasOwn(copy, "hidden"),
  Object.getOwnPropertyDescriptor(copy, "visible").writable);
// false, true
```

Для рабочего кода сначала проверьте список типов, передачу владения и требования к свойствам. Сериализация в JSON с последующим разбором подходит для данных, которые можно представить в JSON. Обычные циклические ссылки приводят к исключению при сериализации. [Алгоритм структурного копирования HTML](https://html.spec.whatwg.org/multipage/structured-data.html#structured-cloning).

### 🎯 20. Как объяснить сложность и проверить решение самому?

Сначала назовите, что измеряете. Для методов массива `n` — начальная длина. Цикл проверяет до `n` позиций, включая пустые. Такую верхнюю оценку записывают `O(n)`. Время самих обработчиков учитывайте отдельно. Для глубокого копирования отдельно считайте число уникальных объектов и число их собственных свойств. Общий объект копируется один раз, но его ссылки могут встречаться многократно.

Составьте проверки до реализации. Начните с обычного входа, затем проверьте пустой вход, типичное нарушение договора и самый маленький пример, который отличает ваш алгоритм от наивного. Сверяйте с нативным API только там, где договоры совпадают. Для разреженного результата проверяйте наличие свойства. Для копии проверяйте идентичность ссылок. Для асинхронного результата завершайте обещания в обратном порядке.

```js
import assert from "node:assert/strict";

const output = [, undefined].map(value => value);
assert.equal(output.length, 2);
assert.equal(Object.hasOwn(output, 0), false);
assert.equal(Object.hasOwn(output, 1), true);
assert.equal(output[1], undefined);
```

## Краткий справочник

| Задача | Инвариант | Что проверить первым |
|---|---|---|
| `map` и `filter` | Длина обхода берётся один раз, наличие позиции проверяется при посещении | Пропуск, `undefined`, удаление следующей позиции |
| `reduce` | Аккумулятор уже представляет пройденную часть | Опущенное начало и явно переданное `undefined` |
| `bindCall` | Сохранённые аргументы идут перед новыми | Получатель, возврат, исключение |
| Комбинаторы | Индекс выдачи сохраняется независимо от момента завершения | Пустой вход, обратный порядок, ошибка итератора |
| Распределитель | Одна запись на подписку | Две одинаковые функции, вложенный `emit` из `once` |
| Кеш | Один ключ соответствует согласованному вычислению | `undefined`, коллизия, очистка |
| Разворачивание и группировка | Порядок входа сохраняется | Пустая позиция, общая ссылка, ключ-объект |
| Путь и глубокая копия | Свойства и связи обрабатываются по договору | Геттер, опасный сегмент, цикл, общая ссылка |

## Типичные ошибки

- Пройти массив через `for...of`, когда нужно сохранить пропущенные индексы.
- Прочитать элемент `filter` повторно после вызова предиката.
- Выбрать начальное значение `reduce` по проверке на `undefined`.
- Добавлять результаты `all` через `push` по мере завершения.
- Удалять `once` после вызова обработчика.
- Использовать один ключ кеша для разных получателей или рассчитывать попадание по истинности значения.
- Создавать копию объекта после обхода его полей и зациклиться на ссылке назад.
- Обходить путь через обычное чтение свойства и случайно вызвать геттер.

## Как объяснить тему на интервью за 30–60 секунд

### Методы массива

«Сначала уточню, поддерживаем ли обычные массивы с пропусками. Я сохраняю начальную длину, а существование индекса проверяю перед каждым чтением. `map` оставляет исходные позиции, `filter` собирает прошедшие значения подряд. У `reduce` ветка без начала берёт первый существующий элемент, поэтому важно проверить число аргументов».

### Комбинаторы

«Я прохожу итерируемый вход и сразу наблюдаю каждый элемент через `Promise.resolve`. Для упорядоченного результата запоминаю индекс при обходе. Потом отдельно задаю условие завершения каждого комбинатора. Проверю пустой вход, ошибки итератора и обещания, которые завершаются в обратном порядке».

### Граф объектов

«Уточню типы и свойства, которые нужно копировать. Для каждого нового объекта сначала создаю пустую копию и сохраняю её в `WeakMap`. Затем заполняю свойства. Если исходный объект встретится снова, возвращаю сохранённую копию. Так сохраняются и циклы, и общие ссылки».
