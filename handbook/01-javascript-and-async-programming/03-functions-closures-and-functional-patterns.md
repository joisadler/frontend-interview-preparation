Функция в JavaScript одновременно является исполняемым кодом и обычным значением. Её можно создать во время выполнения, записать в привязку, передать в другую функцию, вернуть наружу и вызвать позже. Из этого свойства вырастают функции обратного вызова (callbacks), функции высшего порядка (higher-order functions), замыкания (closures), мемоизация (memoization) и большинство функциональных паттернов.

Эта глава строит одну последовательную модель:

```text
функция как значение
  → вызов и параметры
    → функции обратного вызова и функции высшего порядка
      → форма вызова и this
        → захват лексических привязок
          → замыкания в рабочем коде
            → функциональные паттерны и их компромиссы
```

Связь с соседними разделами:

- из 1.1 нужны привязки, лексическая область видимости и различие между объявлением функции и функциональным выражением;
- из 1.2 нужны идентичность объектов, общие ссылки и практическая неизменяемость;
- раздел 1.4 подробно разберёт объектную модель, цепочку прототипов, классы и свойства объектов.

Здесь `this`, `call` / `apply` / `bind` и `new` рассматриваются настолько глубоко, насколько нужно для понимания поведения **функций**. Поэтому группы `JS-16–JS-18` не откладываются на будущее, но полный разбор цепочки прототипов остаётся в 1.4.

## Ментальная модель

Сначала — вся тема в десяти тезисах:

1. Объект-функция имеет собственную идентичность; имя функции и привязка, в которой она хранится, — разные вещи.
2. Объявление функции (function declaration) подготавливается до построчного выполнения; функциональное выражение (function expression) создаёт функцию при вычислении выражения.
3. Параметры принадлежат определению функции, а аргументы — конкретному вызову.
4. Колбэк описывает роль функции в соглашении между вызывающим и вызываемым кодом; функция высшего порядка принимает или возвращает функцию.
5. Обычная функция получает `this` из формы вызова; стрелочная функция (arrow function) не создаёт собственный `this`.
6. `call` и `apply` вызывают сейчас; `bind` создаёт новую функцию для будущего вызова.
7. Замыкание — это функция вместе с доступом к лексическим привязкам из места её создания.
8. Замыкание сохраняет доступ к привязке, а не замороженный снимок её значения.
9. Чистая функция при одинаковых входных данных даёт одинаковый наблюдаемый результат и не создаёт внешних побочных эффектов.
10. Каррирование, частичное применение и композиция полезны, когда делают поток данных яснее; сами по себе они не улучшают код.

Три разных ориентира:

- **функция как значение** похожа на маршрут, который можно сохранить и передать, не проезжая его прямо сейчас;
- **колбэк** похож на номер для обратного звонка: вместе с ним передаётся возможность вызвать функцию позже и соглашение о том, когда и с какими данными это произойдёт;
- **замыкание** похоже на доступ к живому рабочему документу: функция возвращается, но по-прежнему читает связанные с ней привязки, а не фотографию старых данных.

Каждая аналогия объясняет только свой механизм. Ни одна из них не заменяет правила вызова JavaScript.

## Связное объяснение в формате вопросов и ответов

### 🎯 1. Какие формы создания функций есть в JavaScript?

Четыре формы встречаются чаще всего:

```js
function declarationExample(value) {
  return value * 2;
}

const expressionExample = function (value) {
  return value * 2;
};

const namedExpressionExample = function double(value) {
  return value * 2;
};

const arrowExample = (value) => value * 2;
```

Во всех четырёх случаях создаётся вызываемый объект — объект-функция (function object). Но синтаксическая форма влияет на:

- момент создания функции;
- доступность до строки исходного кода;
- внутреннее имя;
- наличие собственного `this`, `arguments` и `new.target`;
- возможность вызова через `new`.

| Форма | Когда создаётся функция | Собственный `this` / `arguments` | `new` |
|---|---|---:|---:|
| объявление функции (function declaration) | при подготовке текущего кода | да | обычно да |
| анонимное функциональное выражение (anonymous function expression) | при вычислении выражения | да | обычно да |
| именованное функциональное выражение (named function expression) | при вычислении выражения | да; есть внутреннее имя | обычно да |
| стрелочная функция (arrow function) | при вычислении выражения | нет | нет |

Слово «обычно» здесь существенно: возможность вызова через `new` зависит от конкретного вида функции. Например, краткая запись метода в объекте и генератор не являются конструкторами. Для интервью в рамках 1.3 нужна основная граница: обычное объявление функции или функциональное выражение обычно можно вызвать через `new`, а стрелочную функцию — никогда.

#### Функция, имя и привязка — разные вещи

```js
function load() {}

const first = load;
const second = first;

console.log(first === second); // true
```

`load` — привязка, которая содержит функцию как значение. `first` и `second` получают то же самое значение, то есть у всех трёх имён одна и та же функция. Присваивание не клонирует её код.

Анонимная функция часто получает предполагаемое имя из позиции, в которую её записали:

```js
const loadUser = function () {};
const saveUser = () => {};

console.log(loadUser.name); // "loadUser"
console.log(saveUser.name); // "saveUser"
```

Такое имя улучшает трассировку стека, но логика приложения не должна зависеть от `function.name`: сборщики и минификаторы могут менять имена.

### 🎯 2. Чем объявление функции отличается от функционального выражения по времени?

Объявление функции связывает имя с готовым объектом-функцией во время подготовки объявлений текущего скрипта, модуля или тела функции. Поэтому функцию можно вызвать раньше строки, на которой она объявлена:

```js
console.log(format("ada")); // "ADA"

function format(value) {
  return value.toUpperCase();
}
```

Функциональное выражение создаёт функцию только тогда, когда выполнение доходит до самого выражения:

```js
// console.log(format("ada")); // ReferenceError: binding format в TDZ

const format = function (value) {
  return value.toUpperCase();
};
```

С `var` ошибка другая:

```js
// format("ada"); // TypeError: format is not a function
var format = function (value) {
  return value.toUpperCase();
};
```

До присваивания привязка `format` уже содержит `undefined`. Имя успешно находится, но его текущее значение нельзя вызвать как функцию.

Краткая связь с 1.1:

```text
объявление функции → привязка сразу содержит готовую функцию
var + выражение     → привязка содержит undefined; функция появится при присваивании
let/const + выражение → привязка в TDZ; функция появится при инициализации
```

Выбор в рабочем коде не сводится к вопросу «что лучше». Объявление функции хорошо подчёркивает именованную операцию верхнего уровня и позволяет расположить файл в логическом порядке. Функциональное выражение подчёркивает, что функция создаётся и присваивается как обычное значение во время выполнения. Важнее соблюдать единый стиль модуля и делать момент создания функции понятным.

### 🎯 3. Зачем нужно именованное функциональное выражение и где видно его имя?

Именованное функциональное выражение даёт созданной функции собственное локальное имя:

```js
const factorial = function calculate(n) {
  if (n <= 1) return 1;
  return n * calculate(n - 1);
};

console.log(factorial(5)); // 120
console.log(typeof calculate); // "undefined"
```

Привязка `factorial` видна во внешней области. Имя `calculate` доступно только внутри тела этой функции. Оно полезно для:

- рекурсии, которая не зависит от внешней привязки;
- понятной трассировки стека;
- самоссылки, которая не сломается после переназначения внешней переменной.

```js
let run = function original() {
  return original.name;
};

const saved = run;
run = null;

console.log(saved()); // "original"
```

Внутреннее имя не «просачивается» наружу:

```js
const handler = function onMessage() {};

console.log(handler.name); // "onMessage"
console.log(typeof onMessage); // "undefined"
```

🔬 Для внутреннего имени создаётся отдельная привязка, принадлежащая самому функциональному выражению. Код тела не должен её переназначать. На интервью достаточно правила: «имя видно внутри функции и не видно снаружи».

### 🎯 4. Чем стрелочная функция отличается от обычной функции?

Стрелочная функция — не просто короткая запись обычной функции. У неё другая семантика вызова.

```js
const double = (value) => value * 2;
const makeUser = (name) => ({ name });
```

Круглые скобки вокруг литерала объекта нужны потому, что без них фигурные скобки разбираются как тело функции:

```js
const wrong = () => { id: 1 };
const right = () => ({ id: 1 });

console.log(wrong()); // undefined
console.log(right()); // { id: 1 }
```

Стрелочная функция:

- не создаёт собственный `this`;
- не создаёт собственный `arguments`;
- не создаёт собственный `super` или `new.target`;
- не имеет `[[Construct]]` и не вызывается через `new`;
- не имеет обычного свойства `prototype`;
- не может быть функцией-генератором.

Обычная функция:

- получает `this` из формы вызова;
- имеет собственный `arguments`;
- может поддерживать вызов через `new`, если у этого вида функции есть внутренний метод `[[Construct]]`;
- подходит для метода с получателем, определяемым при вызове, и для функции-конструктора.

Практическое правило:

| Намерение | Обычно выбирают |
|---|---|
| небольшое преобразование или колбэк без собственного получателя вызова | стрелочная функция |
| метод, которому нужен получатель конкретного вызова | краткая запись метода или обычная функция |
| функция-конструктор | обычная функция или `class` |
| лексический `this` внутри внешнего метода | стрелочный колбэк |
| нужен собственный `arguments` | обычная функция, хотя остаточные параметры обычно яснее |

Не выбирайте стрелочную функцию только ради короткого синтаксиса. Сначала решите, нужен ли функции собственный контекст вызова.

### 🎯 5. Чем параметры отличаются от аргументов?

**Параметры (parameters)** — привязки, перечисленные в определении функции. **Аргументы (arguments)** — значения, переданные при конкретном вызове.

```js
function greet(name, punctuation) { // параметры
  return name + punctuation;
}

greet("Ada", "!"); // аргументы
```

JavaScript не требует совпадения количества:

```js
function pair(first, second) {
  return [first, second];
}

pair("A");             // ["A", undefined]
pair("A", "B", "C");   // ["A", "B"]; лишний аргумент не связан с параметром
```

При каждом вызове для параметров создаются новые локальные привязки. Аргументы передаются по значению, как разобрано в 1.2:

```js
function update(user) {
  user.name = "Grace";       // мутация общего объекта
  user = { name: "Lin" };    // переназначение локальной привязки параметра
}
```

Параметры описывают интерфейс функции. Поэтому длинный список позиционных аргументов быстро становится хрупким:

```js
createRequest("/users", "POST", true, 3, false);
```

Если необязательных настроек несколько, объект обычно читается яснее:

```js
createRequest("/users", {
  method: "POST",
  retries: 3,
  cache: false,
});
```

### 🔬 6. Как вычисляются параметры по умолчанию и где они видны?

Параметр по умолчанию (default parameter) применяется, если аргумент пропущен или равен именно `undefined`:

```js
function label(value = "unknown") {
  return value;
}

label();          // "unknown"
label(undefined); // "unknown"
label(null);      // null
label("");        // ""
```

Выражение справа от `=` вычисляется **при каждом вызове**, когда значение по умолчанию действительно нужно:

```js
let nextId = 0;

function createRecord(id = ++nextId) {
  return { id };
}

createRecord();  // { id: 1 }
createRecord();  // { id: 2 }
createRecord(9); // { id: 9 }; ++nextId не вычисляется
```

Параметры инициализируются слева направо. Значение по умолчанию для более позднего параметра может читать уже инициализированный ранний параметр:

```js
function range(start, end = start + 1) {
  return [start, end];
}

range(5); // [5, 6]
```

Но ранний параметр не может прочитать более поздний до его инициализации:

```js
function broken(first = second, second = 2) {
  return [first, second];
}

// broken(); // ReferenceError
```

Если в списке параметров есть значение по умолчанию, остаточный параметр или деструктуризация, для него создаётся отдельное окружение. Оно находится снаружи окружения тела функции, поэтому выражение по умолчанию не видит объявления из тела:

```js
function build(value = helper()) {
  function helper() {
    return 1;
  }

  return value;
}

// build(); // ReferenceError: helper is not defined
```

Это намеренно неработающий пример: ошибка `ReferenceError` возникает во время вызова, а не при разборе кода.

#### Практические ловушки

1. Значение по умолчанию не заменяет проверку входных данных:

```js
function setRetries(count = 3) {
  return count;
}

setRetries(null); // null, не 3
```

2. Объект или массив по умолчанию создаётся заново при каждом вызове:

```js
function collect(items = []) {
  items.push("x");
  return items;
}

console.log(collect()); // ["x"]
console.log(collect()); // ["x"], это уже другой массив
```

3. Параметру с деструктуризацией нужно внешнее значение по умолчанию, если весь аргумент может отсутствовать:

```js
function connect({ timeout = 1000 } = {}) {
  return timeout;
}

connect(); // 1000
```

В рабочем коде значение по умолчанию должно выражать контракт функции, а не маскировать недопустимые данные или неожиданный `null`.

### 🎯 7. Чем остаточные параметры отличаются от `arguments`?

Остаточный параметр (rest parameter) собирает оставшиеся аргументы в настоящий массив:

```js
function log(level, ...messages) {
  return {
    level,
    messages,
    isArray: Array.isArray(messages),
  };
}

log("info", "started", "ready");
// { level: "info", messages: ["started", "ready"], isArray: true }
```

Остаточный параметр:

- должен быть последним параметром;
- может быть только один;
- всегда создаёт массив, даже если значений нет;
- собирает только аргументы после именованных параметров;
- не может иметь значения по умолчанию.

`arguments` — массивоподобный объект со всеми аргументами конкретного вызова обычной функции:

```js
function inspect(first) {
  return {
    first,
    passed: arguments.length,
    secondArgument: arguments[1],
    isArray: Array.isArray(arguments),
  };
}

inspect("A", "B");
// { first: "A", passed: 2, secondArgument: "B", isArray: false }
```

Сравнение:

| Свойство | остаточный параметр `...args` | `arguments` |
|---|---|---|
| Тип | `Array` | массивоподобный и итерируемый объект |
| Что содержит | оставшиеся аргументы | все переданные аргументы |
| Стрелочная функция | работает | собственного объекта нет |
| Методы массива | доступны напрямую | обычно нужен `Array.from` или spread-синтаксис |
| Современный код | предпочтительный явный интерфейс | совместимость и редкие универсальные обёртки |

Стрелочная функция читает `arguments` из ближайшей внешней обычной функции, если такая привязка существует:

```js
function outer(value) {
  const read = () => arguments[0];
  return read();
}

outer("outer argument"); // "outer argument"
```

Это легко ошибочно принять за собственный `arguments` стрелочной функции. Для самостоятельного колбэка лучше явно объявить остаточный параметр:

```js
const collect = (...args) => args;
```

<details>
<summary>🧓 Legacy: связь параметров с `arguments` в нестрогом режиме</summary>

В обычной функции без строгого режима и со списком простых параметров именованные параметры могут быть связаны с соответствующими элементами `arguments`:

```js
function legacy(value) {
  value = 2;
  return arguments[0];
}

legacy(1); // 2 в нестрогом режиме
```

В строгом режиме и при сложном списке параметров такой связи нет. Не стройте современный код на синхронизации параметров с `arguments`.

`arguments.callee` также запрещён в строгом режиме; именованное функциональное выражение даёт функции безопасную ссылку на саму себя.

</details>

### 🔬 8. Что такое арность и что показывает `Function.prototype.length`?

**Арность (arity)** — ожидаемое число операндов или параметров функции. В обсуждении архитектуры этим словом часто описывают контракт функции, но свойство `fn.length` использует более узкое синтаксическое правило.

`fn.length` считает формальные параметры **до первого параметра со значением по умолчанию**. Остаточный параметр не учитывается. Каждый шаблон деструктуризации считается одним параметром.

```js
function a(first, second) {}
function b(first, second = 2, third) {}
function c(first, ...rest) {}
function d({ id }, [start, end]) {}

console.log(a.length); // 2
console.log(b.length); // 1
console.log(c.length); // 1
console.log(d.length); // 2
```

Сравните три разных числа:

```js
function example(first, second = 2, ...rest) {
  return {
    declaredBeforeDefault: example.length,
    actuallyPassed: arguments.length,
    collectedInRest: rest.length,
  };
}

example("A", undefined, "C", "D");
// { declaredBeforeDefault: 1, actuallyPassed: 4, collectedInRest: 2 }
```

Некоторые библиотеки используют `length` для выбора способа вызова или автоматического каррирования по соглашению. Это хрупкий источник сведений: значения по умолчанию, `bind`, обёртки и транспиляция меняют результат. Контракт рабочего API лучше описывать типами и документацией, а входные данные при необходимости проверять во время выполнения.

### 🎯 9. Что значит «функция первого класса» и что делает функция высшего порядка?

Функции в JavaScript являются **значениями первого класса (first-class values)**: с ними можно делать то же, что с другими значениями.

```js
function normalize(value) {
  return value.trim().toLowerCase();
}

const operation = normalize;        // сохранить
const operations = [normalize];     // положить в коллекцию
runLater(normalize);                // передать
```

**Функция обратного вызова (callback), или колбэк,** передаётся другому коду, чтобы тот вызвал её по своему контракту.

```js
const names = [" Ada ", " GRACE "];
const normalized = names.map((name) => name.trim().toLowerCase());
```

`map` решает, **когда** и **сколько раз** вызывать колбэк, какие аргументы ему передать и как использовать возвращённое значение.

**Функция высшего порядка (higher-order function, HOF)** принимает другую функцию, возвращает функцию или делает и то и другое:

```js
function withLogging(operation) {
  return function logged(...args) {
    console.log("start", args);
    const result = operation(...args);
    console.log("done", result);
    return result;
  };
}
```

Здесь `withLogging` принимает функцию как значение и возвращает новую функцию. Возвращённая функция образует замыкание над параметром `operation` и поэтому может вызвать его позже.

### 🎯 10. Что именно входит в контракт колбэка?

Недостаточно знать, что «сюда передаётся функция». Для надёжного колбэка нужно выяснить:

1. Кто вызывает колбэк?
2. Сколько раз?
3. Синхронно или позже?
4. Какие аргументы и `this` он получает?
5. Как используется возвращаемое значение?
6. Как передаются ошибки?
7. Как отменить регистрацию и кто хранит ссылку на функцию?

```js
["10", "20", "30"].map(parseInt);
// [10, NaN, NaN]
```

Почему? `map` вызывает колбэк как `callback(value, index, array)`, а `parseInt` воспринимает второй аргумент как основание системы счисления (`radix`):

```js
parseInt("10", 0); // 10
parseInt("20", 1); // NaN
parseInt("30", 2); // NaN
```

Исправление вводит небольшую функцию-адаптер и явно согласует два контракта:

```js
["10", "20", "30"].map((value) => Number.parseInt(value, 10));
```

Ещё одна ловушка — случайно **вызвать** функцию вместо того, чтобы передать её:

```js
button.addEventListener("click", save);   // передали функцию
button.addEventListener("click", save()); // вызвали сейчас и передали результат
```

При проверке рабочего кода сначала разбирайте контракт колбэка, а не длину записи стрелочной функции.

### 🎯 11. Откуда обычная функция получает `this`?

У обычной функции `this` обычно определяется **формой текущего вызова**, а не местом определения и не объектом, в котором функция первоначально хранилась.

```js
"use strict";

function describe() {
  return this?.name;
}

const user = { name: "Ada", describe };

console.log(user.describe());                 // "Ada": вызов метода
console.log(describe.call({ name: "Lin" })); // "Lin": явный this
console.log(describe());                      // undefined: обычный вызов в strict mode
```

Для понимания поведения функций достаточно четырёх основных форм:

| Форма вызова | Откуда `this` |
|---|---|
| `fn()` | обычный вызов; в строгом режиме `this` равен `undefined` |
| `obj.fn()` | объект слева от точки, то есть `obj` |
| `fn.call(x, ...)` / `apply` | явно переданный `x` |
| `new Fn(...)` | создаваемый экземпляр |

`this` в обычной функции не является обычным лексическим идентификатором. Его значение нельзя определить, посмотрев только на место объявления функции:

```js
function readName() {
  return this.name;
}

const first = { name: "first", readName };
const second = { name: "second", readName };

first.readName();  // "first"
second.readName(); // "second"
```

Стрелочная функция не подчиняется этой таблице: она использует лексический `this` внешнего контекста выполнения.

### 🎯 12. Почему метод теряет контекст при передаче как колбэк?

Выражение `obj.method` получает функцию как значение. Если затем вызвать это значение в форме `callback()`, объекта слева от точки уже не будет.

```js
"use strict";

const counter = {
  value: 2,
  increment(step) {
    this.value += step;
  },
};

const callback = counter.increment;
// callback(1); // TypeError: this === undefined
```

Функция ничего не «забыла» и объект от неё не «отвязался». Изменилась форма вызова:

```text
counter.increment(1) → слева от точки counter → this = counter
callback(1)          → обычный вызов           → this = undefined в strict mode
```

Практические способы сохранить намерение:

```js
counter.increment(1);                         // вызвать как метод
counter.increment.call(counter, 1);          // вызвать сразу с явным this
const bound = counter.increment.bind(counter);
bound(1);                                    // привязанный колбэк для повторных вызовов
const adapter = (step) => counter.increment(step);
adapter(1);                                  // адаптер читает привязку counter
```

Выбор зависит от жизненного цикла функции:

- разовый вызов → `call` или `apply`;
- колбэк нужно передать и вызвать позже → один сохранённый результат `bind`;
- нужно читать текущее значение переменной с объектом → стрелочный адаптер;
- API принимает контекст отдельным аргументом → следуйте его контракту.

При регистрации DOM-события важна идентичность функции:

```js
const boundClick = controller.onClick.bind(controller);

button.addEventListener("click", boundClick);
button.removeEventListener("click", boundClick); // та же самая функция
```

Два отдельных вызова `bind` создадут две разные функции, поэтому снятие обработчика не найдёт первую.

### 🎯 13. Как связаны `call`, `apply` и `bind`?

Все три метода работают с вызываемой функцией и позволяют явно задать получателя вызова, то есть значение `this`. Главное различие — **когда происходит вызов** и **как передаются аргументы**.

| API | Вызывает сейчас? | Аргументы | Результат |
|---|---:|---|---|
| `fn.call(thisArg, a, b)` | да | отдельным списком | результат `fn` |
| `fn.apply(thisArg, [a, b])` | да | массивоподобное значение | результат `fn` |
| `fn.bind(thisArg, a)` | нет | сохраняет первые аргументы | новая привязанная функция |

```js
function format(greeting, punctuation) {
  return greeting + ", " + this.name + punctuation;
}

const user = { name: "Ada" };

format.call(user, "Hello", "!");          // "Hello, Ada!"
format.apply(user, ["Hello", "!"]);       // "Hello, Ada!"
const greetAda = format.bind(user, "Hello");
greetAda("!");                            // "Hello, Ada!"
```

Запомнить можно так:

```text
call  → вызвать сейчас, аргументы перечислить
apply → вызвать сейчас, аргументы передать вместе
bind  → подготовить новую функцию для будущего вызова
```

Но для интервью этого недостаточно. Следующие два вопроса подробно разбирают выбор между методами, идентичность созданной функции и поведение при вызове через `new`.

### 🎯 14. Когда выбирать `call`, а когда `apply`?

Оба метода немедленно вызывают исходную функцию и возвращают её результат. Различается только способ передачи аргументов.

```js
function total(taxRate, discount) {
  const subtotal = this.items.reduce((sum, item) => sum + item.price, 0);
  return subtotal * (1 + taxRate) - discount;
}

const order = {
  items: [{ price: 10 }, { price: 20 }],
};

console.log(total.call(order, 0.2, 5));       // 31
console.log(total.apply(order, [0.2, 5]));    // 31
```

Выбирайте `call`, когда аргументы известны как отдельные выражения. `apply` удобен, когда они уже собраны в массивоподобном значении:

```js
const argsLike = { 0: 0.2, 1: 5, length: 2 };
total.apply(order, argsLike); // 31
```

Современный spread-синтаксис часто заменяет `apply` именно в части передачи аргументов:

```js
const args = [0.2, 5];

total.apply(order, args);
total.call(order, ...args);
```

Точная разница: `apply` принимает массивоподобный объект, а spread в позиции вызова требует итерируемое значение. Обычный массив подходит в обоих случаях, а пользовательский массивоподобный объект может не быть итерируемым.

#### Заимствование методов и универсальные операции

`call` позволяет применить операцию к явно выбранному получателю без временного добавления свойства:

```js
const hasOwn = Function.prototype.call.bind(
  Object.prototype.hasOwnProperty,
);

console.log(hasOwn({ id: 1 }, "id")); // true
```

В новом коде для этой конкретной задачи яснее `Object.hasOwn(object, key)`. Но пример показывает главное: `call` задаёт получателя вызова, а не «копирует метод» в другой объект.

#### Что произойдёт с `thisArg`?

В обычной функции со строгим режимом `thisArg` используется без преобразований:

```js
function strictReceiver() {
  "use strict";
  return this;
}

strictReceiver.call(null); // null
```

В функции без строгого режима `null` и `undefined` заменяются глобальным объектом, а примитивы оборачиваются в объекты. Это устаревшее поведение, на которое не должен опираться современный код модулей и строгого режима.

У стрелочной функции `thisArg` игнорируется, потому что она не создаёт собственного `this`. При этом аргументы передаются как обычно:

```js
function makeReader() {
  return (prefix) => prefix + ":" + this.name;
}

const reader = makeReader.call({ name: "outer" });

reader.call({ name: "ignored" }, "value"); // "value:outer"
```

#### Где `call` / `apply` не подходят?

- Они не создают колбэк для повторного использования: вызов происходит сразу.
- Не используйте `call` для имитации наследования классов: конструктор класса нельзя вызвать без `new`, а значение `new.target` будет другим.
- Не передавайте огромный массив из ненадёжного источника через `apply` или spread: движок ограничивает число аргументов одного вызова. Большие наборы данных обрабатывайте итерацией или свёрткой.
- Если функция вообще не читает `this`, явный `thisArg` обычно только создаёт шум.

### 🎯 15. Что именно делает `bind` и почему он возвращает новую функцию?

`bind` подготавливает функцию для будущего вызова. Поэтому он создаёт **новый объект привязанной функции (bound function)**, который хранит:

- исходную функцию;
- привязанное значение `thisArg`;
- ноль или несколько заранее переданных первых аргументов.

```js
function multiply(scale, value) {
  return this.offset + scale * value;
}

const context = { offset: 1 };
const doubleFromOne = multiply.bind(context, 2);

console.log(doubleFromOne(5)); // 11
```

Для первого приближения `bind` можно представить такой обёрткой:

```js
function approximateBind(target, thisArg, ...boundArgs) {
  return function (...callArgs) {
    return target.call(thisArg, ...boundArgs, ...callArgs);
  };
}
```

Эта модель правильно объясняет обычный вызов. Встроенная привязанная функция ведёт себя точнее: она сохраняет способность исходной функции работать как конструктор и по особым правилам получает свойства `name` и `length`.

#### Почему меняется идентичность?

Новый объект нужен потому, что одна исходная функция может породить несколько независимо настроенных функций:

```js
const first = multiply.bind({ offset: 1 }, 2);
const second = multiply.bind({ offset: 10 }, 3);

console.log(first === second); // false
console.log(first === multiply); // false
```

Из этого следует важное правило для рабочего кода:

```js
button.addEventListener("click", controller.handle.bind(controller));
button.removeEventListener("click", controller.handle.bind(controller));
// обработчик не снимется: второй bind создал другую функцию
```

Нужно сохранить одну ссылку:

```js
const onClick = controller.handle.bind(controller);

button.addEventListener("click", onClick);
button.removeEventListener("click", onClick);
```

#### Как объединяются заранее привязанные и новые аргументы?

Заранее привязанные аргументы идут первыми:

```js
function list(...values) {
  return values;
}

const withPrefix = list.bind(null, "fixed");
withPrefix("runtime", "last");
// ["fixed", "runtime", "last"]
```

Повторный `bind` не заменяет уже привязанный `this`, но добавляет новые аргументы после привязанных раньше:

```js
function describe(a, b) {
  return [this.name, a, b];
}

const once = describe.bind({ name: "first" }, "A");
const twice = once.bind({ name: "second" }, "B");

console.log(twice()); // ["first", "A", "B"]
```

Это частая ловушка на интервью: получатель вызова уже закреплён первой привязанной функцией.

#### Что происходит с `length` и `name`?

`bind` создаёт наблюдаемую обёртку:

```js
function task(first, second, third) {}

const prepared = task.bind(null, "fixed");

console.log(task.length);     // 3
console.log(prepared.length); // 2
console.log(prepared.name);   // "bound task"
```

Значение `length` привязанной функции примерно равно `max(target.length - boundArgsCount, 0)`. Это ещё одна причина не считать `length` надёжным описанием интерфейса во время выполнения.

#### `bind` и стрелочная функция

`bind` всё равно возвращает новую функцию и может закрепить аргументы, но не может заменить лексический `this` стрелочной функции:

```js
function makeArrow() {
  return (value) => [this.name, value];
}

const arrow = makeArrow.call({ name: "outer" });
const rebound = arrow.bind({ name: "ignored" }, 10);

rebound(); // ["outer", 10]
```

Практический выбор между привязанным методом и стрелочным адаптером:

- `method.bind(object)` фиксирует текущий объект как получателя вызова;
- `(...args) => object.method(...args)` захватывает привязку `object` и читает её текущее значение при каждом вызове;
- оба варианта создают новую функцию и могут удерживать захваченный граф объектов;
- для снятия регистрации нужно сохранить именно ту ссылку, которая была передана API.

### 🔬 16. Что делает `new` и почему стрелочная функция не является конструктором?

Оператор `new` использует внутреннюю возможность функции создавать экземпляры — `[[Construct]]`. Для понимания поведения функции достаточно такой упрощённой модели:

1. создаётся новый объект;
2. объект связывается с `Constructor.prototype`;
3. конструктор вызывается с `this`, равным новому объекту;
4. если конструктор явно вернул объект, результатом становится этот объект; возвращённый примитив игнорируется;
5. иначе результатом становится объект, созданный на первом шаге.

```js
function User(name) {
  this.name = name;
}

const user = new User("Ada");
console.log(user.name); // "Ada"
```

Эта модель нужна здесь только для понимания поведения функции. Полные связи конструктора с прототипом, `Object.create`, классы и наследование остаются в 1.4.

У стрелочной функции есть внутренний метод `[[Call]]`, но нет `[[Construct]]`:

```js
const User = (name) => ({ name });

// Намеренно ошибочный пример:
// new User("Ada"); // TypeError: User is not a constructor
```

Стрелочная функция не получает новый `this` и не имеет обычного свойства `prototype`, поэтому она не может заменить функцию-конструктор.

#### Привязанная функция с `new`

Если исходную функцию можно использовать как конструктор, привязанную функцию тоже можно вызвать через `new`. В этом случае сохранённый `thisArg` игнорируется, потому что `new` создаёт нового получателя вызова, а заранее привязанные аргументы сохраняются:

```js
function Point(x, y) {
  this.x = x;
  this.y = y;
}

const YAxisPoint = Point.bind({ ignored: true }, 0);
const point = new YAxisPoint(5);

console.log(point.x, point.y); // 0 5
console.log(point instanceof Point); // true
```

Если исходную функцию нельзя вызвать через `new`, `bind` не добавляет ей такую возможность:

```js
const arrow = () => {};
const boundArrow = arrow.bind(null);

// Намеренно ошибочный пример:
// new boundArrow(); // TypeError
```

В рабочем коде используйте `class` или явно названную фабрику, если API создаёт экземпляры. Знание функций-конструкторов и привязанных конструкторов важно для интервью и поддержки старого кода, но не оправдывает сложную объектную модель, собранную вручную.

### 🎯 17. Что такое замыкание и когда оно создаётся?

**Замыкание (closure)** — функция вместе с доступом к лексическому окружению, в котором она была создана. Функция получает этот доступ при создании; специальное ключевое слово не требуется.

```js
function makeGreeting(prefix) {
  return function greet(name) {
    return prefix + ", " + name;
  };
}

const welcome = makeGreeting("Welcome");
console.log(welcome("Ada")); // "Welcome, Ada"
```

После завершения `makeGreeting` её кадр стека больше не активен. Но возвращённая функция всё ещё достижима и использует привязку `prefix`, поэтому нужное состояние лексического окружения сохраняется.

Важно разделить:

- **область видимости (scope)** определяет, где имя можно найти по структуре исходного кода;
- **стек вызовов (call stack)** хранит активные незавершённые вызовы;
- **замыкание** позволяет последующему вызову обратиться к привязкам из места создания функции, даже когда внешний вызов уже завершён.

Замыкание не означает, что движок обязан скопировать всю внешнюю область. Практическая модель проще: функция сохраняет доступ к нужному лексическому окружению, а движок может оптимизировать его внутреннее представление.

### 🎯 18. Замыкание сохраняет снимок значения или живую привязку?

Замыкание захватывает **привязку**, а не замороженный снимок значения.

```js
function makeCounter() {
  let count = 0;

  return {
    increment() {
      count += 1;
    },
    read() {
      return count;
    },
  };
}

const counter = makeCounter();
counter.increment();
counter.increment();

console.log(counter.read()); // 2
```

`increment` и `read` разделяют одну привязку `count`. Первый метод меняет её текущее значение, второй читает новое.

#### Переназначение привязки и мутация захваченного объекта

```js
function makeState() {
  let state = { count: 0 };

  return {
    mutate() {
      state.count += 1;
    },
    replace() {
      state = { count: 100 };
    },
    read() {
      return state;
    },
  };
}
```

- `mutate` изменяет объект, на который сейчас указывает привязка `state`;
- `replace` перенаправляет саму привязку на новый объект;
- `read` при каждом вызове читает текущее значение привязки.

Если нужен снимок, его создают явно:

```js
let mode = "light";
const capturedBinding = () => mode;
const snapshot = mode;
const capturedValue = () => snapshot;

mode = "dark";

capturedBinding(); // "dark"
capturedValue();   // "light"
```

Отсюда возникают два класса ошибок:

- разработчик ожидал старое значение, а замыкание видит новое;
- разработчик ожидал новое значение, но сам сохранил отдельный снимок или копию.

На интервью сначала укажите конкретную привязку, затем перечислите, кто её меняет и в какой момент вызывается замыкание.

### 🎯 19. Как замыкания реализуют фабрики, инкапсуляцию и закрытое состояние?

**Фабрика (factory)** создаёт и возвращает настроенную функцию или объект. Каждый вызов фабрики создаёт отдельный набор привязок.

```js
function createCounter(initial = 0) {
  let value = initial;

  return {
    increment(step = 1) {
      value += step;
      return value;
    },
    read() {
      return value;
    },
  };
}

const first = createCounter(0);
const second = createCounter(10);

first.increment();  // 1
second.increment(); // 11
first.read();       // 1
```

`value` нельзя прочитать или переназначить напрямую снаружи. Возвращённые методы образуют контролируемый интерфейс к закрытому состоянию.

Плюсы:

- состояние скрыто за небольшим API;
- инварианты можно проверять в одном месте;
- фабрика легко создаёт независимые экземпляры;
- для простой локальной абстракции не требуется знание прототипов.

Компромиссы:

- каждый экземпляр получает собственные объекты-функции;
- замыкания могут удерживать больше состояния, чем планировалось;
- скрытое состояние может усложнить сериализацию, отладку и тестирование;
- если состояние разделяется между несколькими замыканиями, их общий жизненный цикл должен быть очевидным.

Закрытое состояние через замыкание не является универсальной заменой приватных полей класса. Выбор зависит от требуемой идентичности объектов, совместного использования методов, инструментов и формы API. Полное сравнение с объектной моделью будет в 1.4.

### 🎯 20. Как мемоизация использует замыкание и когда кеш становится проблемой?

**Мемоизация (memoization)** сохраняет результат для уже встречавшихся входных данных, чтобы не повторять вычисление.

```js
function memoizeUnary(operation) {
  const cache = new Map();

  return function memoized(input) {
    if (cache.has(input)) {
      return cache.get(input);
    }

    const result = operation(input);
    cache.set(input, result);
    return result;
  };
}
```

Замыкание сохраняет `cache` между вызовами. Но для корректной мемоизации недостаточно просто добавить `Map`:

1. Операция должна быть детерминированной для выбранного ключа кеша.
2. Правило сравнения ключей должно совпадать с семантикой предметной области.
3. Нужно решить, кэшировать ли ошибки и отклонённые промисы.
4. Изменяемый объект-ключ может изменить содержимое, сохранив прежнюю идентичность.
5. У роста кеша должны быть предел и понятный жизненный цикл, включая удаление записей.
6. Для устаревающих данных нужны правила сброса или обновления.

Неограниченная мемоизация уникальных входных данных превращает ускорение в проблему удержания памяти:

```js
const getReport = memoizeUnary(buildLargeReport);

for (const request of requests) {
  getReport(request.id); // кеш растёт, если идентификаторы не повторяются
}
```

Практические варианты:

- ограниченный LRU-кеш;
- время жизни записи (TTL) и явный сброс;
- кеш с жизненным циклом запроса, компонента или пользовательского сеанса;
- `WeakMap` для ключей-объектов, если подходит сравнение по идентичности и не нужен перебор записей;
- отказ от мемоизации, если повторные попадания редки или вычисление дёшево.

Мемоизация — осознанная политика производительности, а не бесплатная обёртка.

### 🎯 21. Почему замыкания в цикле с `var` часто видят одно итоговое значение?

`var` создаёт одну привязку на уровне функции. Все колбэки замыкаются над ней, а выполняются уже после завершения цикла:

```js
const callbacks = [];

for (var i = 0; i < 3; i += 1) {
  callbacks.push(() => i);
}

console.log(callbacks.map((read) => read())); // [3, 3, 3]
```

Три функции разные, но привязка `i` у них одна. К моменту вызовов её значение равно `3`.

`let` в цикле `for` создаёт отдельную привязку для каждой итерации:

```js
const callbacks = [];

for (let i = 0; i < 3; i += 1) {
  callbacks.push(() => i);
}

console.log(callbacks.map((read) => read())); // [0, 1, 2]
```

Правильная формулировка: «`let` создаёт отдельную привязку для каждой итерации», а не «`let` магически копирует значение».

Если нужно исправить старый код с `var`, фабрика или немедленно вызываемое функциональное выражение (IIFE) создаёт отдельную привязку параметра для каждой итерации:

```js
for (var i = 0; i < 3; i += 1) {
  callbacks.push(
    ((snapshot) => () => snapshot)(i),
  );
}
```

В современном коде `let`, `const` и декларативный перебор читаются яснее. IIFE важно узнавать в старом коде.

### 🎯 22. Как замыкание удерживает память и когда это становится утечкой?

Сборщик мусора освобождает недостижимые объекты. Если долгоживущий колбэк остаётся достижимым через обработчик события, таймер, подписку или кеш, его замыкание может сохранить путь к внешнему состоянию.

```js
function attachPreview(button, largeModel) {
  function onClick() {
    renderPreview(largeModel.summary);
  }

  button.addEventListener("click", onClick);

  return () => {
    button.removeEventListener("click", onClick);
  };
}
```

Цепочка достижимости:

```text
button / реестр событий
  → функция onClick
    → окружение замыкания
      → largeModel
        → вложенный граф объектов
```

Пока обработчик зарегистрирован и `button` достижим, весь граф может оставаться в памяти. Само наличие замыкания ещё не означает утечку. Проблема возникает, когда фактическое время жизни данных превышает ожидаемое или коллекция растёт без ограничения.

#### Уменьшаем удерживаемый граф

Если колбэку нужно только небольшое производное значение, сохраните именно его:

```js
function attachPreview(button, largeModel) {
  const summary = largeModel.summary;

  function onClick() {
    renderPreview(summary);
  }

  button.addEventListener("click", onClick);
  return () => button.removeEventListener("click", onClick);
}
```

Это помогает, если `summary` сама не ссылается обратно на большой граф объектов.

#### Освобождаем ссылки

- обработчик события → `removeEventListener` с той же функцией;
- интервал или таймер → `clearInterval` / `clearTimeout`, если отложенная работа больше не нужна;
- наблюдатель → `disconnect` / `unobserve`;
- подписка → возвращённая функция `unsubscribe` или `dispose`;
- кеш → удаление записей, `clear` или сброс по правилам актуальности;
- асинхронная операция → отмена через `AbortSignal`, если API её поддерживает.

```js
function startPolling(load, delay) {
  const timerId = setInterval(load, delay);

  return function stop() {
    clearInterval(timerId);
  };
}
```

После очистки не нужно механически обнулять все локальные переменные. Главное — разорвать реальную цепочку удержания. Для расследования утечки нужны данные профилировщика памяти; одного замыкания недостаточно, чтобы объявить код причиной утечки.

### 🎯 23. Что такое чистая функция, побочный эффект и практическая неизменяемость?

В практической модели для интервью **чистая функция (pure function)**:

1. для одинаковых входных значений даёт одинаковый наблюдаемый результат;
2. не создаёт наблюдаемых побочных эффектов вне своего результата.

```js
function calculateTotal(items, taxRate) {
  const subtotal = items.reduce((sum, item) => sum + item.price, 0);
  return subtotal * (1 + taxRate);
}
```

Примеры побочных эффектов:

- мутация объекта, принадлежащего вызывающему коду;
- запись в DOM, хранилище или сеть;
- журналирование и аналитика;
- изменение состояния модуля или глобального состояния;
- чтение времени, случайного числа или внешнего изменяемого состояния, если оно влияет на результат;
- регистрация обработчика события, таймера или подписки.

```js
function impureAdd(item) {
  cart.items.push(item);
  analytics.track("item_added");
}
```

Побочные эффекты не являются «плохими»: приложение без ввода-вывода бесполезно. Цель — сделать их границы явными и не смешивать вычисления с эффектами без необходимости.

#### Практическая неизменяемость

Из 1.2: объекты имеют идентичность, а несколько привязок могут вести к одному объекту. Поэтому мутация данных вызывающего кода создаёт зависимость от порядка действий во времени.

```js
function renameUser(user, name) {
  return {
    ...user,
    name,
  };
}
```

Функция не меняет внешний объект, но spread-копия остаётся поверхностной:

```js
function setTheme(user, theme) {
  return {
    ...user,
    settings: {
      ...user.settings,
      theme,
    },
  };
}
```

Практическая неизменяемость означает:

- правила владения данными и допустимой мутации понятны;
- общие входные данные не меняются неожиданно;
- копируются только нужные уровни вложенности;
- стоимость копирования и изменение идентичности учитываются;
- API не обещает глубокую неизменяемость, если её нет.

Чистоту оценивают по наблюдаемому контракту. Локальная мутация только что созданного объекта, который ещё никому не доступен, может оставаться ненаблюдаемой снаружи:

```js
function indexById(items) {
  const result = {};

  for (const item of items) {
    result[item.id] = item;
  }

  return result;
}
```

### 🔬 24. Чем каррирование отличается от частичного применения?

**Каррирование (currying)** преобразует функцию с несколькими аргументами в цепочку одноаргументных вызовов:

```js
function add(a, b, c) {
  return a + b + c;
}

const curriedAdd = (a) => (b) => (c) => a + b + c;

curriedAdd(1)(2)(3); // 6
```

**Частичное применение (partial application)** заранее фиксирует часть аргументов и возвращает функцию с меньшей арностью:

```js
function addTax(rate, amount) {
  return amount * (1 + rate);
}

const addVat = addTax.bind(null, 0.17);
addVat(100); // 117
```

Различие:

```text
каррирование:       f(a, b, c) → f(a)(b)(c)
частичное применение: зафиксировать a → g(b, c)
```

При частичном применении новая функция не обязана принимать ровно один аргумент, и преобразовывать все этапы не требуется. Каррирование, напротив, задаёт форму всей цепочки вызовов.

Универсальная вспомогательная функция для частичного применения:

```js
function partial(operation, ...preset) {
  return (...later) => operation(...preset, ...later);
}
```

Практическая ценность:

- создать заранее настроенную операцию предметной области;
- сделать зависимость явной;
- привести сигнатуру к контракту колбэка;
- переиспользовать стабильное правило.

Ограничения:

- длинные цепочки могут ухудшить трассировку стека и усложнить знакомство с кодом;
- JavaScript API часто используют объекты настроек, а не фиксированную арность;
- для методов, зависящих от `this`, нужно отдельно решить вопрос с получателем вызова;
- автоматическое каррирование по `fn.length` ломается из-за значений по умолчанию и остаточных параметров.

Используйте этот паттерн, когда итоговый API читается как язык предметной области, а не ради демонстрации функционального стиля.

### 🔬 25. Как работают композиция функций и конвейеры?

**Композиция функций (function composition)** создаёт функцию, в которой результат одной операции становится входным значением другой.

```js
const compose = (outer, inner) =>
  (value) => outer(inner(value));

const trim = (value) => value.trim();
const lower = (value) => value.toLowerCase();

const normalize = compose(lower, trim);
normalize(" ADA "); // "ada"
```

Математическая запись читается справа налево:

```text
compose(f, g)(x) = f(g(x))
                     ↑ сначала g, затем f
```

**Конвейер (pipeline)** обычно записывает порядок выполнения слева направо:

```js
function pipe(...operations) {
  return (input) =>
    operations.reduce(
      (value, operation) => operation(value),
      input,
    );
}

const normalize = pipe(trim, lower);
```

Композиция хорошо работает, когда этапы:

- имеют совместимые контракты входных и выходных данных;
- остаются маленькими и именованными;
- не скрывают поток управления;
- согласованно работают с синхронными или асинхронными значениями;
- имеют понятные правила обработки ошибок.

Ловушка с порядком:

```js
const wrap = (value) => [value];
const length = (value) => value.length;

compose(length, wrap)("abc"); // 1
compose(wrap, length)("abc"); // [3]
```

В рабочем конвейере используйте имена из предметной области и оставляйте возможность наблюдать промежуточные сбои:

```js
const prepareUser = pipe(
  validateRawUser,
  normalizeUser,
  enrichUser,
);
```

Не прячьте ветвление, отмену асинхронной операции или восстановление после ошибки в универсальную однострочную конструкцию, если явный поток управления легче проверить и отладить.

### 🎯 26. Как выбирать функциональные паттерны в рабочем коде?

Сначала определите границы данных и побочных эффектов, затем выбирайте синтаксис.

Полезная последовательность:

1. **Контракт:** какие значения принимает и возвращает операция?
2. **Владение:** можно ли мутировать входные данные или они используются совместно?
3. **Контекст:** нужен ли динамический `this` или зависимости лучше передать явно?
4. **Жизненный цикл:** кто хранит колбэк и когда освобождает ссылку?
5. **Состояние:** нужно ли замыкание и как долго живут захваченные значения?
6. **Кеш:** ограничен ли его рост и действительно ли входные данные повторяются?
7. **Композиция:** помогают ли небольшие этапы понять поток данных?
8. **Отладка:** понятны ли имена, трассировки стека и место обработки ошибок?

Хорошая рабочая архитектура часто сочетает несколько подходов:

```js
function createUserService({ fetchJson, now, logger }) {
  const cache = new Map();

  async function loadUser(id) {
    if (cache.has(id)) return cache.get(id);

    logger.info("load_user", { id });
    const user = await fetchJson("/users/" + id);
    const normalized = normalizeUser(user, now());

    cache.set(id, normalized);
    return normalized;
  }

  function clearCache() {
    cache.clear();
  }

  return { loadUser, clearCache };
}
```

- фабрика и замыкание делают зависимости и закрытый кеш явными;
- чистая функция `normalizeUser` отделяет преобразование данных;
- ввод-вывод и журналирование остаются осознанными побочными эффектами;
- у кеша есть понятный жизненный цикл;
- именованные функции улучшают трассировку стека;
- объект настроек устраняет неоднозначность позиционных аргументов.

Функциональные паттерны дают модульность и упрощают тестирование, но могут добавить лишние объекты-функции, обёртки, скрытое состояние и цену абстракции. На Senior-интервью ценится не количество использованных комбинаторов, а способность объяснить их контракт, жизненный цикл и компромиссы.

### Формы функций

| Вопрос | Объявление | Функциональное выражение | Стрелочная функция |
|---|---|---|---|
| можно вызвать до строки | да, после подготовки объявлений | зависит от привязки; функция ещё не создана | зависит от привязки; функция ещё не создана |
| собственный `this` | да | да | нет, используется внешний |
| собственный `arguments` | да | да | нет |
| можно вызвать через `new` | обычно | обычно | никогда |
| типичная роль | именованная операция модуля | функция как значение или именованный колбэк | лексический колбэк или преобразование |

### Параметры

```text
параметр = привязка в определении функции
аргумент = значение в конкретном вызове

значение по умолчанию применяется при отсутствии аргумента или при undefined
остаточный параметр собирает оставшиеся аргументы в Array
arguments содержит все фактические аргументы обычной функции
fn.length считает параметры до первого значения по умолчанию; rest не учитывается
```

### Вызов и контекст

```text
obj.method()          → this = obj
const fn = obj.method
fn()                  → контекст метода потерян
fn.call(obj, a, b)    → вызвать сейчас
fn.apply(obj, [a,b])  → вызвать сейчас
fn.bind(obj, a)       → создать функцию для будущего вызова
arrow.call(obj)       → obj не заменяет внешний this
```

### Замыкание

```text
достижимый колбэк
  → лексическое окружение
    → живые привязки
      → связанный граф объектов
```

Замыкание видит текущее значение привязки. Снимок создаётся отдельной привязкой или значением. Очистка разрывает цепочку удержания через обработчик события, таймер, подписку или кеш.

### Функциональные паттерны

```text
чистая функция: одинаковые входы → одинаковый результат; нет внешних эффектов
каррирование: f(a,b,c) → f(a)(b)(c)
частичное применение: закрепить часть аргументов → функция для остальных
compose(f,g)(x): f(g(x))  // справа налево
pipe(g,f)(x):    f(g(x))  // в порядке слева направо
```

## Типичные ошибки

1. **Считать стрелочную функцию короткой записью обычной функции.** Исправление: отдельно проверить `this`, `arguments`, `new` и `prototype`.

2. **Говорить, что функциональное выражение «не поднимается».** Исправление: привязка подготавливается по правилам `var`, `let` или `const`, но сама функция создаётся только при вычислении выражения.

3. **Искать имя именованного функционального выражения снаружи.** Исправление: внутреннее имя доступно только в теле самой функции.

4. **Путать параметры и аргументы.** Исправление: параметры — привязки из определения функции; аргументы — значения конкретного вызова.

5. **Использовать значение по умолчанию вместо проверки.** Исправление: `null`, неправильный тип и значение вне допустимого диапазона проверяются отдельно.

6. **Думать, что `arguments` — массив.** Исправление: использовать остаточные параметры в современном API или явно преобразовать объект в массив.

7. **Передавать метод как колбэк и ожидать прежний `this`.** Исправление: проверить форму будущего вызова и сохранить одну ссылку на привязанную функцию или адаптер.

8. **Говорить, что `bind` вызывает функцию.** Исправление: `bind` возвращает новую вызываемую функцию, а `call` и `apply` вызывают исходную немедленно.

9. **Вызывать `bind` отдельно при добавлении и снятии обработчика.** Исправление: сохранить одну и ту же функцию.

10. **Считать замыкание снимком значения.** Исправление: указать конкретную живую привязку и весь код, который может её изменить.

11. **Считать любое замыкание утечкой памяти.** Исправление: найти цепочку удержания и сравнить фактическое и ожидаемое время жизни данных.

12. **Добавить мемоизацию без удаления и сброса записей.** Исправление: описать семантику ключей, частоту повторных попаданий, предел размера и правила обновления устаревших данных.

13. **Называть побочные эффекты плохими.** Исправление: отделять необходимые эффекты от чистых вычислений и делать границы явными.

14. **Путать каррирование и частичное применение.** Исправление: каррирование меняет форму всей цепочки вызовов; частичное применение фиксирует часть аргументов.

15. **Перепутать порядок композиции.** Исправление: вручную подставить одно значение и пройти все этапы.

## Ловушки на интервью

### Ловушка 1: объявление и выражение до строки

```js
ready();                 // работает
function ready() {}

// later();              // ReferenceError
const later = function () {};
```

Объясняйте жизненный цикл привязки, а не «перенос строк».

### Ловушка 2: имя именованного выражения

```js
const run = function internal() {
  return typeof internal;
};

console.log(run());          // "function"
console.log(typeof internal); // "undefined"
```

### Ловушка 3: стрелочная функция читает внешний `arguments`

```js
function outer(first) {
  return (() => arguments[0])();
}

outer("A"); // "A"
```

### Ловушка 4: вычисление значения по умолчанию

```js
let value = 1;
function read(current = value) {
  return current;
}

value = 2;
read(); // 2
```

Значение по умолчанию вычисляется во время вызова, когда аргумент отсутствует или равен `undefined`.

### Ловушка 5: `length`

```js
function task(a, b = 2, c) {}
task.length; // 1
```

Счёт прекращается перед первым параметром со значением по умолчанию.

### Ловушка 6: потеря контекста колбэка

```js
"use strict";

const account = {
  balance: 10,
  read() {
    return this.balance;
  },
};

const read = account.read;
// read(); // TypeError
```

### Ловушка 7: повторный bind

```js
function read() {
  return this.value;
}

const first = read.bind({ value: 1 });
const second = first.bind({ value: 2 });

second(); // 1
```

### Ловушка 8: замыкание читает живую привязку

```js
let status = "idle";
const readStatus = () => status;
status = "ready";

readStatus(); // "ready"
```

### Ловушка 9: общее состояние нескольких замыканий

```js
function pair() {
  let value = 0;
  return [() => ++value, () => value];
}

const [increment, read] = pair();
increment();
read(); // 1
```

### Ловушка 10: порядок композиции

```js
const compose = (f, g) => (x) => f(g(x));
const addOne = (x) => x + 1;
const double = (x) => x * 2;

compose(double, addOne)(3); // 8
compose(addOne, double)(3); // 7
```

### Ловушка 11: `new` со стрелочной функцией

```js
const Factory = () => ({ ok: true });

// Намеренно ошибочный пример:
// new Factory(); // TypeError
```

## Практические рекомендации

### Выбор формы

- Именованное объявление или выражение — для значимых операций и понятной трассировки стека.
- Стрелочная функция — для лексических колбэков и небольших преобразований.
- Краткая запись метода или обычная функция — когда получатель определяется формой вызова.
- Фабрика или класс — для API создания объектов с ясной моделью идентичности и жизненного цикла.

### Параметры API

- Объект настроек — для нескольких необязательных флагов и параметров.
- Остаточный параметр — для современного API с переменным числом аргументов.
- Значение по умолчанию — только для документированного случая отсутствия данных.
- Проверка входных данных — отдельно от подстановки значений по умолчанию.
- Не используйте `fn.length` как схему API без жёстко контролируемого соглашения.

### Контекст и колбэки

- Проверяйте контракт колбэка: момент и число вызовов, аргументы, `this`, возвращаемое значение, ошибки и отмену.
- Сохраняйте ссылку на привязанную функцию или обработчик, чтобы затем снять регистрацию.
- Не создавайте новый привязанный колбэк при каждом рендере или вызове без причины.
- Передавайте зависимости явно, если `this` только скрывает их.

### Замыкания и состояние

- Захватывайте только необходимые значения.
- Документируйте, какие замыкания разделяют состояние.
- Возвращайте функцию очистки рядом с кодом регистрации.
- Ограничивайте кеши и определяйте правила их сброса.
- Подтверждайте проблемы с памятью цепочками удержания и данными профилировщика кучи.

### Функциональный дизайн

- Чистые преобразования держите рядом с моделью предметной области.
- Побочные эффекты концентрируйте в понятных границах.
- Практическую неизменяемость применяйте с учётом владения данными и поверхностного копирования.
- Каррирование и композицию используйте, если места вызова становятся яснее.
- Именуйте этапы; не жертвуйте удобством отладки ради безымянной однострочной цепочки.

## 🧓 Legacy: старый код и знания для интервью

- `var` вместе с функциональным выражением до присваивания даёт `undefined`, а попытка вызова — `TypeError`.
- До появления `let` и ES-модулей IIFE использовались для отдельных привязок на каждой итерации и для модульной приватности.
- В нестрогой функции с простыми параметрами именованные параметры могут быть связаны с индексами `arguments`.
- `arguments.callee` запрещён в строгом режиме; используйте именованное функциональное выражение.
- `Function.prototype.call` и `apply` часто применялись для заимствования методов и цепочек конструкторов; современные встроенные методы, классы и объекты настроек обычно яснее.
- Функции-конструкторы по-прежнему важны для чтения старого кода и вопросов про `new`.

## Как объяснить тему на интервью за 30–60 секунд

### Объявление функции и функциональное выражение

> Объявление функции сразу подготавливает привязку с готовым объектом-функцией, поэтому вызов раньше строки объявления работает. Функциональное выражение создаёт функцию только при вычислении самого выражения; до этого поведение привязки определяется `var`, `let` или `const`. Именованное выражение дополнительно получает внутреннее имя, доступное только в теле функции: оно полезно для рекурсии и трассировки стека.

### Стрелочная и обычная функции

> Стрелочная функция — не просто короткий синтаксис. Она не создаёт собственные `this`, `arguments`, `super` и `new.target`, и её нельзя вызвать через `new`. Поэтому она удобна для лексических колбэков. Метод с получателем, определяемым при вызове, требует обычной функции или краткой записи метода, а для создания экземпляров используют обычную функцию или класс. `call`, `apply` и `bind` не могут заменить лексический `this` стрелочной функции.

### `call` / `apply` / `bind`

> `call` и `apply` вызывают функцию немедленно и явно задают `this`: `call` принимает аргументы отдельным списком, а `apply` — одним массивоподобным значением. `bind` ничего не вызывает, а возвращает новую функцию, в которой сохранены `this` и первые аргументы для будущего вызова. Первый привязанный `this` уже нельзя заменить повторным `bind`. Если такую функцию передают как обработчик, ссылку нужно сохранить, иначе снять регистрацию той же функции не получится.

### Замыкание

> Замыкание — это функция вместе с доступом к лексическим привязкам из места её создания. Оно сохраняет не снимки значений, а доступ к самим привязкам. Поэтому несколько замыканий могут видеть и менять общее состояние, а более поздний вызов прочитает текущее значение. Пока функция достижима, через её окружение могут оставаться достижимыми захваченные объекты, поэтому у обработчиков, таймеров, подписок и кешей должен быть ясный жизненный цикл.

### Чистая функция и неизменяемость

> Чистая функция для одинаковых входных данных даёт одинаковый наблюдаемый результат и не создаёт внешних побочных эффектов. Эффекты нужны для интерфейса и ввода-вывода, но их лучше отделять от вычислений. Практическая неизменяемость уменьшает неожиданные изменения общих объектов, однако spread создаёт только поверхностную копию, а копирование тоже имеет стоимость.

### Каррирование и частичное применение

> Каррирование превращает функцию `f(a,b,c)` в цепочку `f(a)(b)(c)`. Частичное применение фиксирует только часть аргументов и возвращает функцию для остальных. Оба паттерна помогают создавать заранее настроенные операции, но полезны лишь тогда, когда места вызова становятся яснее. Автоматическое каррирование по `length` хрупко из-за значений по умолчанию, остаточных параметров и обёрток.
