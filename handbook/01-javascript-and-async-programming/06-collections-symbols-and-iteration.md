## Ментальная модель

Вы показываете список результатов поиска. Поля строки, например `id` и `title`, описывают одну сущность. Индекс «ID → строка» отвечает на другой вопрос: как найти произвольную строку по ключу? Набор уже показанных ID решает третью задачу: встречался ли такой ID? А получение следующих результатов по мере прокрутки — задача обхода, у которого может вообще не быть заранее готовой коллекции.

| Что требуется | С чего начать |
|---|---|
| Описать запись с именованными полями | Обычный объект |
| Найти значение по произвольному ключу | `Map` |
| Запомнить факт присутствия | `Set` |
| Привязать метаданные к объекту с независимым временем жизни | `WeakMap` |
| Дать коду возможность запрашивать элементы по одному | Итерируемый объект или генератор |

## Связное объяснение в формате вопросов и ответов

### 🎯 1. Как выбрать между `Map` и обычным объектом?

Обычный объект удобен для записи известной формы: `row.id` и `row.title`. `Map` выражает работу с записями «ключ → значение»: `set`, `get`, `has`, `delete`, `clear`, `size`. У объекта ключ свойства — строка или символ. Число в квадратных скобках преобразуется в строку. У `Map` ключом может быть любое значение, в том числе объект или функция.

```js
const row = { id: 7 };
const index = new Map([[7, row], ["7", undefined]]);

console.log(index.size, index.get(7) === row); // 2 true
console.log(index.has("7"), index.get("7")); // true undefined
console.log(index.has(8), index.get(8)); // false undefined
```

`get` возвращает `undefined` и для отсутствующего ключа, и для сохранённого `undefined`. Если разница важна, спросите `has`. Для динамического словаря со строковыми ключами объект без прототипа (`Object.create(null)`) тоже разумен, если контракт требует именно свойства. Для обычного объекта проверяйте собственное свойство через `Object.hasOwn`.

**🧓 Legacy.** В старом коде часто встречаются `dictionary[key]` и `key in dictionary` для проверки наличия. Первое читает и унаследованное значение, второе ищет по всей цепочке. `Object.prototype.hasOwnProperty.call(dictionary, key)` остаётся вариантом для сред без `Object.hasOwn`.

### 🎯 2. Когда два ключа `Map` считаются одним ключом?

Наблюдаемое сравнение соответствует `SameValueZero`: `NaN` совпадает с `NaN`, оба нуля совпадают, `7` отличается от `"7"`, объекты сравниваются по идентичности. Две одинаковые карточки читателя с разными номерами — разные ключи. Так же два литерала `{ id: 7 }` создают два объекта.

```js
const row = { id: 7 };
const labels = new Map([[row, "selected"], [NaN, "invalid"], [-0, "zero"]]);

console.log(labels.get(row)); // selected
console.log(labels.get({ id: 7 })); // undefined
console.log(labels.get(NaN), labels.get(+0)); // invalid zero
```

Если два экземпляра должны обозначать одну сущность, ключом обычно служит её устойчивый ID. Спецификация требует в среднем сублинейного времени доступа для `Map` и `Set`. Из этого требования нельзя вывести точную сложность каждой операции или преимущество над объектом в конкретном приложении.

### 🎯 3. Как обходятся записи и что именно считает `size`?

`for (const [key, value] of map)` обходит пары в порядке вставки. `keys()`, `values()`, `entries()` дают отдельные итераторы. Повторный `set` обновляет значение на прежнем месте. Удаление и повторная вставка перемещают ключ в конец. `size` считает записи, включая запись со значением `undefined`.

```js
const map = new Map([["10", "ten"], ["2", "two"]]);
map.set("10", "updated");
console.log([...map.keys()]); // ["10", "2"]
map.delete("10");
map.set("10", "again");
console.log([...map.keys()]); // ["2", "10"]
console.log(Object.keys({ 10: "ten", 2: "two" })); // ["2", "10"]
```

У обычного объекта свои правила. Например, `Object.keys` и `Object.entries` видят только собственные перечисляемые строковые свойства, а индексные ключи идут первыми по возрастанию. `Object.keys(obj).length` считает именно этот набор. Унаследованные, неперечисляемые и символьные ключи требуют отдельного решения.

### 🔬 4. Что увидит уже открытый итератор при изменении `Map`?

Обход работает с живой коллекцией. Если удалить ещё не посещённый ключ, он пропускается. Новый ключ может попасть в тот же обход, пока итератор не завершился. Удалённый и заново добавленный ключ может встретиться второй раз. Если нужно пройти фиксированный список пар, снимите его через `[...map]` перед изменениями. Сами ключи и значения при этом сохраняют свои идентичности.

```js
const map = new Map([["a", 1], ["b", 2]]);
const cursor = map.keys();
console.log(cursor.next().value); // a
map.delete("b");
map.set("c", 3);
console.log([...cursor]); // ["c"]
```

### 🎯 5. Как передать `Map` через границу с JSON?

У записей `Map` своё внутреннее хранилище. У обычного экземпляра `JSON.stringify(new Map([["id", 7]]))` даёт `"{}"`. Для строкового словаря с подходящими значениями можно явно получить запись через `Object.fromEntries`. Если нужно различать число и строку, массив пар сохраняет эту разницу в пределах типов, представимых в JSON.

```js
const index = new Map([[7, "number"], ["7", "text"]]);
console.log(Object.fromEntries(index)); // { "7": "text" }
const encoded = JSON.stringify([...index]);
console.log(new Map(JSON.parse(encoded)).size); // 2
```

Массив пар не переносит идентичность объектного ключа между системами. На внешней границе договоритесь об устойчивом ID и формате данных. Полный договор JSON относится к [1.7](07-modules-errors-and-serialization.md).

### 🎯 6. Когда `Set` действительно удаляет дубликаты?

`Set` хранит каждое значение один раз по тому же правилу равенства, что и `Map`. Он обходит значения в порядке вставки. После удаления новая вставка добавляет значение в конец. `add` добавляет значение, `has` проверяет присутствие, `delete` удаляет, `size` сообщает число элементов. Итерация по умолчанию выдаёт значения.

```js
const first = { id: 7, title: "Draft" };
const update = { id: 7, title: "Published" };

console.log([...new Set([NaN, NaN, -0, +0, "0"])]); // [NaN, 0, "0"]
console.log(new Set([first, update, first]).size); // 2
```

При дедупликации записей по `id` сначала определите победителя. `Set` посещённых ID и отдельный результат удобно сохраняют первое совпадение. Если побеждает последняя запись, можно обновлять `Map` по ID. При таком обновлении порядок ключей остаётся порядком первого появления.

### 🔬 7. Какие современные операции с коллекциями полезно знать?

У `Set` есть операции над множествами (`union`, `intersection`, `difference`, `symmetricDifference`) и проверки отношений (`isSubsetOf`, `isSupersetOf`, `isDisjointFrom`). Например, `selected.intersection(visible)` даёт новый набор выбранных видимых ID. Справа нужен объект с договором множества (`size`, `has()`, `keys()`), поэтому подходит `Map` как набор своих ключей. Массив можно преобразовать через `new Set(values)`. Порядок `intersection` следует обходу меньшего из наборов, при равном размере — получателя. Если порядок важен для интерфейса, закрепите его явно.

```js
const selected = new Set([3, 1, 2]);
const visible = new Map([[2, "two"], [3, "three"]]);
console.log([...selected.intersection(visible)]); // [2, 3]
```

`Map.groupBy(items, keyOf)` сохраняет произвольные ключи, например объект команды. `Object.groupBy` использует ключи свойств и возвращает объект без прототипа. Для группировки по идентичности используйте `Map.groupBy`. Для словаря, где ключ — стабильная строка, подходит `Object.groupBy`.

### 🎯 8. Что значит «слабая» ссылка?

Пока существует цепочка сильных ссылок от работающей программы, например через переменную, живой объект или обычный `Map`, объект доступен коду. Это сильная достижимость (strong reachability). Хранилище метаданных может существовать дольше строки интерфейса, к которой относится запись. Слабый ключ позволяет привязать данные к этой строке, не продлевая её жизнь самим фактом регистрации. Исчезновение остальных сильных ссылок лишь позволяет сборку. Срока или гарантии наблюдаемой сборки нет.

### 🎯 9. Чем различаются `WeakMap`, `WeakSet` и `WeakRef`?

| API | Задача | Операции |
|---|---|---|
| `WeakMap` | Внешние данные по идентичности объекта | `get`, `set`, `has`, `delete` |
| `WeakSet` | Отметка «этот объект уже обработан» | `add`, `has`, `delete` |
| `WeakRef` | Попробовать получить отдельную цель | `deref()` → цель либо `undefined` |

У слабых коллекций нет `size` и обхода. Если бы код перечислял записи, результат зависел бы от того, успел ли сборщик убрать уже недостижимые ключи. Если нужна выгрузка, ограничение размера или удаление по времени, используйте явно управляемое хранилище.

```js
const row = { id: 7 };
const layout = new WeakMap();
const measured = new WeakSet();

layout.set(row, { height: 32 });
measured.add(row);
console.log(layout.get(row).height, measured.has(row)); // 32 true
```

### 🔬 10. Какие ключи можно держать слабо и что происходит со значением?

Помимо объектов, включая функции, современный стандарт допускает незарегистрированные символы, например `Symbol("row")`. `Symbol.for("row")` зарегистрирован и запрещён. `WeakMap#set`, `WeakSet#add` и `new WeakRef` выбрасывают `TypeError` для недопустимой цели. Запросы `has` и `delete` возвращают `false`, `WeakMap#get` — `undefined`. В старых рантаймах поддержка символов отличается от поддержки самого API.

Значение `WeakMap` может быть любым. Оно удерживается через карту при достижимом ключе. Если значение ссылается на ключ, одна только запись слабой карты не спасает этот цикл от сборки. Если значение удерживается отдельно и ссылается на ключ, такая внешняя сильная цепочка уже способна удержать ключ. Спецификационная модель условной связи известна как ephemeron.

```js
const token = Symbol("row");
const metadata = new WeakMap([[token, "measured"]]);
console.log(metadata.get(token), metadata.has(Symbol.for("row"))); // measured false
```

### 🎯 11. Когда `WeakRef` подходит для прикладной задачи?

Только когда исчезновение цели допустимо, а основной путь умеет получить результат заново. Например, слабая ссылка может дать шанс переиспользовать заново вычислимый объект. Сам индекс `Map<Id, WeakRef<Value>>` при этом всё ещё удерживает свои ID и обёртки. Для ограничения индекса нужен явный жизненный цикл.

```js
function readOrBuild(ref, build) {
  const cached = ref.deref();
  return cached ?? build();
}
```

Храните результат `deref()` в локальной переменной, если дальше нужна эта же цель. Редкая точность: движок сохраняет цель до конца текущего задания (job), в котором она была создана через `WeakRef` или успешно прочитана через `deref`. Для теста промаха подставьте объект с `deref: () => undefined`. Сбрасывать ссылку и ждать определённого результата сборщика бессмысленно.

### 🎯 12. Чем отличаются `Symbol()`, `Symbol.for()` и известные символы?

Символ — примитив с собственной идентичностью. Описание помогает при отладке и не участвует в сравнении. `Symbol.for(key)` ищет или создаёт символ в общем реестре (global symbol registry), а `Symbol.keyFor` возвращает его зарегистрированный ключ. Имя вроде `"my-app.measurement"` полезно, когда несколько частей программы сознательно договариваются об одном маркере. Для локального независимого ключа хватит `Symbol()`.

```js
console.log(Symbol("id") === Symbol("id")); // false
const shared = Symbol.for("my-app.measurement");
console.log(shared === Symbol.for("my-app.measurement")); // true
console.log(Symbol.keyFor(shared), Symbol.keyFor(Symbol("id"))); // my-app.measurement undefined
```

Известные символы (well-known symbols) задают точки расширения самого языка. `Symbol.iterator` определяет обычный обход, `Symbol.asyncIterator` — асинхронный, `Symbol.toPrimitive` — преобразование в примитив, `Symbol.toStringTag` — метку в `Object.prototype.toString`. `Symbol.for("Symbol.iterator")` создаёт другой символ. Для выполнения протокола движок ищет точный ключ.

### 🎯 13. Делает ли символьный ключ свойство приватным?

Он снижает риск случайного совпадения имён. `Object.keys`, `Object.entries` и `for...in` пропускают символы, но `Reflect.ownKeys` и `Object.getOwnPropertySymbols` их показывают. Объектный spread копирует собственные перечисляемые символьные свойства. Для настоящего ограничения доступа используйте подходящий механизм инкапсуляции, например поле `#private`.

```js
const marker = Symbol("marker");
const row = { id: 7, [marker]: true };

console.log(Object.keys(row)); // ["id"]
console.log(Reflect.ownKeys(row).includes(marker)); // true
console.log(({ ...row })[marker]); // true
```

### 🎯 14. Чем итерируемый объект отличается от итератора?

Итерируемое значение (iterable) предоставляет метод `[Symbol.iterator]()`. Метод открывает обход и возвращает итератор (iterator). Его `next()` возвращает объект результата с `value` и `done`. Если `done` ложен, `value` — очередной элемент. Если истинен, цикл заканчивается, даже если в этом результате есть `value`.

Представьте книгу и закладку. Книга задаёт последовательность страниц, закладка отмечает место конкретного читателя. Повторно обходимая коллекция выдаёт каждому читателю свою закладку. Сам итератор может также реализовать `[Symbol.iterator]() { return this; }`, чтобы цикл продолжал с уже достигнутой позиции.

```js
const letters = new Set(["a", "b"]);
const cursor = letters[Symbol.iterator]();
console.log(cursor.next()); // { value: "a", done: false }
console.log([...cursor]); // ["b"]
console.log([...letters]); // ["a", "b"]
```

### 🎯 15. Как понять, какой вид обхода использует синтаксис?

`for...of` и spread в массиве берут значения через протокол. `for...in` перечисляет строковые ключи перечисляемых свойств, включая унаследованные. У литерала объекта по умолчанию нет обычного итератора, поэтому для обхода его пар можно взять `Object.entries(obj)`. У массивоподобного значения (array-like) могут быть индексы и `length` без итератора. `Array.from` умеет читать такой вход, тогда как `[...input]` потребует итератор. Объектный spread относится к свойствам, как разобрано в [1.5](05-arrays-transformations-and-copying.md).

```js
const arrayLike = { 0: "a", length: 1 };
console.log(Array.from(arrayLike)); // ["a"]
console.log([...Object.entries({ id: 7 })]); // [["id", 7]]
```

### 🎯 16. Как написать повторно обходимую последовательность вручную?

Пусть каждый вызов `[Symbol.iterator]()` создаёт собственное состояние. Тогда два потребителя смогут читать независимо и не будут делить одну позицию. Верните объект даже в последнем результате. `undefined` вполне может быть законным элементом, поэтому проверяйте `done`.

```js
function range(start, end) {
  return {
    [Symbol.iterator]() {
      let current = start;
      return {
        next() {
          if (current >= end) return { done: true };
          return { value: current++, done: false };
        },
        [Symbol.iterator]() {
          return this;
        },
      };
    },
  };
}

const values = range(2, 5);
const left = values[Symbol.iterator]();
const right = values[Symbol.iterator]();
console.log(left.next().value, left.next().value, right.next().value); // 2 3 2
console.log([...values]); // [2, 3, 4]
```

### 🎯 17. Что добавляет генератор?

`function*` описывает ход обхода обычным кодом. Вызов возвращает генератор (generator), тело стартует на первом `next()`, `yield` выдаёт значение и приостанавливает выполнение. Следующий `next()` возобновляет его. Генератор сам итерируем и одноразов. Повторный вызов функции создаёт новый генератор. Метод `*[Symbol.iterator]()` совмещает это с повторно обходимой оболочкой. `yield*` делегирует обход другой последовательности.

```js
const columns = {
  *[Symbol.iterator]() {
    yield "id";
    yield* ["name", "status"];
    return "finished";
  },
};
console.log([...columns]); // ["id", "name", "status"]
console.log([...columns]); // ["id", "name", "status"]
```

### 🔬 18. Куда попадают аргумент `next(value)` и значение `return`?

После приостановки аргумент следующего `next(value)` становится результатом выражения `yield` внутри тела. Первый аргумент `next` пропускается, потому что приостановленного `yield` ещё нет. Значение `return` попадает в результат с `done: true` и через обычный цикл не выдаётся. Метод `throw(error)` вводит исключение в точку приостановки. Эти детали полезны для чтения управляющих генераторов, а для выдачи данных обычно хватает `yield` и обычного `next()`.

```js
function* select() {
  const name = yield "choose";
  return name.toUpperCase();
}
const cursor = select();
console.log(cursor.next("ignored")); // { value: "choose", done: false }
console.log(cursor.next("a")); // { value: "A", done: true }
```

### 🎯 19. Кто освобождает ресурс при раннем выходе?

При `break`, выходе из функции или исключении в теле `for...of` цикл закрывает итератор, вызывая его `return()`, если метод есть. Генератор при закрытии выполняет `finally`. Если вызываете `next()` вручную и бросаете обход, ответственность за закрытие у вызывающего кода. Пишите источник так, чтобы он освобождал свои ресурсы и при ошибке получения данных. В `finally` освобождайте ресурс сразу. Если генератор снова сделает `yield`, одного вызова `return()` может не хватить для завершения. Если исключение пришло из самого `next()`, цикл не даёт универсальной гарантии вызова `return()`.

```js
function* tracked(events) {
  events.push("open");
  try {
    yield "first";
    yield "second";
  } finally {
    events.push("close");
  }
}

const events = [];
for (const item of tracked(events)) {
  events.push(item);
  break;
}
console.log(events); // ["open", "first", "close"]
```

### 🔬 20. Зачем нужны методы итераторов (iterator helpers)?

`Iterator.from(source)` принимает итерируемый источник или итератор и даёт доступ к методам. `map`, `filter`, `take` создают ленивую цепочку. Терминальные операции, например `find` или `toArray`, начинают обход. Это удобно, если достаточно нескольких совпадений из длинного источника. Вызов `toArray` без конечной границы по-прежнему попытается собрать весь остаток.

```js
function* count() {
  for (let n = 1; ; n++) yield n;
}

const firstThree = Iterator.from(count())
  .filter((n) => n % 2 === 0)
  .map((n) => n * n)
  .take(3)
  .toArray();

console.log(firstThree); // [4, 16, 36]
```

Обычный объект с `next()` может соответствовать протоколу и при этом не иметь методов `Iterator.prototype`. У каждой цепочки есть позиция в исходном итераторе. Для независимых проходов открывайте источник заново.

### 🎯 21. Что меняется, если следующий элемент приходит позже?

У асинхронного итерируемого объекта (async iterable) метод `[Symbol.asyncIterator]()` возвращает итератор, чей `next()` даёт обещание результата обхода. `for await...of` ждёт очередной шаг. При раннем выходе он ждёт и закрытие через `return()`, если метод есть. Асинхронный генератор `async function*` соединяет `await` внутри источника и `yield` на его границе.

```js
async function* pages(load) {
  for (const page of [1, 2]) yield await load(page);
}

const requested = [];
for await (const rows of pages(async (page) => {
  requested.push(page);
  return [`row-${page}`];
})) {
  console.log(rows); // ["row-1"]
  break;
}
console.log(requested); // [1]
```

Потребитель запрашивает страницы по очереди. Когда ему достаточно первой, в этой реализации вторая даже не запрашивается. Поток может сам буферизовать данные, поэтому последовательность вызовов цикла ещё не описывает всю политику буферизации или отмены. Здесь достаточно видеть общий договор между источником и потребителем.

### 🔬 22. Почему `for await...of` принимает и обычный массив?

Если асинхронного метода нет, цикл адаптирует синхронный итератор и ожидает обещания, которые тот выдаёт. Поэтому массив обещаний допустим, но цикл не отменяет работу, которую эти обещания уже начали. Для синхронных данных без ожидания проще `for...of`. Для конечного асинхронного источника `Array.fromAsync` собирает результат в массив, а `for await...of` позволяет обрабатывать элементы по мере получения и остановиться раньше.

Тонкость совместимости: по актуальной спецификации адаптер закрывает синхронный итератор, если отклоняется обещание, выданное как очередной элемент (`done: false`). В проверенных Node.js 20.18.2 и 22.13.1 в таком случае `finally` синхронного генератора пропускается. В Node.js 24.21.0 и 26.4.0 он выполняется. Если нужна переносимая уборка при ошибке ожидания, используйте асинхронный генератор с `await` внутри `try` либо обычный `for...of` с `await` в теле потребителя.

## Краткий справочник

| Сигнал в задаче | Что проверить |
|---|---|
| Ключ похож на объект из прошлой версии данных | Идентичность или устойчивый ID |
| Значение бывает `undefined` | Наличие ключа через `has` |
| Нужно перечислить все записи | Сильная коллекция и явное владение |
| Два потребителя читают один источник | Новый итератор или общий курсор |
| Есть ранний выход | Договор `return()`, `finally` и владелец ресурса |
| Данные могут быть бесконечными | Ограничение до материализации |

## Типичные ошибки

- Записать `map[key] = value` и ожидать, что `get` и `size` увидят запись. Так меняется свойство объекта `Map`.
- Обещать дедупликацию сущностей через `new Set(rows)`, когда строки приходят заново созданными объектами.
- Брать `WeakMap` для списка активных строк или TTL-кеша, которому нужны обход и предсказуемое удаление.
- Хранить общую позицию на повторно обходимом объекте и случайно связывать два независимых обхода.
- Материализовать ленивую или асинхронную последовательность целиком, когда нужен только префикс.

## Ловушки на интервью

- `Map` различает `1` и `"1"`, но объединяет `-0` и `+0`.
- Символьный ключ виден рефлексии. Символ с тем же описанием и зарегистрированный символ с тем же именем имеют другую идентичность, чем локальный символ.
- Итератор может выдать `undefined` с `done: false`. `return value` генератора даёт `done: true`.
- Массив — итерируемый объект. Операции `Set` требуют от правого операнда ещё и договора множества.
- `for await...of` работает и с синхронным источником. Запущенная работа и закрытие итератора — разные договоры.

## Практические рекомендации

Разделяйте семантику стандарта, поддержку целевых сред и редкие детали реализации. В новом коде выбирайте структуру по ключам, порядку и владению. В опубликованном ECMAScript 2026 уже есть операции множеств, группировка, методы синхронных итераторов и `Array.fromAsync`. По MDN группировка и операции множеств относятся к Baseline 2024, `Iterator.prototype.map` и `take` — к Baseline 2025. У встроенных слабых ссылок и поддержки символов как слабых ключей разные строки в таблицах совместимости.

На локальных Node.js 22.13.1 и 24.21.0 доступны группировка, операции множеств, методы синхронных итераторов и `Array.fromAsync`. В проверенной сборке Node.js 20.18.2 этих методов нет. `Map#getOrInsert`, `getOrInsertComputed` и `Iterator.concat` уже поставляются современными браузерами (Baseline 2026), и доступны в проверенном Node.js 26.4.0. В проверенных сборках 22.13.1 и 24.21.0 их нет. Оба API входят в опубликованное издание ECMAScript 2026. `getOrInsert` сохраняет имеющееся значение, даже если оно равно `undefined`. `getOrInsertComputed` вызывает функцию только при отсутствии ключа. `Iterator.concat` последовательно обходит несколько итерируемых объектов. Если нужна совместимость, выбирайте явную проверку `has` и последующий `set`, обычный цикл или делегирование через `yield*`. Синхронная цепочка `Iterator` сама по себе не адаптирует асинхронный источник. Поддержку проверяйте для точной версии браузера или рантайма приложения.

## Как объяснить тему на интервью за 30–60 секунд

### `Map`, объект и `Set`

> Для записи известной формы беру объект. Для динамического индекса с произвольными ключами выбираю `Map`: есть `has`, `size`, обход пар в порядке вставки, а объектные ключи сравниваются по идентичности. `Set` использую для проверки принадлежности или уникальных значений. Если уникальность определяется ID, сначала задам политику первого или последнего совпадения. На JSON-границе преобразую структуру явно и сохраняю устойчивые ключи.

### Слабые коллекции

> `Map` удерживает ключи. `WeakMap` привязывает данные к объекту и не удерживает ключ только из-за этой записи. `WeakSet` так же подходит для отметок присутствия. Они не дают перечислить ключи или посчитать размер, потому что эти наблюдения зависели бы от сборки мусора. `WeakRef` пробует вернуть цель. Для него всегда нужен рабочий путь на случай `undefined`, а обязательную очистку и ограничения размера я управляю явно.

### Символы

> `Symbol()` создаёт новый примитив, даже если описание совпадает. `Symbol.for()` возвращает общий символ по ключу из реестра. Символьное свойство помогает избежать конфликтов имён, но остаётся видимым через `Reflect.ownKeys`. Известные символы — отдельные ключи, по которым язык находит поведение. Например, `for...of` вызывает метод с ключом `Symbol.iterator`. Строка с тем же названием или символ из реестра этот договор не выполняют.

### Обход, генераторы и асинхронные источники

> Итерируемый объект открывает обход через `Symbol.iterator`, а итератор продвигает конкретный обход через `next()` и сообщает `done`. Новый итератор позволяет начать с начала. Генератор реализует курсор через `yield` и возобновляет тело по требованию. При раннем выходе цикл закрывает его через `return()`, что позволяет выполнить `finally`. Если шаг нужно ждать, источник предоставляет `Symbol.asyncIterator`, а потребитель использует `for await...of`.
