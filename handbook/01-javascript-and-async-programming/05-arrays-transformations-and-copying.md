Массив кажется простым контейнером, пока интервьюер не добавит пустой слот, `sort()`, вложенный объект или требование «не менять вход». Тогда приходится одновременно держать в голове структуру массива, контракт метода и владение ссылками.

Главная последовательность главы:

```text
массив и length → плотный / разреженный → мутация → преобразования
                → сортировка → деструктуризация / spread
                → поверхностная копия → структурное разделение
                → договор глубокой копии → structuredClone → компромиссы
```

Из раздела 1.4 понадобятся идентичность объекта, собственные свойства и дескрипторы. Здесь мы используем их для массивов и копирования, но не повторяем объектную модель целиком. `Map`, `Set`, Symbols и устройство протокола итерации остаются в 1.6. JSON рассматривается только как ловушка клонирования; полноценная сериализация остаётся в 1.7.

## Ментальная модель

1. Массив — объект с особыми правилами для индексных собственных свойств и `length`.
2. `length` описывает диапазон индексов, а не количество реально существующих элементов.
3. Пустой слот (hole) означает отсутствие свойства; явный `undefined` — существующее свойство со значением `undefined`.
4. Методы обхода не образуют одну группу: одни пропускают пустые слоты, другие читают их как `undefined`, третьи сохраняют разреженность.
5. Название метода недостаточно: всегда уточняйте, меняет ли он вход и что возвращает.
6. Новый внешний массив не копирует вложенные объекты. Поверхностная копия меняет контейнер, а не весь граф.
7. Структурное разделение (structural sharing) копирует изменяемый путь, а неизменившиеся ветви намеренно оставляет общими.
8. Глубокая копия — договор о поддерживаемом графе данных: типах, прототипах, циклах, повторных ссылках и служебном состоянии.
9. `structuredClone` реализует конкретный алгоритм клонирования, а не универсальное воспроизведение любого JavaScript-объекта.
10. Копирование, как и мутация, должно следовать владению данными и измеренным требованиям, а не лозунгу.

## Связное объяснение в формате вопросов и ответов

### 🎯 1. Чем массив отличается от обычного объекта на практике?

У массива есть объектная идентичность, прототип и свойства. Но запись индексного элемента согласована с особым свойством `length`:

```js
const items = ["a", "b"];

items[4] = "e";
items.note = "draft";

console.log(items.length);       // 5
console.log(2 in items);         // false
console.log(items.note);         // "draft"
console.log(Object.keys(items)); // ["0", "1", "4", "note"]
```

`items[4]` увеличил `length` до `5`, но не создал свойства `2` и `3`. Обычное строковое свойство `note` не влияет на длину. Практичная модель:

```text
array = object identity
      + indexed own properties
      + length boundary
      + Array.prototype methods
```

Для проверки настоящего массива используйте `Array.isArray(value)`. Проверка через `value instanceof Array` зависит от идентичности конструктора и ломается для массива из другой среды выполнения (realm), например из `iframe`. `Array.isArray` выполняет внутреннюю проверку вида объекта и работает между realms. Она возвращает `false` для `TypedArray`.

```js
Array.isArray([]);                              // true
Array.isArray(new Uint8Array(4));               // false
Array.isArray({ __proto__: Array.prototype });  // false
```

### 🎯 2. Что именно означает `length`?

Для непустого обычного массива `length` обычно равен наибольшему собственному индексу плюс один. Это не число существующих элементов:

```js
const values = [];
values[3] = "x";

console.log(values.length);              // 4
console.log(Object.keys(values).length); // 1
```

Увеличение `length` создаёт диапазон пустых позиций, но не свойства. Уменьшение удаляет собственные индексные свойства на новой границе и правее:

```js
const values = ["a", "b", "c"];
values.length = 5;

console.log(3 in values); // false

values.length = 1;
console.log(values);      // ["a"]
console.log(1 in values); // false
```

Точный спецификационный термин — массивный экзотический объект (Array exotic object): его внутренняя операция определения свойства отдельно обрабатывает индексы массива (array indices) и `length`. Индексы лежат в диапазоне от `0` до `2³² - 2`; строка `"4294967295"`, отрицательные числа, дроби и строки вроде `"01"` остаются обычными ключами и не увеличивают `length`.

```js
const values = [];
values[-1] = "left";
values["01"] = "padded";
values[1.5] = "fraction";

console.log(values.length); // 0
```

🔬 Эта точность полезна, когда вы отлаживаете странный `length`, Proxy или массивоподобный объект. В обычном интервью начните с практичной модели, а не с диапазона `uint32`.

### 🎯 3. Чем hole отличается от явного `undefined`?

В обоих случаях чтение возвращает `undefined`, но структура различается:

```js
const sparse = new Array(3);
const explicit = [undefined, undefined, undefined];

console.log(sparse.length, explicit.length); // 3 3
console.log(sparse[0], explicit[0]);          // undefined undefined
console.log(0 in sparse, 0 in explicit);      // false true
console.log(Object.hasOwn(sparse, 0));        // false
console.log(Object.hasOwn(explicit, 0));      // true
```

Пустой слот — отсутствие собственного индексного свойства внутри диапазона `0…length - 1`. Разреженный массив (sparse array) содержит хотя бы одну такую позицию. В плотном массиве (dense array) каждая позиция диапазона существует, даже если её значение равно `undefined`.

Консоль может показать оба значения похоже, а чтение даст один результат. Поэтому диагностируйте отдельно:

```text
значение: array[index]
наличие по цепочке: index in array
собственное наличие: Object.hasOwn(array, index)
граница: array.length
```

### 🎯 4. Почему `delete items[index]` не удаляет позицию как `splice()`?

`delete` удаляет свойство. Он не сдвигает соседей и не меняет `length`:

```js
const first = ["a", "b", "c"];
delete first[1];

console.log(first.length); // 3
console.log(1 in first);   // false
```

`splice` меняет последовательность: удаляет указанный диапазон, сдвигает элементы и возвращает массив удалённых значений.

```js
const second = ["a", "b", "c"];
const removed = second.splice(1, 1);

console.log(second);  // ["a", "c"]
console.log(removed); // ["b"]
```

Если API моделирует упорядоченный список, обычно нужен `splice` или `toSpliced`. `delete` уместен, когда вы действительно хотите удалить свойство и сохранить разреженный диапазон, что в прикладном коде встречается реже.

### 🎯 5. Какие методы пропускают пустые слоты, а какие их читают?

Нельзя запомнить одно правило «методы массива пропускают пустоты». Смотрите на конкретный контракт.

| Операция | Вызов callback для пустого слота | Результат |
|---|---:|---|
| `map` | нет | сохраняет пустой слот в той же позиции |
| `filter` | нет | возвращает плотный массив выбранных существующих элементов |
| `forEach` | нет | ничего не создаёт |
| `some` / `every` | нет | проверяют только существующие элементы |
| `reduce` | нет | использует только существующие элементы |
| `find` / `findIndex` | да | читает пустой слот как `undefined` |
| `slice` | — | сохраняет пустые слоты в скопированном диапазоне |
| spread / `Array.from` | — | итерация материализует пустые слоты как явные `undefined` |
| `toSorted` / `toSpliced` / `toReversed` / `with` | — | создают плотный результат; пустые слоты становятся `undefined` |

```js
const input = [1, , 3];

console.log(input.map((value) => value * 2)); // [2, <1 empty item>, 6]
console.log(input.filter(() => true));        // [1, 3]
console.log([...input]);                      // [1, undefined, 3]
console.log(input.slice());                   // [1, <1 empty item>, 3]

const visited = [];
input.find((value, index) => {
  visited.push([index, value]);
  return false;
});
console.log(visited); // [[0, 1], [1, undefined], [2, 3]]
```

Унаследованное индексное свойство добавляет ещё один нюанс: методы, использующие проверку наличия свойства, могут увидеть его по цепочке. В рабочем коде не храните индексные данные массива в `Array.prototype`.

### 🎯 6. Как современные копирующие методы обрабатывают разреженный массив?

Методы `toSorted`, `toSpliced`, `toReversed` и `with` создают новый обычный массив и читают каждую позицию. Отсутствующий индекс становится явным `undefined`:

```js
const sparse = ["a", , "c"];

const reversed = sparse.toReversed();
const replaced = sparse.with(0, "A");

console.log(reversed);      // ["c", undefined, "a"]
console.log(1 in reversed); // true
console.log(replaced);      // ["A", undefined, "c"]
console.log(1 in replaced); // true
console.log(1 in sparse);   // false
```

Это не ошибка и не «автоматическое исправление» исходника. Это часть контракта конкретных методов. Если различие hole/`undefined` важно для данных, добавьте отдельный тест границы.

### 🔬 7. Как точно связаны индекс, свойство и `length`?

У массива индекс — специальное имя собственного свойства. Запись за текущей границей поднимает `length`; сокращение `length` пытается удалить индексные свойства справа. Если там есть неконфигурируемое свойство, операция не может выполнить обещанное сокращение полностью и в строгом режиме приводит к ошибке.

```js
"use strict";

const values = ["a", "b", "c"];
Object.defineProperty(values, "2", {
  configurable: false,
  writable: true,
  enumerable: true,
  value: "c",
});

// Намеренно ошибочная операция:
// values.length = 1; // TypeError; индекс 2 нельзя удалить
```

Для большинства задач достаточно помнить инвариант `length > каждый собственный array index`. Подробный алгоритм `ArraySetLength` нужен лишь при дополнительном вопросе о дескрипторах.

## Мутация и новые контейнеры

### 🎯 8. Какие основные методы меняют исходный массив и что возвращают?

| Метод | Меняет вход | Возвращает | `length` |
|---|---:|---|---|
| `push(...items)` | да | новую длину | растёт |
| `pop()` | да | удалённый последний элемент или `undefined` | уменьшается, если не пуст |
| `unshift(...items)` | да | новую длину | растёт |
| `shift()` | да | удалённый первый элемент или `undefined` | уменьшается, если не пуст |
| `splice(start, count, ...items)` | да | новый массив удалённых элементов | зависит от удаления/вставки |
| `sort(compareFn?)` | да | ту же ссылку на массив | обычно та же |
| `reverse()` | да | ту же ссылку на массив | та же |
| `fill(value, start?, end?)` | да | ту же ссылку на массив | та же |
| `copyWithin(target, start, end?)` | да | ту же ссылку на массив | та же |

Частая ошибка — присвоить результат `push` как будто это массив:

```js
const items = ["a"];
const result = items.push("b");

console.log(result); // 2, не ["a", "b"]
console.log(items);  // ["a", "b"]
```

`sort` и `reverse`, наоборот, возвращают тот же массив, поэтому цепочка выглядит функционально, хотя вход уже изменён:

```js
const input = [3, 1, 2];
const output = input.sort((a, b) => a - b);

console.log(output === input); // true
```

Ссылки на элементы не копируются. Перестановка массива перемещает ссылки, а не клонирует объекты.

### 🎯 9. `slice` и `splice`: как не путать похожие имена?

```text
slice(start, end)                  → новый диапазон, end не включён
splice(start, deleteCount, ...x)  → меняет исходник, возвращает удалённое
```

```js
const source = ["a", "b", "c", "d"];

console.log(source.slice(1, 3)); // ["b", "c"]
console.log(source);             // исходник не изменён

console.log(source.splice(1, 2, "x")); // ["b", "c"]
console.log(source);                    // ["a", "x", "d"]
```

Мнемоника помогает только вспомнить начальную развилку. На ревью всё равно проверяйте вход и возвращаемое значение.

### 🎯 10. Когда мутация является ошибкой, а когда нормальным решением?

Мутация опасна, когда функция меняет данные, которыми владеет вызывающий код, а контракт этого не обещает:

```js
function sortedUsers(users) {
  return users.sort((a, b) => a.name.localeCompare(b.name));
}

const users = [{ name: "Lin" }, { name: "Ada" }];
sortedUsers(users);
// users тоже переставлен
```

Ясные варианты:

```js
function sortedUsers(users) {
  return users.toSorted((a, b) => a.name.localeCompare(b.name));
}

function sortUsersInPlace(ownedUsers) {
  ownedUsers.sort((a, b) => a.name.localeCompare(b.name));
  return ownedUsers;
}
```

Локальная мутация нового, никому не переданного результата часто проще и дешевле постоянного копирования:

```js
function indexById(items) {
  const result = Object.create(null);

  for (const item of items) {
    result[item.id] = item;
  }

  return result;
}
```

Инженерное правило: сначала определите владельца и наблюдателей объекта. Неизменяемый публичный контракт и локальная мутация реализации могут сосуществовать.

### 🎯 11. Какие операции создают новый массив, но остаются поверхностными?

| Операция | Намерение | Важная деталь |
|---|---|---|
| `array.slice()` | копия диапазона | сохраняет пустые слоты |
| `array.concat(other)` | соединение | поверхностная копия; учитывает распространяемые массивы |
| `[...array]` | копия через встроенную итерацию | пустые слоты → `undefined` |
| `Array.from(arrayLike)` | материализация/преобразование | поверхностная копия; можно передать функцию преобразования |
| `toSorted(compareFn)` | сортировка копии | исходник не меняется; плотный результат |
| `toSpliced(...)` | вставка/удаление в копии | возвращает итог, а не удалённое |
| `toReversed()` | разворот копии | исходник не меняется |
| `with(index, value)` | замена одной позиции в копии | отрицательный индекс допустим; вне диапазона `RangeError` |

```js
const rows = [{ id: 1 }, { id: 2 }];
const copy = rows.toReversed();

console.log(copy === rows);       // false
console.log(copy[1] === rows[0]); // true
```

`with` не расширяет массив:

```js
const values = ["a", "b", "c"];

console.log(values.with(-1, "C")); // ["a", "b", "C"]

// Намеренно ошибочная операция:
// values.with(3, "d"); // RangeError
```

Современные немутирующие методы массива из семейства Change Array by Copy вошли в ECMAScript 2023 и доступны в актуальных средах 2026 года. Для старых поддерживаемых окружений проверяйте целевые версии среды и применяемый полифил.

🧓 До этих API часто писали `[...items].sort(compareFn)`, `items.slice().reverse()` или комбинации `slice`. Их нужно узнавать, но современные методы точнее выражают намерение, когда среда их поддерживает.

## Преобразования и запросы

### 🎯 12. Как выбирать `map`, `filter`, `find`, `some`, `every`, `forEach` и `reduce`?

Начните с формы результата:

| Вопрос | Метод | Результат |
|---|---|---|
| один результат на каждый существующий элемент | `map` | новый массив той же длины; пустые слоты сохраняются |
| оставить подмножество | `filter` | новый массив выбранных значений |
| найти первое подходящее значение | `find` | элемент или `undefined` |
| существует хотя бы одно подходящее? | `some` | boolean, short-circuit на `true` |
| подходят все? | `every` | boolean, short-circuit на `false` |
| выполнить эффект для каждого существующего | `forEach` | всегда `undefined` |
| свернуть несколько значений в один результат | `reduce` | accumulator |

У `map`, `filter`, `find`, `some`, `every` и `forEach` функция обратного вызова (callback) получает `(value, index, array)`. У `reduce` — `(accumulator, value, index, array)`.

Не выбирайте `reduce` только потому, что он способен выразить любую свёртку. Ясный цикл лучше, если аккумулятор меняет сложную форму, нужны ранний выход, несколько состояний или последовательность трудно прочитать.

### 🎯 13. Чем `map` отличается от `forEach`?

`map` описывает преобразование и использует возвращаемое значение callback. `forEach` игнорирует его и предназначен для побочного эффекта:

```js
const values = [1, 2, 3];

const doubled = values.map((value) => value * 2);
values.forEach((value) => console.log(value));

console.log(doubled); // [2, 4, 6]
```

Ловушка с фигурными скобками:

```js
const wrong = values.map((value) => {
  value * 2;
});

console.log(wrong); // [undefined, undefined, undefined]
```

Нужен явный `return value * 2` или выражение без блока. Использование `map` только ради побочного эффекта создаёт ненужный массив; использование `forEach` в надежде получить массив возвращает `undefined`.

### 🎯 14. Какие ловушки есть у `filter`, `find`, `some` и `every`?

`filter(Boolean)` удаляет все ложные значения (falsy values), а не только отсутствующие:

```js
const readings = [0, 1, null, 2, "", 3, false];
console.log(readings.filter(Boolean)); // [1, 2, 3]
```

Если `0`, пустая строка или `false` допустимы, задайте точный predicate:

```js
readings.filter((value) => value !== null && value !== undefined);
```

`find` возвращает `undefined` и при отсутствии совпадения, и когда найденный элемент сам равен `undefined`. Если различие важно, используйте `findIndex` и проверяйте `-1`.

На пустом массиве:

```js
[].some(() => true);   // false: не существует подходящего элемента
[].every(() => false); // true: нет контрпримера
```

Это математические кванторы «существует» и «для всех». Пустое `every` часто удивляет в валидации: отдельно проверьте непустоту, если она входит в бизнес-условие.

### 🎯 15. Почему `reduce` обычно получает явный `initialValue`?

С начальным значением форма аккумулятора определена самим вызовом:

```js
const total = [2, 3, 4].reduce(
  (sum, value) => sum + value,
  0,
);
```

Без `initialValue` первый существующий элемент становится аккумулятором, а обход начинается со следующего. Пустой массив без существующих элементов приводит к `TypeError`:

```js
// Намеренно ошибочная операция:
// [].reduce((sum, value) => sum + value); // TypeError
```

На разреженном массиве алгоритм ищет первый существующий индекс, а не просто позицию `0`. Явное начальное значение делает пустой случай предсказуемым, фиксирует форму аккумулятора и уменьшает зависимость от типа первого элемента. Для сложного состояния обычный цикл может быть яснее.

### 🎯 16. Почему `forEach(async () => ...)` не ждёт работу?

Контракт `forEach` синхронный: он вызывает callback и игнорирует возвращаемое значение. `async` callback возвращает Promise, но `forEach` его не собирает и не ожидает.

```js
const result = [1, 2, 3].forEach(async (id) => {
  await save(id);
});

console.log(result); // undefined
```

`map(async ...)` вернёт массив объектов `Promise`, а не массив готовых значений. Дальнейшая координация зависит от требования и разбирается в 1.10–1.11. Для 1.5 достаточно распознать несоответствие договору callback.

### 🎯 17. Что происходит, если менять массив во время обхода через callback?

Методы вроде `map`, `filter`, `forEach`, `some`, `every` и `reduce` фиксируют исходную длину перед первым вызовом callback. Элементы, добавленные за эту границу, не будут посещены. Значение существующего индекса читается в момент посещения; удалённая до посещения позиция обычно пропускается.

```js
const values = [1, 2, 3];
const seen = [];

values.forEach((value, index) => {
  seen.push(value);
  if (index === 0) {
    values.push(4);
    values[2] = 30;
  }
});

console.log(seen); // [1, 2, 30]
```

`find` отличается: он посещает каждый индекс исходного диапазона и читает удалённую позицию как значение из прототипа или `undefined`. Изменение длины, `shift` или `splice` во время обхода легко приводит к пропускам. Обычно подготовьте новый массив или используйте явный цикл с документированной логикой индекса.

## Сортировка

### 🎯 18. Почему `[10, 2].sort()` даёт неожиданный результат?

Без функции сравнения элементы превращаются в строки и сравниваются по последовательностям кодовых единиц UTF-16:

```js
const values = [10, 2, 30];
console.log(values.sort()); // [10, 2, 30]
```

Для чисел нужна функция сравнения:

```js
values.sort((a, b) => a - b); // по возрастанию
values.sort((a, b) => b - a); // по убыванию
```

Знак результата задаёт отношение:

```text
< 0 → a раньше b
> 0 → a позже b
  0 → элементы равны для этой сортировки
```

Comparator `(a, b) => a > b` неверен: он возвращает только `true`/`false`, то есть `1`/`0`, и не даёт отрицательного ответа при обратном порядке. Нарушается anti-symmetry, поэтому разные движки вправе получить разные результаты.

### 🔬 19. Как объяснить корректную функцию сравнения без лишней теории?

Для интервью достаточно четырёх правил:

1. Чистота: одинаковая пара даёт одинаковый результат и не меняет внешнее состояние.
2. Равенство: сравнение равных по ключу элементов возвращает `0`.
3. Anti-symmetry: если `a` идёт раньше `b`, то при перестановке аргументов `b` идёт позже `a`.
4. Transitivity: если `a < b` и `b < c`, то `a < c`.

Спецификация требует стабильную сортировку: элементы, для которых функция сравнения возвращает `0`, сохраняют взаимный порядок. Сравнение по нескольким полям можно строить явно:

```js
const collator = new Intl.Collator("en", { sensitivity: "base" });

const byScoreThenName = (a, b) =>
  b.score - a.score || collator.compare(a.name, b.name);

const ranked = users.toSorted(byScoreThenName);
```

`localeCompare` подходит для единичного сравнения строк. Повторно используемый `Intl.Collator` удобен при большой сортировке с локалью и опциями. Доменные `null`, `undefined` и невалидные числа нормализуйте до вызова функции сравнения или обработайте явно.

### 🎯 20. Чем `sort` отличается от `toSorted`?

Оба используют один договор функции сравнения и стабильную сортировку. Различается владение контейнером:

```js
const source = [{ score: 2 }, { score: 1 }];
const copied = source.toSorted((a, b) => a.score - b.score);

console.log(source.map((x) => x.score)); // [2, 1]
console.log(copied.map((x) => x.score)); // [1, 2]
console.log(copied[0] === source[1]);     // true
```

`sort` меняет исходный массив и возвращает его же. `toSorted` создаёт новый массив, но элементы остаются общими ссылками. На разреженном массиве `sort` сохраняет число пустых слотов и переносит их в конец после явных `undefined`; `toSorted` материализует пустые слоты как `undefined`.

Спецификация гарантирует порядок при корректном comparator и стабильность, но не универсальный алгоритм и не конкретную временную или пространственную сложность. Для огромных массивов измеряйте выбранную среду и реальные данные.

## Destructuring, rest и spread

### 🎯 21. Как деструктуризация массива читает значения и применяет значения по умолчанию?

```js
const input = ["Ada", undefined, null, ["admin"]];
const [name, status = "idle", note = "none", [role]] = input;

console.log(name);   // "Ada"
console.log(status); // "idle"
console.log(note);   // null
console.log(role);   // "admin"
```

Default применяется только когда извлечённое значение равно `undefined`: отсутствующая позиция, hole или явный `undefined`. `null` считается намеренным значением и default не включает.

Можно пропускать позиции и собирать остаток:

```js
const [first, , third, ...rest] = [1, 2, 3, 4, 5];
// first = 1, third = 3, rest = [4, 5]
```

Rest element должен быть последним и создаёт новый массив. Обмен значений выражается как `[left, right] = [right, left]`. Объектный destructuring извлекает свойства, умеет переименовывать и применяет те же defaults:

```js
const { name: displayName, status = "idle" } = user;
```

Rest parameter функции из 1.3 собирает оставшиеся аргументы в настоящий массив. Это другой синтаксический контекст с похожей идеей «собрать остаток».

### 🎯 22. Почему spread означает разные операции в разных местах?

В массиве и списке аргументов spread требует итерируемое значение (iterable). Мы используем встроенное поведение массива; устройство протокола остаётся в 1.6.

```js
const merged = [...left, ...right];
fn(...args);
```

В объектном литерале spread перечисляет собственные перечисляемые строковые и Symbol-ключи источника:

```js
const options = { timeout: 1000, ...defaults, ...overrides };
```

Позднее свойство перезаписывает значение предыдущего. Все эти копии поверхностны. Кроме того, `fn(...veryLargeArray)` может превысить внутренний лимит числа аргументов движка; универсального безопасного порога спецификация не задаёт. Для агрегации большого массива используйте цикл или подходящий метод.

### 🎯 23. Чем object spread отличается от `Object.assign` и копирования дескрипторов?

Оба подхода читают собственные перечисляемые строковые свойства и свойства с ключами-символами, поэтому геттеры источника могут выполниться. Но запись различается:

```js
const target = {
  set value(next) {
    console.log("setter", next);
  },
};

Object.assign(target, { value: 1 }); // вызывает setter целевого объекта
const copy = { ...target, value: 2 }; // обычное свойство в новом объекте
```

`Object.assign(target, source)` использует обычную запись `[[Set]]` в существующий целевой объект и может вызвать сеттер. Object spread создаёт собственные свойства данных в новом объекте.

Ни один вариант не переносит исходный дескриптор как дескриптор. Геттер вычисляется, а результат становится обычным изменяемым свойством. Если договор требует сохранить дескрипторы:

```js
const clone = Object.defineProperties(
  {},
  Object.getOwnPropertyDescriptors(source),
);
```

Это всё ещё поверхностная операция и не воспроизводит автоматически прототип или внутренние слоты.

## Поверхностная копия и структурное разделение

### 🎯 24. Как нарисовать поверхностную копию?

```js
const original = [
  { id: 1, meta: { selected: false } },
  { id: 2, meta: { selected: false } },
];

const copy = [...original];
copy[0].meta.selected = true;

console.log(original[0].meta.selected); // true
```

```text
original ──> Array A ──[0]──> Row X ──meta──> Meta M
copy     ──> Array B ──[0]──> Row X ──meta──> Meta M
```

Скопирован только внешний контейнер. Поверхностная копия (shallow copy) переносит значения верхнего уровня, а значения-объекты остаются ссылками на те же сущности. `slice`, `concat`, spread, `Array.from`, object spread и `Object.assign` ведут себя поверхностно в своей области.

Общая ссылка (aliasing) означает, что два пути приводят к одному изменяемому объекту. Это может быть намеренным разделением или ошибкой владения; копирующий синтаксис сам не решает вопрос.

### 🎯 25. Что такое структурное разделение и как копировать только изменяемый путь?

Если меняется один вложенный элемент, можно создать новые контейнеры вдоль пути, а остальные ветви сохранить:

```js
function selectRow(rows, id) {
  return rows.map((row) =>
    row.id === id
      ? {
          ...row,
          meta: { ...row.meta, selected: true },
        }
      : row,
  );
}
```

```text
oldRows ─> Array A ─> Row 1 ─> Meta 1
                  └─> Row 2 ─> Meta 2

newRows ─> Array B ─> Row 1' ─> Meta 1'   new changed path
                  └─> Row 2 ───> Meta 2    shared unchanged branch
```

Это даёт новые идентичности для изменённого пути и сохраняет неизменившиеся ветви. Сравнение ссылок позволяет быстро заметить изменение. Но это не глубокая неизменяемость: код должен соблюдать договор «общие ветви больше не мутируются».

### 🎯 26. Когда копирование само становится проблемой?

Цепочка `filter().map().toSorted()` ясна и часто достаточна, но создаёт промежуточные массивы. На больших или горячих путях один цикл может быть проще и экономнее:

```js
const result = [];

for (const item of items) {
  if (!item.active) continue;
  result.push(toViewModel(item));
}

result.sort(compareViewModels); // локальная мутация принадлежащего функции результата
```

Не оптимизируйте по догадке. Сначала проверьте объём данных, частоту вызова, память, читаемость и фактический профиль. Контракт важнее синтаксиса.

## Глубокая копия как договор

### 🎯 27. Почему универсального «клонировать всё» нет?

JavaScript-значение может быть графом, а не деревом:

```js
const shared = { count: 1 };
const graph = { first: shared, second: shared };
graph.self = graph;
```

Корректная для одного продукта копия может требовать:

- сохранить цикл `clone.self === clone`;
- сохранить повторную ссылку `clone.first === clone.second`;
- отделить новые объекты от исходных;
- сохранить `Date`, `Map`, `Set`, буферы и типизированные массивы;
- решить, что делать с пользовательскими прототипами и экземплярами классов;
- определить судьбу дескрипторов, геттеров/сеттеров, неперечисляемых свойств и ключей-символов;
- отклонить или разделить функции, DOM-узлы, внешние ресурсы и закрытое/внутреннее состояние;
- контролировать стоимость обхода и возможное выполнение геттера/`toJSON`.

Поэтому варианты выбирают по модели данных:

1. Ручное копирование известной доменной схемы — самое явное, если поддерживаемых типов мало.
2. `structuredClone` — стандартный алгоритм для поддерживаемого графа данных.
3. Цикл JSON-сериализации и разбора — только для намеренно JSON-совместимой модели и с принятыми преобразованиями.
4. Библиотека — если её документированный контракт действительно нужен и покрыт тестами.

Глубокая копия может скрывать исходную проблему: два слоя не договорились, кто владеет объектом. Иногда лучше нормализовать данные на входе или предоставить явный API обновления.

### 🎯 28. Что гарантирует `structuredClone`?

`structuredClone(value)` применяет алгоритм структурированного клонирования (structured clone algorithm) и возвращает отдельный граф поддерживаемых значений. Алгоритм ведёт таблицу уже посещённых ссылок, поэтому сохраняет циклы и повторные ссылки внутри результата:

```js
const shared = { count: 1 };
const source = {
  first: shared,
  second: shared,
  date: new Date("2026-01-01T00:00:00Z"),
};
source.self = source;

const clone = structuredClone(source);

console.log(clone !== source);             // true
console.log(clone.self === clone);         // true
console.log(clone.first === clone.second); // true
console.log(clone.first !== source.first); // true
console.log(clone.date instanceof Date);   // true
```

Основные поддерживаемые группы: примитивы кроме `symbol`, обычные объекты, массивы, `Date`, `RegExp`, `Map`, `Set`, `ArrayBuffer`, типизированные массивы, `DataView`, многие объекты `Error` и определённые типы Web API. Точный список типов среды зависит от стандарта и платформы.

Неподдерживаемая часть графа, например функция или DOM-узел в браузере, приводит к `DataCloneError`. `Promise`, `WeakMap` и объекты с неподдерживаемыми внутренними слотами также не становятся магически копируемыми.

### 🔬 29. Что `structuredClone` не сохраняет у пользовательских объектов?

Алгоритм не является копированием JavaScript-объекта «как есть»:

- экземпляр пользовательского класса обычно восстанавливается как обычный объект, без пользовательской цепочки прототипов и закрытых полей;
- дескрипторы свойств, определения геттеров/сеттеров и ограничения `writable`/`configurable` не воспроизводятся;
- функции не клонируются;
- примитив `Symbol` не поддерживается, а свойства с ключами-символами не являются надёжной частью переносимого договора клонирования;
- `RegExp.lastIndex` не сохраняется;
- DOM-узлы не поддерживаются;
- внешнее состояние и ресурсы среды подчиняются отдельным правилам платформы.

```js
class User {
  constructor(name) {
    this.name = name;
  }

  greet() {
    return `Hi, ${this.name}`;
  }
}

const clone = structuredClone(new User("Ada"));

console.log(clone.name);            // "Ada"
console.log(clone instanceof User); // false в проверенной среде
console.log(typeof clone.greet);    // "undefined"
```

Аксессор может быть прочитан во время получения сериализуемых данных, но его функция и дескриптор не переносятся. Не используйте `structuredClone` как способ сохранить модель поведения класса.

### 🎯 30. Чем перенос владения отличается от копирования?

Для передаваемых ресурсов (transferables) можно передать владение вместо копирования. Наиболее понятный пример — `ArrayBuffer`:

```js
const buffer = new ArrayBuffer(8);
new Uint8Array(buffer)[0] = 42;

const clone = structuredClone(
  { buffer },
  { transfer: [buffer] },
);

console.log(buffer.byteLength);               // 0: исходный buffer отсоединён
console.log(clone.buffer.byteLength);         // 8
console.log(new Uint8Array(clone.buffer)[0]); // 42
```

После переноса исходный ресурс становится непригодным для прежнего использования. Это наблюдаемая смена владения, а не оптимизация, которую нужно включать автоматически. Список передаваемых типов задаётся платформой. Отдельно тестируйте отсоединение исходного ресурса и обработку ошибок.

### 🎯 31. Почему `JSON.parse(JSON.stringify(value))` — ненадёжная глубокая копия?

JSON описывает формат данных, а не полную модель JavaScript-объектов. Цикл сериализации и разбора имеет намеренные преобразования:

| Вход | Результат / проблема |
|---|---|
| цикл | `TypeError` |
| `BigInt` | `TypeError`, если нет явного `toJSON` |
| свойство объекта со значением `undefined`, функцией или `Symbol` | свойство пропускается |
| те же значения в массиве / пустой слот | `null` |
| `NaN`, `Infinity`, `-Infinity` | `null` |
| `Date` | строка через `toJSON` |
| `Map`, `Set` без replacer | обычно `{}` |
| пользовательский прототип / дескрипторы / аксессоры | не восстанавливаются |
| повторная ссылка без цикла | сериализуется дважды; общая ссылка теряется |
| пользовательский `toJSON` | может произвольно заменить представление |

```js
const shared = { value: 1 };
const source = { first: shared, second: shared };
const clone = JSON.parse(JSON.stringify(source));

console.log(clone.first === clone.second); // false
```

Такой цикл допустим, если модель по договору уже совместима с JSON и потеря специфической семантики JavaScript принята. Тогда это сериализация и чтение нового представления, а не универсальное клонирование.

## Частые ошибки

1. Считать `length` числом реально существующих элементов.
2. Определять пустой слот только по `array[index] === undefined`.
3. Обобщать поведение одного метода на разреженном массиве на все методы.
4. Использовать `delete` как удаление элемента последовательности.
5. Принимать результат `push` или `unshift` за массив.
6. Забывать, что `sort`, `reverse` и `splice` меняют вход.
7. Считать новый массив глубокой копией элементов.
8. Использовать `map` ради побочного эффекта или `forEach` ради результата.
9. Терять значимые `0`, `false` и `""` через `filter(Boolean)`.
10. Вызывать `reduce` без начального значения для потенциально пустого массива.
11. Ожидать, что `forEach` дождётся `Promise` из callback.

## Практические рекомендации

- Сначала определите владельца массива и наблюдателей его изменений.
- Назовите мутацию в API или возвращайте новый контейнер; не оставляйте контракт случайным.
- Выбирайте метод преобразования по форме результата, а не по моде.
- Отделяйте чистое преобразование от логирования, сети и других побочных эффектов.
- Используйте `toSorted`, `toSpliced`, `toReversed` и `with`, когда они точнее выражают неизменяемое обновление и входят в целевые версии среды.
- Не копируйте автоматически на каждой границе: иногда нужна передача владения или документированная локальная мутация.
- Не используйте глубокую копию как универсальную изоляцию. Сначала уточните модель данных.
- При структурном разделении копируйте изменяемый путь и не мутируйте общие ветви позднее.
- Для больших данных учитывайте временные массивы и сборку мусора; измеряйте реальный путь.
- Выбирайте цикл, если цепочка методов скрывает алгоритм или требует сложного аккумулятора.
- Тестируйте функцию сравнения на равных значениях, обратных парах и транзитивности.
- Тестируйте границу клонирования на циклах, повторных ссылках, поддерживаемых встроенных типах, ошибках и отсоединении после переноса.

## 🧓 Legacy и совместимость

- `slice().sort()`, `[...items].sort()` и `slice().reverse()` остаются распространёнными способами копирования до методов семейства Change Array by Copy.
- `instanceof Array` нужно узнавать, но для внешних значений предпочтительнее `Array.isArray`.
- Ручные циклы не являются устаревшими: они уместны, когда яснее выражают контроль, ранний выход или уменьшают промежуточные результаты.
- Цикл JSON-сериализации встречается как короткий обходной путь; воспринимайте его только как явно ограниченную JSON-нормализацию.
- Политика полифилов и транспиляции определяется целевыми средами проекта. Наличие современного метода в стандарте не заменяет проверку совместимости конкретного продукта.

## Как объяснить на интервью за 30–60 секунд

### Плотные и разреженные массивы

> `length` задаёт верхнюю границу индексов, но не число существующих элементов. Пустой слот (hole) — отсутствующее индексное свойство внутри этой границы; явный `undefined` — существующее свойство со значением `undefined`. Чтение обоих даёт `undefined`, поэтому я проверяю `index in array` или `Object.hasOwn`. Методы ведут себя по-разному: `map` сохраняет пустые слоты, `filter` их пропускает, `find` посещает как `undefined`, `slice` сохраняет, а spread и новые копирующие методы материализуют `undefined`.

### Мутирующие и копирующие API

> Я сначала выясняю владельца массива. `push`, `pop`, `shift`, `unshift`, `splice`, `sort` и `reverse` меняют исходник, причём возвращаемые значения у них различаются. `slice`, `concat`, spread и `toSorted`/`toSpliced`/`toReversed`/`with` создают новый контейнер. Но все эти копии поверхностны: вложенные объекты остаются общими ссылками. Локальная мутация принадлежащего функции результата нормальна; неожиданная мутация входа — ошибка договора.

### Выбор метода преобразования

> Форма результата задаёт метод: `map` — один результат на элемент, `filter` — подмножество, `find` — первый элемент, `some`/`every` — логический вопрос с ранним выходом, `forEach` — побочный эффект без результата, `reduce` — свёртка. Я не использую `reduce` как замену любому циклу. Дополнительно проверяю пустые слоты, возврат callback, пустой вход и то, что синхронные callback массивов не ожидают `Promise`.

### Функция сравнения

> `sort` мутирует массив и по умолчанию сравнивает строковые представления. Функция сравнения должна возвращать отрицательное число, ноль или положительное число, быть чистой, антисимметричной и транзитивной; равные ключи дают ноль. Современная сортировка стабильна, но конкретный алгоритм и сложность спецификацией не фиксированы. Если вход менять нельзя, использую `toSorted`. Для нескольких полей объединяю сравнения через `primary || secondary`.

### Поверхностная копия и структурное разделение

> Поверхностная копия (shallow copy) создаёт новый внешний контейнер, но переносит те же ссылки на объекты, поэтому вложенная мутация видна через обе структуры. При неизменяемом обновлении я копирую только контейнеры на изменяемом пути, а неизменившиеся ветви намеренно разделяю. Это даёт предсказуемые новые идентичности для обнаружения изменений без полного клонирования, но требует больше не мутировать общие ветви.

### `structuredClone`

> `structuredClone` копирует поддерживаемый граф, сохраняя циклы и повторные ссылки внутри результата. Он умеет многие встроенные типы, включая `Date`, `Map`, `Set`, буферы и типизированные массивы, но функции и DOM-узлы приводят к `DataCloneError`. Пользовательский прототип, методы, закрытые поля и дескрипторы не сохраняются как модель класса. Передаваемые ресурсы можно переместить без копирования, но исходный буфер станет отсоединённым. Поэтому сначала определяю договор клонирования и тестирую границу типов.
