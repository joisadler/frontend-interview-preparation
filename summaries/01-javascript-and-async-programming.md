## 1.1. Execution Model, Declarations & Scope

> Быстрое повторение: [полная глава](../handbook/01-javascript-and-async-programming/01-execution-model-declarations-and-scope.md) · [инфографика на английском, A4](../infographics/01-javascript-and-async-programming/01-execution-model-declarations-and-scope.pdf)

### 🧠 Одна модель

Программа как офис с комнатами:

- **область видимости (scope)** = комната;
- **привязка (binding)** = запись имени в журнале комнаты;
- **поиск имени (identifier resolution)** = движение от текущей комнаты наружу;
- **затенение (shadowing)** = ближняя запись с тем же именем скрывает дальнюю;
- **поднятие объявлений (hoisting)** = журнал готовят заранее, но код физически не двигают;
- **временная мёртвая зона (Temporal Dead Zone, TDZ)** = имя уже записано, но доступ ещё закрыт;
- **стек вызовов (call stack)** = стопка незавершённых вызовов: последний вошёл → первый вышел.

### ⚡ Термины и жизненный цикл

**Идентификатор (identifier)** — имя в коде → **привязка (binding)** связывает имя с состоянием → **значение (value)** хранится в привязке.

Объявление создаёт имя → инициализация впервые записывает значение → последующее присваивание меняет его.

| Объявление | Область видимости | До своей строки | Переназначение | Повторное объявление в той же области |
|---|---|---|---:|---:|
| `var` | функция / верхний уровень обычного скрипта | `undefined` | ✅ | обычно ✅ |
| `let` | блок | TDZ → `ReferenceError` | ✅ | ❌ |
| `const` | блок | TDZ → `ReferenceError` | ❌ | ❌ |

🎯 В новом коде: `const` по умолчанию → `let`, если нужно переназначение → `var` только для чтения устаревшего кода и интервью. `const` запрещает переназначение привязки, но **не** делает объект неизменяемым.

### Области видимости и поиск имени

- **глобальная область** — глобальные имена среды;
- **область модуля** — верхний уровень ES-модуля, который не становится глобальным объектом;
- **область функции** — параметры, локальные имена и `var`;
- **область блока** — `{}`, `if`, `for`, `switch`; действует для `let` / `const`, но не для обычного `var`;
- **лексическая область видимости** — доступность имени определяется местом написания функции, а не местом её вызова.

Поиск: текущая область → внешняя → ещё внешняя → имя не найдено = `ReferenceError`. Если ближайшая привязка найдена, но находится в TDZ, поиск **не** перескакивает к внешнему имени.

Свойство объекта — другой механизм: неизвестное имя → `ReferenceError`; отсутствующее `object.key` → обычно `undefined`.

### Модель выполнения

- До обычного выполнения JavaScript подготавливает объявления и проверяет конфликты.
- **Контекст выполнения (execution context)** — активное состояние выполняемого скрипта, модуля или функции.
- Вызов функции добавляет контекст в стек вызовов; обычный блок создаёт область видимости, но не новый кадр стека.
- **Лексическое окружение / запись окружения (Lexical Environment / Environment Record)** — спецификационная модель хранения привязок и ссылки на внешнее окружение. Это не обязательно обычные JavaScript-объекты.

### Поднятие объявлений, TDZ и функции

- `var` читается раньше своей строки как `undefined`.
- `let` / `const` / `class` существуют раньше строки, но до инициализации находятся в TDZ.
- `typeof undeclaredName` → `"undefined"`, но `typeof name` для имени в TDZ → `ReferenceError`.
- Объявление функции (function declaration) обычно можно вызвать раньше его строки.
- `var fn = function…` раньше строки → `fn === undefined` → вызов даёт `TypeError`.
- `const fn = function…` раньше строки → TDZ → `ReferenceError`.

### Затенение и конфликты объявлений

- **Затенение**: одинаковое имя в разных вложенных областях обычно допустимо.
- **Повторное объявление (redeclaration)**: новое объявление имени в той же эффективной области.
- `let` / `const` конфликтуют друг с другом и с `var` той же области → обычно `SyntaxError` до выполнения.
- Внешний `var` + внутренний блочный `let` — допустимо.
- Внешний `let` + `var` внутри обычного блока — конфликт: `var` принадлежит окружающей функции или глобальной области. Это часто называют **недопустимым затенением (illegal shadowing)**.
- Все `case` одного `switch` делят одну блочную область; отдельные `{}` предотвращают конфликты.

### Глобальный код, строгий режим и устаревшее поведение

| Где верхний уровень | Что происходит |
|---|---|
| обычный браузерный скрипт | `var` часто становится свойством `globalThis`; `let` / `const` — нет |
| браузерный или Node.js ES-модуль | все объявления принадлежат модулю; строгий режим включён автоматически |
| Node.js CommonJS | файл обёрнут функцией; верхние объявления локальны для модуля |

- Присваивание необъявленному имени в обычном скрипте без строгого режима может создать **случайную глобальную переменную (accidental global)**; в строгом режиме будет `ReferenceError`.
- `delete` удаляет свойство объекта, но не привязку переменной.
- 🧓 `with`, прямой `eval`, блочные функции из Annex B — узнавать на интервью и в старом коде, но не использовать в современном решении.

### Следствие для замыканий

Замыкание (closure) сохраняет доступ к привязке, а не копирует её значение: `for (var i…)` → одна общая `i`, более поздние колбэки обычно видят итоговое значение; `for (let i…)` → отдельная привязка для каждой итерации.

### 🪤 Как предсказывать результат

1. Уточни среду: обычный скрипт / ES-модуль / CommonJS.
2. Проверь ранние конфликты: если `SyntaxError`, выполнение не начнётся.
3. Отметь границы функций и блоков.
4. Выпиши привязки и их начальное состояние: `undefined` / TDZ / функция.
5. Для каждого имени ищи от текущей области наружу.
6. Только теперь выполняй строки и называй точный результат: значение / `undefined` / `ReferenceError` / `TypeError` / `SyntaxError`.

### 🗣️ Ответ за 30–60 секунд

> Область видимости определяет, к какой привязке относится имя. Поиск начинается в текущей лексической области и идёт наружу. До построчного выполнения объявления подготавливаются: `var` получает `undefined`, `let` и `const` остаются в TDZ, а привязка объявления функции обычно уже содержит функцию. Поэтому поднятие объявлений — не перенос кода, а наблюдаемый результат предварительной подготовки.

### ✅ Быстрая самопроверка

- Могу без подсказки сравнить `var` / `let` / `const`.
- Отличаю область видимости, контекст выполнения и стек вызовов.
- Объясняю поднятие объявлений без фразы «код переносится вверх».
- Предсказываю TDZ, затенение, конфликты объявлений и ошибки функциональных выражений.
- Уточняю среду выполнения перед вопросом про `globalThis`.
- Объясняю разницу `for (var…)` и `for (let…)` через привязки.

## 1.2. Values, Types, Equality & Coercion

> Быстрое повторение: [полная глава](../handbook/01-javascript-and-async-programming/02-values-types-equality-and-coercion.md) · [инфографика на английском, A4](../infographics/01-javascript-and-async-programming/02-values-types-equality-and-coercion.pdf)

### Значения, идентичность и мутация

`привязка → значение`; объект обладает собственной **идентичностью (identity)**.

| Примитивы — неизменяемы | Объекты — по умолчанию изменяемы |
|---|---|
| `undefined`, `null`, `boolean`, `number`, `bigint`, `string`, `symbol` | объекты, массивы, функции, даты… |
| операция создаёт новое значение | свойства существующего объекта можно менять |
| сравнение обычно идёт по значению | равенство объектов проверяет идентичность |

`const` запрещает **переназначение привязки**, но не мутацию объекта. `{ ...source }` и `Object.assign({}, source)` создают **поверхностную копию (shallow copy)**: внешний объект новый, а вложенные объекты остаются общими.

Аргументы всегда передаются **по значению (pass by value)**. Если аргумент — объект, параметр получает копию значения, указывающего на тот же объект. Поэтому вызывающий код видит мутацию этого объекта, но не переназначение самого параметра.

### Проверка типа и особые числовые значения

```text
typeof null        → "object"      typeof []          → "object"
typeof function(){}→ "function"    typeof NaN         → "number"
typeof 1n          → "bigint"      typeof Symbol()    → "symbol"
```

- `typeof undeclaredName` → `"undefined"`; но имя в TDZ → `ReferenceError`.
- `undefined` обычно означает отсутствие значения; `null` — намеренно пустое значение по контракту.
- `Symbol()` создаёт уникальный примитив, пригодный как ключ свойства; `Symbol("x") !== Symbol("x")`.
- BigInt хранит целые числа произвольной точности: `1n + 2n` ✅, `1n + 2` → `TypeError`; деление отбрасывает дробную часть.
- `NaN !== NaN`; надёжная проверка → `Number.isNaN(value)`.
- Глобальная `isNaN` сначала преобразует аргумент; `Number.isNaN` этого не делает.
- `Number.isFinite` и `Number.isSafeInteger` проверяют разные ограничения.
- `Object.is(-0, 0) === false`; `1 / -0 === -Infinity`.

Числа с плавающей точкой: `0.1 + 0.2 !== 0.3`. Для измерений используйте допустимую абсолютную и относительную погрешность предметной области. Деньги с фиксированной точностью храните в целых минимальных единицах, проверяйте безопасный диапазон и задавайте явное правило округления.

### Ложные, пустые и запасные значения

**Ложные значения (falsy):** `false`, `0`, `-0`, `0n`, `NaN`, `""`, `null`, `undefined`.

**Пустые значения (nullish):** только `null` и `undefined`.

| Выражение | Когда берётся запасное значение |
|---|---|
| `value || fallback` | `value` — любое ложное значение |
| `value ?? fallback` | `value` — `null` или `undefined` |

Операторы короткого замыкания возвращают один из исходных операндов, а не обязательно логическое значение. Если `0`, `""` и `false` допустимы, для запасного значения обычно нужен `??`.

Опциональная цепочка (optional chaining):

- `user?.profile?.name` → `undefined`, если основание равно `null` или `undefined`;
- необъявленное корневое имя всё равно даёт `ReferenceError`;
- `obj.method?.()` бросит `TypeError`, если `method` существует, но не является функцией;
- `(obj?.a).b` разрывает непрерывную цепочку;
- ошибки существующих геттеров и методов не подавляются.

### Способы сравнения

| Проверка | `NaN` = `NaN` | `0` = `-0` | Где используется |
|---|---:|---:|---|
| `===` | ❌ | ✅ | основной вариант в новом коде, `indexOf()` |
| `Object.is` / SameValue | ✅ | ❌ | точные числовые граничные случаи |
| SameValueZero | ✅ | ✅ | `includes()`, ключи `Set` и `Map` |
| `==` | с преобразованием | ✅ | старый код и интервью; осознанное `value == null` означает `null` или `undefined` |

Объекты: `{a: 1} === {a: 1}` → `false`; две ссылки на один и тот же объект → `true`.

### Явное преобразование на границе

Предпочтительная последовательность:

```text
внешние данные → проверить формат и тип → явно вызвать Boolean/Number/String
               → проверить конечность, диапазон и безопасное целое → значение нужного типа
```

- `Boolean(value)` использует список ложных значений.
- `Number("") → 0`, `Number(null) → 0`, `Number(undefined) → NaN`.
- `String(null) → "null"`; `String(Symbol())` работает, но неявная конкатенация `Symbol` бросает `TypeError`.
- Бинарный `+`: применить `ToPrimitive` к обоим операндам → если хотя бы один результат является строкой, выполнить конкатенацию; иначе сложить числа.
- Другие арифметические операторы обычно приводят операнды к числам: `"5" - 2 → 3`.
- Операторы отношения сравнивают две строки лексикографически; в остальных случаях используют собственный алгоритм. Формулировка «всегда вызывают `Number` для обеих сторон» неточна.

`ToPrimitive(object, hint)`:

1. `[Symbol.toPrimitive](hint)`, если есть;
2. для подсказки `"string"`: `toString()` → `valueOf()`;
3. для `"number"` / `"default"` у обычного объекта: `valueOf()` → `toString()`;
4. результат должен быть примитивом, иначе `TypeError`.

### 🪤 Как предсказывать результат

1. Определи категории значений и оператор.
2. Вычисли унарные операции и короткое замыкание.
3. Для объекта проследи `ToPrimitive`.
4. Примени правила преобразования конкретного оператора.
5. Назови значение **и тип**; отдельно отметь исключение.

`[] == ![]` → `![]` даёт `false` → массив преобразуется в `""` → обе стороны становятся `0` → результат `true`. Эта задача проверяет модель преобразований, а не рекомендуемый стиль рабочего кода.

### ✅ Быстрая самопроверка

- Объяснить: примитивы и объекты, идентичность, передачу по значению, выбор способа сравнения.
- Предсказать: `typeof`, ложные и пустые значения, `+`, `==`, `NaN`, `-0`, ошибки BigInt.
- Реализовать: нормализацию входных данных, числовую проверку, безопасные значения по умолчанию.
- Отладить: мутацию общего объекта, последствия поверхностной копии, ошибки плавающей точки и денежных расчётов.
- Проверить: явные типы и владение данными, `===` по умолчанию, только осознанные неявные преобразования.

## 1.3. Functions, Closures & Functional Patterns

> Быстрое повторение: [полная глава](../handbook/01-javascript-and-async-programming/03-functions-closures-and-functional-patterns.md) · [инфографика на английском, A4](../infographics/01-javascript-and-async-programming/03-functions-closures-and-functional-patterns.pdf)

### Функция как значение

| Форма | Создание / имя | Собственный контекст | `new` |
|---|---|---|---:|
| объявление (declaration) | при подготовке объявлений | `this` + `arguments` | обычно ✅ |
| функциональное выражение | при вычислении; имя даёт внешняя привязка | `this` + `arguments` | обычно ✅ |
| именованное выражение | при вычислении; внутреннее имя видно только в теле | `this` + `arguments` | обычно ✅ |
| стрелочная функция | при вычислении | внешний `this`; нет своего `arguments` | ❌ |

- объявление функции до строки → можно вызвать;
- `var fn = function…` до присваивания → `undefined` → вызов даёт `TypeError`;
- `const fn = …` до инициализации → TDZ → `ReferenceError`.

### Параметры и вызовы

**Параметр (parameter)** — привязка в определении функции; **аргумент (argument)** — значение конкретного вызова.

- значение по умолчанию → только отсутствующий аргумент / `undefined`; вычисляется при каждом вызове слева направо;
- необязательный объект с деструктуризацией → `function f({ x = 1 } = {})`;
- остаточный параметр (rest parameter) `...args` → оставшиеся аргументы в массиве;
- объект `arguments` → все фактические аргументы обычной функции; стрелочная функция читает `arguments` внешней функции;
- `fn.length` → число параметров до первого значения по умолчанию; остаточный параметр не учитывается; один шаблон деструктуризации считается одним параметром.

### Колбэки и функции высшего порядка

Функцию первого класса можно сохранить, передать и вернуть. Функция высшего порядка (higher-order function, HOF) принимает или возвращает другую функцию.

Контракт колбэка: **кто вызывает / когда / сколько раз / с какими аргументами и `this` / как использует результат / как сообщает об ошибках / как отменить и очистить**.

`["10","20","30"].map(parseInt)` → `[10, NaN, NaN]`: индекс массива становится аргументом `radix`. Нужен адаптер, который явно передаст основание `10`.

### `this`, `call`, `apply`, `bind`

```text
obj.method()          → this = obj
const fn = obj.method
fn()                  → получатель потерян (строгий режим: this = undefined)

fn.call(obj, a, b)    → вызвать сейчас; аргументы списком
fn.apply(obj, [a,b])  → вызвать сейчас; аргументы одним массивоподобным значением
fn.bind(obj, a)       → новая функция на будущее; первые аргументы закреплены
```

- у стрелочной функции лексический `this`; явный `thisArg` игнорируется, но аргументы передаются и привязываются;
- повторный `bind` не заменяет первого получателя, но добавляет аргументы;
- каждый `bind` возвращает новую функцию → для добавления и снятия обработчика сохраните одну ссылку;
- `length` привязанной функции примерно равен длине исходной функции минус число закреплённых аргументов, но не меньше нуля;
- `new boundFn` игнорирует привязанный `this`, но сохраняет закреплённые аргументы, если исходную функцию можно вызвать через `new`.

`new`: создать объект → связать с `Fn.prototype` → вызвать с новым `this` → явно возвращённый объект заменяет созданный. У стрелочной функции нет `[[Construct]]` → `TypeError`.

### Замыкание = функция + живые лексические привязки

```text
колбэк → лексическое окружение → привязка → текущее значение / идентичность объекта
```

Замыкание захватывает **привязку**, а не замороженный снимок. Несколько замыканий могут разделять состояние. Снимок = отдельная привязка или значение.

Цикл:

- `var` → одна общая привязка → более поздние колбэки часто дают `[3,3,3]`;
- `let` в `for` → отдельная привязка на итерацию → `[0,1,2]`.

Фабрики и инкапсуляция: каждый вызов фабрики создаёт отдельные закрытые привязки.
Мемоизация: замыкание хранит кеш; нужны правила ключей, ограничение размера или удаление записей, сброс и политика обработки ошибок.

Удержание памяти:

```text
обработчик / таймер / подписка / кеш
  → колбэк
    → замыкание
      → захваченный граф объектов
```

Для очистки нужна та же функция; освободите таймер, подписку и кеш. Захватывайте минимум данных. Подтверждайте утечку цепочкой удержания и снимками кучи.

### Чистые функции и неизменяемость

Чистая функция: одинаковые входы → одинаковый наблюдаемый результат; нет внешних наблюдаемых эффектов.

Эффекты: мутация данных вызывающего кода, DOM/хранилище/сеть, журналирование/аналитика, таймеры/обработчики, состояние модуля/глобальное состояние, зависимость от времени/случайности.

Локальная мутация только что созданного результата может оставаться ненаблюдаемой снаружи. Практическая неизменяемость защищает общие объекты и границы владения; копирование через оператор разворота (`...`) поверхностно и не равно глубокой заморозке.

### Функциональные паттерны

```text
каррирование: f(a,b,c) → f(a)(b)(c)
частичное применение: закрепить a → g(b,c)
compose(f,g)(x) = f(g(x))  // справа налево
pipe(g,f)(x)    = f(g(x))  // в порядке слева направо
```

Используйте, когда места вызова и поток данных становятся яснее. Избегайте магии вокруг арности, цепочек безымянных обёрток и скрытых эффектов.

1. Форма функции и момент создания.
2. Параметры, значения по умолчанию, остаточный параметр и фактические аргументы.
3. Форма вызова и получатель.
4. Момент вызова, сигнатура и очистка колбэка.
5. Захваченные привязки, места записи и идентичности.
6. Цепочки удержания и предел кеша.
7. Чистое преобразование и явные эффекты.
8. Порядок композиции и цена абстракции.
