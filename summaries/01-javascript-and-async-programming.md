## 1.1. Execution Model, Declarations & Scope

> Быстрое повторение: [полная глава](../handbook/01-javascript-and-async-programming/01-execution-model-declarations-and-scope.md) · [инфографика на английском, A4](../infographics/01-javascript-and-async-programming/01-execution-model-declarations-and-scope.pdf)

### 🧠 Одна модель

Программа как офис с комнатами:

- **область видимости (scope)** = комната;
- **привязка (binding)** = запись имени в журнале комнаты;
- **поиск имени (identifier resolution)** = движение от текущей комнаты наружу;
- **затенение (shadowing)** = ближняя запись с тем же именем скрывает дальнюю;
- **поднятие объявлений (hoisting)** = журнал готовят заранее, но код физически не двигают;
- **временная мёртвая зона (Temporal Dead Zone, TDZ)** = имя уже записано, но доступ ещё закрыт;
- **стек вызовов (call stack)** = стопка незавершённых вызовов: последний вошёл → первый вышел.

### ⚡ Термины и жизненный цикл

**Идентификатор (identifier)** — имя в коде → **привязка (binding)** связывает имя с состоянием → **значение (value)** хранится в привязке.

Объявление создаёт имя → инициализация впервые записывает значение → последующее присваивание меняет его.

| Объявление | Область видимости | До своей строки | Переназначение | Повторное объявление в той же области |
|---|---|---|---:|---:|
| `var` | функция / верхний уровень обычного скрипта | `undefined` | ✅ | обычно ✅ |
| `let` | блок | TDZ → `ReferenceError` | ✅ | ❌ |
| `const` | блок | TDZ → `ReferenceError` | ❌ | ❌ |

🎯 В новом коде: `const` по умолчанию → `let`, если нужно переназначение → `var` только для чтения устаревшего кода и интервью. `const` запрещает переназначение привязки, но **не** делает объект неизменяемым.

### Области видимости и поиск имени

- **глобальная область** — глобальные имена среды;
- **область модуля** — верхний уровень ES-модуля, который не становится глобальным объектом;
- **область функции** — параметры, локальные имена и `var`;
- **область блока** — `{}`, `if`, `for`, `switch`; действует для `let` / `const`, но не для обычного `var`;
- **лексическая область видимости** — доступность имени определяется местом написания функции, а не местом её вызова.

Поиск: текущая область → внешняя → ещё внешняя → имя не найдено = `ReferenceError`. Если ближайшая привязка найдена, но находится в TDZ, поиск **не** перескакивает к внешнему имени.

Свойство объекта — другой механизм: неизвестное имя → `ReferenceError`; отсутствующее `object.key` → обычно `undefined`.

### Модель выполнения

- До обычного выполнения JavaScript подготавливает объявления и проверяет конфликты.
- **Контекст выполнения (execution context)** — активное состояние выполняемого скрипта, модуля или функции.
- Вызов функции добавляет контекст в стек вызовов; обычный блок создаёт область видимости, но не новый кадр стека.
- **Лексическое окружение / запись окружения (Lexical Environment / Environment Record)** — спецификационная модель хранения привязок и ссылки на внешнее окружение. Это не обязательно обычные JavaScript-объекты.

### Поднятие объявлений, TDZ и функции

- `var` читается раньше своей строки как `undefined`.
- `let` / `const` / `class` существуют раньше строки, но до инициализации находятся в TDZ.
- `typeof undeclaredName` → `"undefined"`, но `typeof name` для имени в TDZ → `ReferenceError`.
- Объявление функции (function declaration) обычно можно вызвать раньше его строки.
- `var fn = function…` раньше строки → `fn === undefined` → вызов даёт `TypeError`.
- `const fn = function…` раньше строки → TDZ → `ReferenceError`.

### Затенение и конфликты объявлений

- **Затенение**: одинаковое имя в разных вложенных областях обычно допустимо.
- **Повторное объявление (redeclaration)**: новое объявление имени в той же эффективной области.
- `let` / `const` конфликтуют друг с другом и с `var` той же области → обычно `SyntaxError` до выполнения.
- Внешний `var` + внутренний блочный `let` — допустимо.
- Внешний `let` + `var` внутри обычного блока — конфликт: `var` принадлежит окружающей функции или глобальной области. Это часто называют **недопустимым затенением (illegal shadowing)**.
- Все `case` одного `switch` делят одну блочную область; отдельные `{}` предотвращают конфликты.

### Глобальный код, строгий режим и устаревшее поведение

| Где верхний уровень | Что происходит |
|---|---|
| обычный браузерный скрипт | `var` часто становится свойством `globalThis`; `let` / `const` — нет |
| браузерный или Node.js ES-модуль | все объявления принадлежат модулю; строгий режим включён автоматически |
| Node.js CommonJS | файл обёрнут функцией; верхние объявления локальны для модуля |

- Присваивание необъявленному имени в обычном скрипте без строгого режима может создать **случайную глобальную переменную (accidental global)**; в строгом режиме будет `ReferenceError`.
- `delete` удаляет свойство объекта, но не привязку переменной.
- 🧓 `with`, прямой `eval`, блочные функции из Annex B — узнавать на интервью и в старом коде, но не использовать в современном решении.

### Следствие для замыканий

Замыкание (closure) сохраняет доступ к привязке, а не копирует её значение: `for (var i…)` → одна общая `i`, более поздние колбэки обычно видят итоговое значение; `for (let i…)` → отдельная привязка для каждой итерации.

### 🪤 Как предсказывать результат

1. Уточни среду: обычный скрипт / ES-модуль / CommonJS.
2. Проверь ранние конфликты: если `SyntaxError`, выполнение не начнётся.
3. Отметь границы функций и блоков.
4. Выпиши привязки и их начальное состояние: `undefined` / TDZ / функция.
5. Для каждого имени ищи от текущей области наружу.
6. Только теперь выполняй строки и называй точный результат: значение / `undefined` / `ReferenceError` / `TypeError` / `SyntaxError`.

### 🗣️ Ответ за 30–60 секунд

> Область видимости определяет, к какой привязке относится имя. Поиск начинается в текущей лексической области и идёт наружу. До построчного выполнения объявления подготавливаются: `var` получает `undefined`, `let` и `const` остаются в TDZ, а привязка объявления функции обычно уже содержит функцию. Поэтому поднятие объявлений — не перенос кода, а наблюдаемый результат предварительной подготовки.

### ✅ Быстрая самопроверка

- Могу без подсказки сравнить `var` / `let` / `const`.
- Отличаю область видимости, контекст выполнения и стек вызовов.
- Объясняю поднятие объявлений без фразы «код переносится вверх».
- Предсказываю TDZ, затенение, конфликты объявлений и ошибки функциональных выражений.
- Уточняю среду выполнения перед вопросом про `globalThis`.
- Объясняю разницу `for (var…)` и `for (let…)` через привязки.

## 1.2. Values, Types, Equality & Coercion

> Быстрое повторение: [полная глава](../handbook/01-javascript-and-async-programming/02-values-types-equality-and-coercion.md) · [инфографика на английском, A4](../infographics/01-javascript-and-async-programming/02-values-types-equality-and-coercion.pdf)

### Значения, идентичность и мутация

`привязка → значение`; объект обладает собственной **идентичностью (identity)**.

| Примитивы — неизменяемы | Объекты — по умолчанию изменяемы |
|---|---|
| `undefined`, `null`, `boolean`, `number`, `bigint`, `string`, `symbol` | объекты, массивы, функции, даты… |
| операция создаёт новое значение | свойства существующего объекта можно менять |
| сравнение обычно идёт по значению | равенство объектов проверяет идентичность |

`const` запрещает **переназначение привязки**, но не мутацию объекта. `{ ...source }` и `Object.assign({}, source)` создают **поверхностную копию (shallow copy)**: внешний объект новый, а вложенные объекты остаются общими.

Аргументы всегда передаются **по значению (pass by value)**. Если аргумент — объект, параметр получает копию значения, указывающего на тот же объект. Поэтому вызывающий код видит мутацию этого объекта, но не переназначение самого параметра.

### Проверка типа и особые числовые значения

```text
typeof null        → "object"      typeof []          → "object"
typeof function(){}→ "function"    typeof NaN         → "number"
typeof 1n          → "bigint"      typeof Symbol()    → "symbol"
```

- `typeof undeclaredName` → `"undefined"`; но имя в TDZ → `ReferenceError`.
- `undefined` обычно означает отсутствие значения; `null` — намеренно пустое значение по контракту.
- `Symbol()` создаёт уникальный примитив, пригодный как ключ свойства; `Symbol("x") !== Symbol("x")`.
- BigInt хранит целые числа произвольной точности: `1n + 2n` ✅, `1n + 2` → `TypeError`; деление отбрасывает дробную часть.
- `NaN !== NaN`; надёжная проверка → `Number.isNaN(value)`.
- Глобальная `isNaN` сначала преобразует аргумент; `Number.isNaN` этого не делает.
- `Number.isFinite` и `Number.isSafeInteger` проверяют разные ограничения.
- `Object.is(-0, 0) === false`; `1 / -0 === -Infinity`.

Числа с плавающей точкой: `0.1 + 0.2 !== 0.3`. Для измерений используйте допустимую абсолютную и относительную погрешность предметной области. Деньги с фиксированной точностью храните в целых минимальных единицах, проверяйте безопасный диапазон и задавайте явное правило округления.

### Ложные, пустые и запасные значения

**Ложные значения (falsy):** `false`, `0`, `-0`, `0n`, `NaN`, `""`, `null`, `undefined`.

**Пустые значения (nullish):** только `null` и `undefined`.

| Выражение | Когда берётся запасное значение |
|---|---|
| `value || fallback` | `value` — любое ложное значение |
| `value ?? fallback` | `value` — `null` или `undefined` |

Операторы короткого замыкания возвращают один из исходных операндов, а не обязательно логическое значение. Если `0`, `""` и `false` допустимы, для запасного значения обычно нужен `??`.

Опциональная цепочка (optional chaining):

- `user?.profile?.name` → `undefined`, если основание равно `null` или `undefined`;
- необъявленное корневое имя всё равно даёт `ReferenceError`;
- `obj.method?.()` бросит `TypeError`, если `method` существует, но не является функцией;
- `(obj?.a).b` разрывает непрерывную цепочку;
- ошибки существующих геттеров и методов не подавляются.

### Способы сравнения

| Проверка | `NaN` = `NaN` | `0` = `-0` | Где используется |
|---|---:|---:|---|
| `===` | ❌ | ✅ | основной вариант в новом коде, `indexOf()` |
| `Object.is` / SameValue | ✅ | ❌ | точные числовые граничные случаи |
| SameValueZero | ✅ | ✅ | `includes()`, ключи `Set` и `Map` |
| `==` | с преобразованием | ✅ | старый код и интервью; осознанное `value == null` означает `null` или `undefined` |

Объекты: `{a: 1} === {a: 1}` → `false`; две ссылки на один и тот же объект → `true`.

### Явное преобразование на границе

Предпочтительная последовательность:

```text
внешние данные → проверить формат и тип → явно вызвать Boolean/Number/String
               → проверить конечность, диапазон и безопасное целое → значение нужного типа
```

- `Boolean(value)` использует список ложных значений.
- `Number("") → 0`, `Number(null) → 0`, `Number(undefined) → NaN`.
- `String(null) → "null"`; `String(Symbol())` работает, но неявная конкатенация `Symbol` бросает `TypeError`.
- Бинарный `+`: применить `ToPrimitive` к обоим операндам → если хотя бы один результат является строкой, выполнить конкатенацию; иначе сложить числа.
- Другие арифметические операторы обычно приводят операнды к числам: `"5" - 2 → 3`.
- Операторы отношения сравнивают две строки лексикографически; в остальных случаях используют собственный алгоритм. Формулировка «всегда вызывают `Number` для обеих сторон» неточна.

`ToPrimitive(object, hint)`:

1. `[Symbol.toPrimitive](hint)`, если есть;
2. для подсказки `"string"`: `toString()` → `valueOf()`;
3. для `"number"` / `"default"` у обычного объекта: `valueOf()` → `toString()`;
4. результат должен быть примитивом, иначе `TypeError`.

### 🪤 Как предсказывать результат

1. Определи категории значений и оператор.
2. Вычисли унарные операции и короткое замыкание.
3. Для объекта проследи `ToPrimitive`.
4. Примени правила преобразования конкретного оператора.
5. Назови значение **и тип**; отдельно отметь исключение.

`[] == ![]` → `![]` даёт `false` → массив преобразуется в `""` → обе стороны становятся `0` → результат `true`. Эта задача проверяет модель преобразований, а не рекомендуемый стиль рабочего кода.

### ✅ Быстрая самопроверка

- Объяснить: примитивы и объекты, идентичность, передачу по значению, выбор способа сравнения.
- Предсказать: `typeof`, ложные и пустые значения, `+`, `==`, `NaN`, `-0`, ошибки BigInt.
- Реализовать: нормализацию входных данных, числовую проверку, безопасные значения по умолчанию.
- Отладить: мутацию общего объекта, последствия поверхностной копии, ошибки плавающей точки и денежных расчётов.
- Проверить: явные типы и владение данными, `===` по умолчанию, только осознанные неявные преобразования.

## 1.3. Functions, Closures & Functional Patterns

> Быстрое повторение: [полная глава](../handbook/01-javascript-and-async-programming/03-functions-closures-and-functional-patterns.md) · [инфографика на английском, A4](../infographics/01-javascript-and-async-programming/03-functions-closures-and-functional-patterns.pdf)

### Функция как значение

| Форма | Создание / имя | Собственный контекст | `new` |
|---|---|---|---:|
| объявление (declaration) | при подготовке объявлений | `this` + `arguments` | обычно ✅ |
| функциональное выражение | при вычислении; имя даёт внешняя привязка | `this` + `arguments` | обычно ✅ |
| именованное выражение | при вычислении; внутреннее имя видно только в теле | `this` + `arguments` | обычно ✅ |
| стрелочная функция | при вычислении | внешний `this`; нет своего `arguments` | ❌ |

- объявление функции до строки → можно вызвать;
- `var fn = function…` до присваивания → `undefined` → вызов даёт `TypeError`;
- `const fn = …` до инициализации → TDZ → `ReferenceError`.

### Параметры и вызовы

**Параметр (parameter)** — привязка в определении функции; **аргумент (argument)** — значение конкретного вызова.

- значение по умолчанию → только отсутствующий аргумент / `undefined`; вычисляется при каждом вызове слева направо;
- необязательный объект с деструктуризацией → `function f({ x = 1 } = {})`;
- остаточный параметр (rest parameter) `...args` → оставшиеся аргументы в массиве;
- объект `arguments` → все фактические аргументы обычной функции; стрелочная функция читает `arguments` внешней функции;
- `fn.length` → число параметров до первого значения по умолчанию; остаточный параметр не учитывается; один шаблон деструктуризации считается одним параметром.

### Колбэки и функции высшего порядка

Функцию первого класса можно сохранить, передать и вернуть. Функция высшего порядка (higher-order function, HOF) принимает или возвращает другую функцию.

Контракт колбэка: **кто вызывает / когда / сколько раз / с какими аргументами и `this` / как использует результат / как сообщает об ошибках / как отменить и очистить**.

`["10","20","30"].map(parseInt)` → `[10, NaN, NaN]`: индекс массива становится аргументом `radix`. Нужен адаптер, который явно передаст основание `10`.

### `this`, `call`, `apply`, `bind`

```text
obj.method()          → this = obj
const fn = obj.method
fn()                  → получатель потерян (строгий режим: this = undefined)

fn.call(obj, a, b)    → вызвать сейчас; аргументы списком
fn.apply(obj, [a,b])  → вызвать сейчас; аргументы одним массивоподобным значением
fn.bind(obj, a)       → новая функция на будущее; первые аргументы закреплены
```

- у стрелочной функции лексический `this`; явный `thisArg` игнорируется, но аргументы передаются и привязываются;
- повторный `bind` не заменяет первого получателя, но добавляет аргументы;
- каждый `bind` возвращает новую функцию → для добавления и снятия обработчика сохраните одну ссылку;
- `length` привязанной функции примерно равен длине исходной функции минус число закреплённых аргументов, но не меньше нуля;
- `new boundFn` игнорирует привязанный `this`, но сохраняет закреплённые аргументы, если исходную функцию можно вызвать через `new`.

`new`: создать объект → связать с `Fn.prototype` → вызвать с новым `this` → явно возвращённый объект заменяет созданный. У стрелочной функции нет `[[Construct]]` → `TypeError`.

### Замыкание = функция + живые лексические привязки

```text
колбэк → лексическое окружение → привязка → текущее значение / идентичность объекта
```

Замыкание захватывает **привязку**, а не замороженный снимок. Несколько замыканий могут разделять состояние. Снимок = отдельная привязка или значение.

Цикл:

- `var` → одна общая привязка → более поздние колбэки часто дают `[3,3,3]`;
- `let` в `for` → отдельная привязка на итерацию → `[0,1,2]`.

Фабрики и инкапсуляция: каждый вызов фабрики создаёт отдельные закрытые привязки.
Мемоизация: замыкание хранит кеш; нужны правила ключей, ограничение размера или удаление записей, сброс и политика обработки ошибок.

Удержание памяти:

```text
обработчик / таймер / подписка / кеш
  → колбэк
    → замыкание
      → захваченный граф объектов
```

Для очистки нужна та же функция; освободите таймер, подписку и кеш. Захватывайте минимум данных. Подтверждайте утечку цепочкой удержания и снимками кучи.

### Чистые функции и неизменяемость

Чистая функция: одинаковые входы → одинаковый наблюдаемый результат; нет внешних наблюдаемых эффектов.

Эффекты: мутация данных вызывающего кода, DOM/хранилище/сеть, журналирование/аналитика, таймеры/обработчики, состояние модуля/глобальное состояние, зависимость от времени/случайности.

Локальная мутация только что созданного результата может оставаться ненаблюдаемой снаружи. Практическая неизменяемость защищает общие объекты и границы владения; копирование через оператор разворота (`...`) поверхностно и не равно глубокой заморозке.

### Функциональные паттерны

```text
каррирование: f(a,b,c) → f(a)(b)(c)
частичное применение: закрепить a → g(b,c)
compose(f,g)(x) = f(g(x))  // справа налево
pipe(g,f)(x)    = f(g(x))  // в порядке слева направо
```

Используйте, когда места вызова и поток данных становятся яснее. Избегайте магии вокруг арности, цепочек безымянных обёрток и скрытых эффектов.

## 1.4. `this`, Invocation & Object Model

> Быстрое повторение: [полная глава](../handbook/01-javascript-and-async-programming/04-this-invocation-and-object-model.md) · [инфографика на английском, A4](../infographics/01-javascript-and-async-programming/04-this-invocation-and-object-model.pdf)

### Вызов определяет `this`

```text
fn()                    → undefined в строгой функции
object.fn()             → object
fn.call(x, a)           → x, вызвать сейчас
fn.apply(x, argsLike)   → x, вызвать сейчас
fn.bind(x, a)           → новая функция на будущее
new Fn()                → новый экземпляр
arrow                   → внешний лексический this
```

Отделённый метод вызывается уже как обычная функция. Для колбэка сохраните один результат `bind` либо используйте понятный адаптер. Повторный `bind` не заменяет первый `this`; `new boundFn` игнорирует связанный `thisArg`, но сохраняет аргументы, если исходная функция является конструктором.

### Создание объекта и `new`

| Подход | Где состояние | Где методы |
|---|---|---|
| литерал | собственные свойства | собственные свойства |
| фабрика + замыкание | закрытые привязки | функции результата |
| функция-конструктор | собственные свойства экземпляра | `Constructor.prototype` |
| `Object.create(proto)` | добавить явно | в выбранном `proto` |
| класс | поля экземпляра, включая приватные | методы прототипа |

```text
new Constructor(args)
  → создать объект
  → object.[[Prototype]] = Constructor.prototype
  → вызвать Constructor с новым this
  → возвращённый object/function заменяет результат; примитив игнорируется
```

`.prototype` — обычное свойство конструктора для будущих экземпляров. `[[Prototype]]` — внутренняя ссылка конкретного объекта. Функция-конструктор сама обычно наследует от `Function.prototype`.

### Поиск, затенение и запись

Чтение: собственное свойство → прототип → … → `null`; первое найденное свойство останавливает поиск, даже если его значение `undefined`.

Присваивание:

- собственное изменяемое свойство с данными → изменить значение;
- унаследованное изменяемое свойство с данными → создать собственное свойство у получателя операции (receiver);
- унаследованный setter → вызвать его с получателем в роли `this`;
- неизменяемое свойство или accessor-свойство без setter → отклонить запись.

`Object.defineProperty` определяет собственное свойство непосредственно и не вызывает setter прототипа. Публичное поле класса тоже использует определение, а не обычное присваивание.

🧓 `__proto__` — историческое accessor-свойство. Используйте `Object.getPrototypeOf` / `Object.setPrototypeOf`; ещё лучше — создавайте правильную цепочку сразу. `Object.create(null)` не наследует `Object.prototype` и подходит для простого словаря.

### Классы

- класс требует `new`, имя до инициализации находится в TDZ, тело строгое;
- `method() {}` → один неперечисляемый метод прототипа;
- `field = () => ...` → отдельная перечисляемая собственная функция каждого экземпляра с лексическим `this`;
- `extends` связывает цепочки экземпляров и конструкторов;
- производный конструктор не может использовать `this` до `super()`;
- `super.method()` ищет метод в базовом классе, но получателем остаётся текущий экземпляр;
- статические элементы находятся на конструкторе класса;
- приватные элементы `#private` не являются свойствами и требуют, чтобы объект имел приватную метку (private brand) объявившего их класса.

Композиция обычно проще, если повторно используются независимые операции, а не устойчивый контракт «является разновидностью».

### Свойства: две оси и ключи

```text
собственные / унаследованные   ×   перечислимые / неперечислимые
строковые ключи                +   ключи Symbol
```

| Нужно | API |
|---|---|
| собственное свойство существует | `Object.hasOwn(object, key)` |
| собственное или унаследованное | `key in object` |
| собственные перечислимые строковые ключи | `Object.keys` / `values` / `entries` |
| перечислимые строковые ключи по цепочке | `for...in` |
| все собственные строковые ключи | `Object.getOwnPropertyNames` |
| все собственные ключи Symbol | `Object.getOwnPropertySymbols` |
| все собственные ключи | `Reflect.ownKeys` |

`Object.values` / `entries` могут вызвать getter. Enumerability и Symbol не дают приватности.

### Дескрипторы и аксессоры

```text
с данными:  value + writable
accessor:   get + set
для обоих: enumerable + configurable
```

В одном дескрипторе нельзя смешивать поля свойства с данными и accessor-свойства. При создании свойства через `Object.defineProperty` пропущенные флаги равны `false`. Getter и setter выполняются с получателем в роли `this`; `Reflect.get` и `Reflect.set` позволяют передать получателя явно.

### Уровни целостности — поверхностная гарантия

| Возможность | preventExtensions | seal | freeze |
|---|---:|---:|---:|
| добавить собственное свойство | ❌ | ❌ | ❌ |
| удалить собственное свойство | иногда | ❌ | ❌ |
| изменить значение изменяемого свойства с данными | ✅ | ✅ | ❌ |
| вызвать существующий setter | ✅ | ✅ | ✅ |
| изменить вложенный объект | ✅ | ✅ | ✅ |

`const` ограничивает привязку; `freeze` — собственные свойства одного объекта. Вложенные объекты, приватные поля, аксессоры и внутреннее состояние встроенных объектов требуют отдельного контракта.

### Proxy → перехватчик → Reflect → исходный объект

```text
операция с Proxy → нужный перехватчик → Reflect.operation(target, ..., receiver)
```

- сохраняйте получателя для getter и setter;
- `proxy !== target`; исходный объект и Proxy — разные ключи для `Map`;
- прямой доступ к исходному объекту обходит перехватчики;
- Proxy не получает приватные поля и внутренние слоты исходного объекта;
- перехватчики обязаны соблюдать инварианты, иначе возникает `TypeError`;
- `Proxy.revocable` отключает будущие операции через обёртку, но не уничтожает исходный объект.

Для нескольких известных действий явная обёртка часто проще. Proxy оправдан для общего перехвата, виртуализации или библиотечной инфраструктуры.

## 1.5. Arrays, Transformations & Copying

### Модель массива

```text
массив = идентичность объекта + собственные индексные свойства + граница length
```

- `Array.isArray(value)` → надёжная проверка, включая другую среду выполнения (realm); `instanceof Array` зависит от идентичности конструктора.
- Запись `array[i]` за границей → `length = i + 1`; промежуточные свойства не создаются.
- Увеличить `length` → пустые слоты; уменьшить → удалить собственные индексы массива справа.
- `array.note`, `array[-1]`, `array["01"]` → обычные свойства, `length` не меняют.

| Позиция | Чтение | `i in array` | `Object.hasOwn(array, i)` |
|---|---|---:|---:|
| пустой слот (hole) | `undefined` | `false`* | `false` |
| явный `undefined` | `undefined` | `true` | `true` |

\* если свойства нет и в цепочке прототипов.

`delete array[i]` → пустой слот, длина та же. `splice(i, 1)` → мутация + сдвиг + меньшая длина. `toSpliced(i, 1)` → новый итоговый массив.

### Разреженный массив: проверять конкретный метод

| Операция | Пустой слот |
|---|---|
| `map` | callback пропущен; пустой слот сохранён |
| `filter` | callback пропущен; результат плотный |
| `forEach`, `some`, `every`, `reduce` | callback пропущен |
| `find`, `findIndex` | callback получает `undefined` |
| `slice` | пустой слот сохранён |
| spread, `Array.from` | пустой слот → явный `undefined` |
| `toSorted`, `toSpliced`, `toReversed`, `with` | плотный результат; пустой слот → `undefined` |

### Мутация ↔ копирование

| Намерение | Мутирующий вариант | Возвращает | Копирующий вариант |
|---|---|---|---|
| добавить справа/слева | `push` / `unshift` | новая длина | spread / `concat` |
| удалить край | `pop` / `shift` | удалённое значение | `slice` |
| вставить/удалить | `splice` | массив удалённых | `toSpliced` → новая версия |
| сортировать | `sort` | тот же массив | `toSorted` |
| развернуть | `reverse` | тот же массив | `toReversed` |
| заменить индекс | `array[i] = x` | `x` | `with(i, x)`; вне диапазона → `RangeError` |

Все обычные копии поверхностны: новый внешний контейнер, те же идентичности вложенных объектов.

### Метод выбирает форма результата

```text
1 результат / элемент → map
подмножество           → filter
первое совпадение      → find
существует?            → some    (ранний выход при true)
все подходят?          → every   (ранний выход при false)
побочный эффект        → forEach (возвращает undefined)
много → одно           → reduce  (явный initialValue)
сложное управление     → читаемый цикл
```

Ловушки:

- callback с телом-блоком требует `return`;
- `filter(Boolean)` удаляет `0`, `false`, `""`, `NaN`, `null`, `undefined`;
- `[].some(...) === false`; `[].every(...) === true`;
- `reduce` без начального значения бросает исключение для пустого или полностью разреженного массива;
- длина обхода обычно фиксируется перед первым callback; будущие значения читаются в момент посещения;
- `forEach(async ...)` не ждёт `Promise`; `map(async ...)` → `Promise[]`.

### Функция сравнения

```text
compare(a, b) < 0 → a перед b
compare(a, b) > 0 → a после b
compare(a, b) = 0 → равны для порядка; стабильное равенство
```

- `sort` по умолчанию → преобразование в строки + порядок кодовых единиц UTF-16.
- Числа по возрастанию → `(a, b) => a - b`.
- `(a, b) => a > b` ❌: boolean-функция сравнения нарушает антисимметрию.
- Договор → чистота + равенство даёт `0` + антисимметрия + транзитивность.
- Несколько полей → `primary(a, b) || secondary(a, b)`.
- Строки → `localeCompare` / повторно используемый `Intl.Collator`.
- `sort` мутирует; `toSorted` копирует поверхностно.
- Стабильный порядок гарантирован; конкретные алгоритм и сложность по времени/памяти — нет.
- `sort`: обычные значения → явный `undefined` → пустые слоты. `toSorted`: пустые слоты становятся `undefined`.

### Деструктуризация / rest / spread

- `[a = fallback]`: значение по умолчанию только при `undefined`/пустом слоте, не при `null`.
- `[head, , third, ...tail]`: пропуск + rest-массив.
- `[a, b] = [b, a]`: обмен значений.
- `{ name: label, status = "idle" }`: новое локальное имя + значение по умолчанию.
- `[...value]`, `fn(...value)` → значения итерируемого объекта; устройство протокола в 1.6.
- `{ ...value }` → собственные перечисляемые строковые свойства и свойства с ключами-символами; позднее значение побеждает.
- Spread большого массива в вызове может превысить лимит аргументов движка.
- Object spread определяет свойства данных в новом объекте; `Object.assign` пишет через сеттеры в существующий целевой объект.
- Spread/assign не сохраняют дескрипторы; для этого нужны `getOwnPropertyDescriptors` + `defineProperties`.

### Поверхностная копия → структурное разделение

```text
старый корень ─> изменённая ветвь ─> вложенный объект
новый корень  ─> новая ветвь      ─> новый вложенный объект
              └> неизменённая ветвь (общая ссылка)
```

Копируйте только изменяемый путь. Это позволяет обнаруживать изменения сравнением ссылок без полного клонирования. Условие: общие ветви больше не мутируются.

### Глубокая копия = договор о графе данных

До выбора инструмента решить:

```text
циклы | повторные ссылки | прототипы/классы | дескрипторы/аксессоры
функции | Symbols | встроенные типы | DOM/ресурсы среды | закрытое состояние | цена
```

| Подход | Когда |
|---|---|
| ручное копирование доменной модели | известная схема, инварианты и нормализация |
| `structuredClone` | поддерживаемый граф данных |
| сериализация и разбор JSON | намеренно совместимое с JSON представление |
| библиотека | нужен её конкретный проверенный договор |

### `structuredClone`

- Новый граф; циклы и повторные ссылки внутри результата сохраняются.
- Поддерживает массивы, обычные данные и важные встроенные типы: `Date`, `RegExp`, `Map`, `Set`, буферы, типизированные массивы и др.
- Функция / DOM-узел / неподдерживаемое внутреннее состояние → `DataCloneError`.
- Пользовательский прототип, методы, закрытые поля и дескрипторы не сохраняются как модель класса.
- Передаваемый ресурс → владение перемещается; исходный `ArrayBuffer` отсоединяется (`byteLength === 0`).

### Ловушки JSON-клонирования

```text
цикл / BigInt                     → TypeError
undefined/function/Symbol в объекте → свойство пропущено
те же значения в массиве + hole   → null
NaN / Infinity                    → null
Date                              → строка через toJSON
Map / Set                         → {}
прототип / дескрипторы            → потеряны
повторная ссылка                  → независимые копии
пользовательский toJSON           → представление заменено
```

### Порядок ревью

```text
индексы существуют? → length? → мутация? → возвращаемое значение?
→ вызовы callback / ранний выход? → общие идентичности?
→ граф поддерживается клонированием? → владение + измеренная стоимость?
```

## 1.6. Collections, Symbols & Iteration

> Быстрое повторение: [полная глава](../handbook/01-javascript-and-async-programming/06-collections-symbols-and-iteration.md) · [инфографика на английском, A4](../infographics/01-javascript-and-async-programming/06-collections-symbols-and-iteration.pdf)

### Выбор структуры

| Потребность | Структура | Что помнить |
|---|---|---|
| Именованные поля записи | Объект | Ключ — строка или символ. `Object.keys` видит собственные перечисляемые строковые ключи. |
| Индекс по произвольному ключу | `Map` | `has` отличает отсутствие от сохранённого `undefined`. `size` считает записи. |
| Принадлежность и уникальность | `Set` | Примитивы и объекты сравниваются по правилам `SameValueZero`. |
| Данные или отметка по экземпляру | `WeakMap` / `WeakSet` | Без обхода и `size`. Само наличие записи не держит ключ сильно. |
| Допустима потеря цели | `WeakRef` | `deref()` → цель или `undefined`. Нужен рабочий путь при промахе. |

- `Map` и `Set` объединяют `NaN` с `NaN` и оба знака нуля. Объекты совпадают по идентичности. Для уникальности по `id` задайте победителя.
- `Map` обходит пары в порядке вставки. Обновление не переставляет ключ, удаление с новой вставкой отправляет его в конец. Открытый итератор видит изменения.
- Обычный `Map` превращается в `"{}"` при прямом `JSON.stringify`. Явные пары сохраняют различие `7` и `"7"` для JSON-совместимых данных. Объектной идентичности нужен внешний ID.
- Допустимы слабые цели-объекты и незарегистрированные символы. `Symbol.for` запрещён. Уборка недетерминирована. Наличие `WeakRef` внутри `Map` не ограничивает сам индекс.

### Символы и обход

- `Symbol("id")` создаёт новый ключ, `Symbol.for("id")` возвращает общий ключ из реестра. `Reflect.ownKeys` видит символьные свойства.
- Известные символы включают поведение языка: `Symbol.iterator`, `Symbol.asyncIterator`, `Symbol.toPrimitive`, `Symbol.toStringTag`.
- Итерируемый объект → `[Symbol.iterator]()` → итератор → `next()` → `{ value, done }`. `done` отделяет конец от элемента `undefined`.
- Повторяемый обход → отдельный курсор при каждом вызове. Генератор — одноразовый курсор. `yield` отдаёт элемент, `return` завершает, `yield*` делегирует.
- `for...of` берёт значения, `for...in` перечисляет строковые ключи. Массивоподобный объект без итератора подходит `Array.from`; spread внутри массива потребует итератор.
- Ранний выход из цикла → `return()`, если есть → `finally` у генератора. При ручном обходе закрывайте курсор сами.
- `Symbol.asyncIterator` → обещание следующего результата → `for await...of`. Для конечного источника `Array.fromAsync` материализует всё, а цикл позволяет остановиться.

### Современные API

`Map.groupBy` сохраняет тип и идентичность ключа. `Set#intersection` принимает договор множества и может менять ожидаемый порядок. `Iterator.from(source).filter(match).take(n).toArray()` сначала ограничивает обход, затем собирает массив. Проверяйте поддержку новых методов на целевых версиях.

## 1.7. Modules, Errors & Serialization

> Быстрое повторение: [полная глава](../handbook/01-javascript-and-async-programming/07-modules-errors-and-serialization.md) · [инфографика на английском, A4](../infographics/01-javascript-and-async-programming/07-modules-errors-and-serialization.pdf)

### Модульная граница

| Механизм | Что вспоминать |
|---|---|
| ESM | Своя область, строгий режим, явные экспорты, верхнеуровневый `this` — `undefined` |
| Статический граф | Загрузка → связывание → выполнение. Импорт не становится поздним от положения строки. |
| Живые привязки (live bindings) | Чтение видит текущее значение источника; присваивание импортированному имени запрещено. Локальный снимок остаётся снимком. |
| Цикл | Допустим, но раннее чтение `let`/`const` может попасть в TDZ. Передать зависимость параметром или убрать цикл. |
| `import()` | Обещание пространства имён; отказ загрузки или выполнения надо наблюдать. Части сборки зависят от инструмента. |
| Top-level await | Задерживает готовность зависимых модулей, не всего процесса. Для необязательной операции бывает яснее функция загрузки. |

- `export default value` сохраняет результат выражения; `export { value as default }` экспортирует привязку.
- `import * as api` включает `default`. `export *` его не переэкспортирует.
- 🧓 CommonJS: `require()` возвращает `module.exports`; переназначить `exports` недостаточно. Деструктуризация снимает значение свойства.
- Node.js: `.mjs` → ESM, `.cjs` → CJS; для `.js` задавайте `type` явно. Браузер не читает `node_modules` сам.
- CJS из ESM: надёжный default — `module.exports`; автоматически обнаруженные именованные экспорты не являются живыми привязками.
- `require(esm)`: в проверенных Node.js 22.13.1/24.21.0/26.4.0 допускает граф без TLA; с TLA → `ERR_REQUIRE_ASYNC_MODULE`. В 20.18.2 без флага → `ERR_REQUIRE_ESM`.
- Условные `exports` могут выбрать независимые реализации и создать двойное состояние. Проверяйте оба пути в одном процессе.
- Tree shaking — работа сборщика по используемым экспортам и побочным эффектам. Ложное `sideEffects: false` может убрать регистрацию или стили.

### Ошибка — тоже договор

`throw` → ближайший активный обработчик → встретившиеся `finally` → дальнейший исход.

- Обычное завершение `finally` сохраняет исход; его `return`/`throw` заменяет прежний.
- Для отклонения обещания нужен `await` внутри `try` или обработчик обещания. Отложенная функция вне завершённого блока.
- Перехватывайте ради конкретного действия. Без нового контекста — `throw error`; с контекстом — пользовательская ошибка и `{ cause }`.
- `cause` сохраняет любое исходное значение. Формат стека зависит от среды; сырые ошибки не являются внешним DTO.

### JSON-граница

**Текст → разбор синтаксиса → проверка версии и схемы → согласованные данные.**

| Случай обычного `stringify` | Результат |
|---|---|
| `undefined` / функция / символ в объекте | Поле пропущено |
| То же в массиве, пустой слот | `null` |
| Корневой `undefined` | Значение `undefined`, не строка |
| `NaN` / бесконечность | `null` |
| BigInt / цикл без преобразования | `TypeError` |
| Дата / обычный Map / Set | Обычно ISO-строка / `"{}"` / `"{}"` |

- `toJSON` идёт до `replacer`; функция записи видит корень с `""`. Массив имён фильтрует и вложенные объекты.
- `reviver`: дети → родитель → корень `""`. Возврат `undefined` удаляет поле, у массива оставляет пустой слот. Не забывайте общий `return value`.
- `reviver` способен сам выбросить ошибку. Для ясных кодов отделяйте чистый разбор от схемы и преобразования.
- Большой ID лучше передавать строкой. `BigInt` после неточного `Number` цифры не вернёт; `context.source` требует поддержки целевой среды.
- Корректные `null`, `42` и `[]` могут нарушать схему. Проверяйте тип корня, собственные поля, версию, типы, диапазоны и неизвестные поля.

## 1.8. Memory Management

> Быстрое повторение: [полная глава](../handbook/01-javascript-and-async-programming/08-memory-management.md) · [инфографика на английском, A4](../infographics/01-javascript-and-async-programming/08-memory-management.pdf)

### 🧠 Одна модель

**Корень → сильные ссылки → объект → вложенный граф.**

Панель закрыта ≠ путь удалён. GC видит доступность, а не полезность для пользователя. Время жизни значения ≠ область видимости одного имени.

### ⚡ Главное

| Механизм | Что вспоминать |
|---|---|
| Достижимость | `null` убирает одно имя; псевдоним, кеш или обработчик могут удерживать тот же объект |
| Цикл | Без внешнего пути может быть собран. Когда именно — не обещано |
| Замыкание | Читает внешнюю привязку; доступная функция может удерживать большой граф |
| DOM | `remove()` убирает из документа; отдельно проверяем внешний путь |
| Обработчик | Снять: та же цель + тип + функция + `capture`; `once` ждёт события |
| Таймер / подписка | Отмена / отписка у владельца; общий `abort` помогает только поддерживающим сигнал API |
| Кеш | Нужны бюджет и политика; число записей ≠ байты; ленивый TTL не очищает непрочитанные ключи |
| `blob:` | Создать → использовать → отозвать после конца использования; замена и закрытие имеют владельца |

- Завершение: **запретить позднюю работу → снять свои регистрации → убрать тяжёлые ссылки**.
- Создание упало посередине → откатить уже приобретённое. Повторное завершение безопасно.
- `WeakMap` — возможные метаданные объектного ключа; `WeakRef` и финализатор не заменяют обязательную очистку.

### 🪤 Ловушки

- Сохранённый `dispose()` тоже может удерживать узел после вызова.
- Новая стрелка / новый `bind()` не снимает старую функцию.
- Забыть строку URL ≠ отозвать регистрацию. Слишком ранний отзыв ломает чтение.
- Пик: одновременные копии. Утечка: ненужные данные всё ещё удерживаются. Прогрев кеша и частые выделения — отдельные гипотезы.

### 🔎 Проверка

**Одинаковые входы → прогрев → исходное состояние → циклы открыть/закрыть → сравнение → путь удержания → исправление → тот же сценарий.**

Собственный размер — сам объект; удерживаемый — то, что потеряло бы доступность вместе с ним. Независимый путь меняет вывод. Не удерживать подозреваемые объекты самой консолью.

Тест: регистрации, таймеры, отписки, URL, работа до/после, повтор и отказ. **Ни срок GC, ни финализатор, ни точные байты не являются условием успеха.**

### 🗣️ Ответ за 30 секунд

> Я ищу путь от долгоживущего владельца к уже ненужным данным. Закрытие интерфейса должно снять обработчики, отменить таймеры, отписаться и освободить URL. Потом проверю одинаковые циклы до и после исправления. Удаление пути и реальное освобождение памяти — разные события; момент GC не обещаю.

### ✅ Быстрая самопроверка

- [ ] Рисую путь через замыкание и объясняю псевдонимы и циклы.
- [ ] Называю симметричное завершение каждого ресурса.
- [ ] Отличаю пик, бюджет кеша и утечку.
- [ ] Планирую сравнение снимков и проверку жизненного цикла без ожидания GC.

## 1.9. Event Loop & Scheduling

> Быстрое повторение: [полная глава](../handbook/01-javascript-and-async-programming/09-event-loop-and-scheduling.md) · [английская инфографика, A4](../infographics/01-javascript-and-async-programming/09-event-loop-and-scheduling.pdf)

### 🧠 Одна модель

**Занятый обычный вызов → завершение → контрольная точка микрозадач → дальнейшее планирование среды.**

Готовность ≠ запуск. Изменение DOM ≠ показ пикселей. Несколько источников задач ≠ одна общая FIFO-очередь.

### ⚡ Главное

| Механизм | Что вспоминать |
|---|---|
| Стек | Вложенные активные вызовы; таймер не прерывает текущий синхронный код |
| Задачи | Таймеры, ввод, сеть и другие источники; полного порядка между ними может не быть |
| Микрозадачи | Готовые реакции Promise и `queueMicrotask`; важен порядок постановки |
| Опустошение | Новые микрозадачи тоже выполняются; между двумя таймерами возможна микрозадача первого |
| Promise | Исполнитель конструктора синхронный; реакция ожидающего обещания ещё не готова |
| Голодание | Бесконечные микрозадачи не завершают контрольную точку; стек при этом может не расти |
| Порции | Короткая работа → следующая обычная задача; возможность планирования, не гарантия кадра |
| Таймер | Порог допуска, занятый поток, фон и ограничения; ни ноль, ни период не задают точный запуск |

### ⏱️ Время и кадры

- Вложенные таймеры: уровень **> 5**, задержка **< 4 мс** → минимум 4 мс. Не все таймеры и не точные 4 мс.
- Число тиков ≠ прошедшее время. Остаток = `max(0, ceil((deadline − now) / 1000))`; совместимые часы обязательны.
- Фон может задерживать таймеры и приостанавливать rAF. При возвращении — пересчёт и явная политика паузы.
- rAF: **один запрос → подходящее визуальное обновление → новый запрос для продолжения**. Отменять ожидающий ID.
- Положение = скорость × прошедшее время; фиксированные пиксели за кадр меняют скорость на разных экранах.
- Много изменений → последнее значение + не более одного ожидающего rAF. Сбросить ID перед применением.

### 🪤 Ловушки

- Все Promise раньше `queueMicrotask` — нет: сначала определить готовность и порядок постановки.
- `dispatchEvent()` синхронен; реальные события среды могут иметь иные границы контрольных точек.
- `await` готового Promise не обещает времени обычным задачам и интерфейсу.
- rAF, геометрия и двойной rAF не доказывают физический показ промежуточного состояния.
- Node.js — другая среда; `nextTick` и `setImmediate` нельзя механически добавить в браузерный рисунок.

### 🗣️ Ответ за 30 секунд

> Сначала завершается текущий обычный вызов. Готовые реакции и `queueMicrotask` обрабатываются в контрольной точке вместе с вложенными микрозадачами. Длинную работу делю на порции обычных задач, визуальные изменения объединяю в rAF. Таймеры не являются точными часами; время считаю по отметкам. Конкретный кадр после каждой задачи не обещаю.

### ✅ Быстрая самопроверка

- [ ] Прослеживаю синхронный код, готовность реакции и очередь микрозадач.
- [ ] Узнаю голодание и создаю границу обычной задачи.
- [ ] Объясняю допуск, фон, дрейф и отмену таймера.
- [ ] Считаю движение по времени, объединяю кадры и проверяю завершение.
- [ ] Отличаю установленный частичный порядок от случайного журнала.

## 1.10. Promises & `async`/`await`

> Быстрое повторение: [полная глава](../handbook/01-javascript-and-async-programming/10-promises-and-async-await.md) · [английская инфографика, A4](../infographics/01-javascript-and-async-programming/10-promises-and-async-await.pdf)

### 🧠 Одна модель

**Операция ≠ обещание ≠ владелец.** Promise — один исход; цепочка — зависимости; владелец — ошибка, отмена и актуальность.

`pending → fulfilled | rejected`. **Settled** = окончательный исход. **Resolved** = решение зафиксировано, но можно ещё ждать принятого Promise.

### ⚡ Цепочки и ошибки

| Механизм | Что вспоминать |
|---|---|
| Конструктор | Исполнитель синхронный; resolve не прекращает тело; return исполнителя не является результатом |
| `then` | Новое обещание: значение → успех; throw → отказ; Promise/thenable → принятие его исхода |
| Нет `return` | Следующая часть получает undefined и не ждёт отдельно начатую работу |
| Ветви | Catch исходного p не защищает любое новое q; каждая потерянная ветвь требует наблюдения |
| `catch` | Обычное возвращённое значение восстанавливает успех; throw передаёт отказ |
| `finally` | Без аргументов, обычно сохраняет исход; возвращённую очистку ждёт, её отказ заменяет исход |
| `async` / `await` | Своё обещание; тело начинается синхронно; await приостанавливает эту функцию, отказ становится выбросом |
| `return await` | Важен для локального catch и времени жизни ресурса в finally; не удалять механически |

### 🔀 Как ждать вместе

| Метод | Договор | Пустой вход |
|---|---|---|
| `all` | Все успехи, ранний отказ | Успех `[]` |
| `allSettled` | Полный отчёт исходов | Успех `[]` |
| `race` | Первый окончательный исход | Продолжает ждать |
| `any` | Первый успех, иначе AggregateError | Отказ, `errors: []` |

- Итоги `all`/`allSettled` и `AggregateError.errors` — в порядке входа.
- Комбинатор не вызывает переданные функции и не отменяет проигравших.
- Зависимости → последовательное ожидание. Независимые операции → запуск и немедленное общее наблюдение.
- `await array` не ждёт элементы; `map(async ...)` даёт Promise[], `forEach(async ...)` не собирает завершение.
- Поздний await уже запущенной ветви может опоздать к её отказу. Нужен владелец сразу.

### 🛑 Отмена и актуальность

**Сигнал → поддерживающий API → исход операции.** Особого состояния Promise «отменено» нет.

- Новый цикл → новый контроллер. Сохранять `reason`, включая `null`; имя AbortError не охватывает все причины.
- Отмена таймера → убрать таймер и слушатель. Успех → убрать слушатель.
- Fetch Response ≠ HTTP-успех ≠ готовое JSON-тело. Проверить статус, чтение и нужную границу сигнала.
- `any` сигналов + `timeout` — при поддержке среды; браузерное активное время ≠ универсальный календарный срок.
- **Текущая версия + живой владелец + неотменённый сигнал → применение данных/ошибки.** Старый finally не трогает новый запрос.

### 🪤 Ловушки

Thenable: getter читается синхронно, метод усваивается заданием языка. Async-обёртка не сохраняет идентичность исходного Promise. `void` не ловит отказ. Тайм-аут через race не отменяет запрос. Отмена клиента не откатывает серверный эффект.

### 🗣️ Ответ за 30 секунд

> Я возвращаю каждую зависимость в цепочку и сразу наблюдаю все запущенные ветви. Последовательно жду настоящие зависимости, для независимых выбираю комбинатор по договору успеха. Отдельно передаю сигнал отмены и проверяю версию перед изменением интерфейса: источник может проигнорировать отмену. Ошибки и finally тоже принадлежат конкретной версии.

- [ ] Выбираю catch/finally и четыре комбинатора, помню пустые входы.
- [ ] Узнаю потерянный return, каскад и ненаблюдаемую ветвь.

## 1.11. Async Coordination Patterns

[Полная глава](../handbook/01-javascript-and-async-programming/11-async-coordination-patterns.md) · [A4-инфографика](../infographics/01-javascript-and-async-programming/11-async-coordination-patterns.pdf)

### 🧠 Четыре разных вопроса

| Что ограничиваем | Выбор | Чего не гарантирует |
|---|---|---|
| Входы до паузы | Debounce: последний после затишья | Регулярный результат при вечном потоке |
| Частоту выполнения | Throttle: обновления во время потока | Серверную квоту без отдельного договора |
| Незавершённые операции | Общий ограничитель + очередь фабрик | Запросы в секунду, малую очередь |
| Повтор после отказа | Политика + бюджет + задержка | Безопасность произвольного действия |

### ⏱️ Края и завершение

- `leading` → первый вход; `trailing` → последний отложенный.
- Учебный debounce с обоими краями: один вход → один вызов; серия → первый + последний.
- `cancel` → удалить ожидающий и его данные; `flush` → выполнить имеющийся отложенный.
- У наших обёрток возврат `undefined`; асинхронный отказ наблюдает сам обработчик.
- Сохраняются последние аргументы и `this`, объекты не становятся глубокими снимками.
- Одна стабильная обёртка на владельца; при закрытии — отмена таймера и отдельно начатой работы.
- Реальные таймеры могут опоздать; порядок на общей границе задаётся отдельно.

### 🚦 Очередь: сначала допуск, потом запуск

**Фабрика → очередь FIFO → active++ → вызов → фактический исход → active--.**

| Событие | Наш договор |
|---|---|
| Отмена ожидающей | Удалить запись/обработчик, отклонить её Promise |
| Отмена активной | Передать сигнал; место занято до фактического завершения |
| `close(reason)` | Отклонить ожидающих/новые, активных сам не отменяет |
| Частичный отчёт | `allSettled` сохраняет позиции входа, не порядок завершения |
| Переполнение | Явный отказ; большой поток требует обратного давления |

Не передавать уже начатую работу. Не ждать вложенное последнее место того же ограничителя. Небольшой active не делает миллион обещаний маленьким входом.

### 🔁 Повторы: разрешение раньше формулы

**Безопасная операция + временный отказ → бюджет → пауза → новая попытка.**

- `maxAttempts` включает первый запуск; после последнего отказа паузы нет.
- Отмена, неверный ввод, постоянный отказ → обычно завершить сразу.
- Потерянный ответ не доказывает отсутствие серверного эффекта.
- Одна логическая операция → стабильный ключ идемпотентности + серверный договор.
- Предел: `min(maxDelay, baseDelay × 2^(failedAttempt−1))`.
- Полный разброс: `floor(random × предел)`, `random ∈ [0,1)`; ноль допустим.
- `Retry-After` → секунды или HTTP-дата; не сокращать серверное ожидание ради своего бюджета.
- Общий срок включает согласованные очередь + попытки + паузы; три слоя по три попытки → до 27 нижних запусков.

### 🧵 Отмена и место

Один сигнал → очередь → операция → пауза → запрет следующего старта/старого результата. Причина сохраняется как значение, включая `null`.

`limit(() => retry(...))` → место на логическую операцию с паузами. `retry(() => limit(...))` → место на попытку, каждый повтор снова ждёт допуск.

Поиск: **новый input → версия++ и abort сразу → debounce → запрос → проверка версии/жизни владельца → UI**. Старый ответ не допускается даже до следующего старта.

### 🗣️ Ответ за 30 секунд

> Я сначала разделяю частоту входов, число активных операций и допустимость повтора. Очередь получает фабрики, резервирует место до запуска и освобождает после фактического исхода. Повторы ограничены безопасностью и общим бюджетом, сигнал проходит и в запрос, и в паузу. Порядок отчёта сохраняю по входам, а право менять интерфейс — по версии владельца.

- [ ] Отделяю управляемые часы от настоящих таймеров и проверяю закрытие владельца.
