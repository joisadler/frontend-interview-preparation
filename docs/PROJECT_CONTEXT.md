# Project Context

## Purpose

This is a long-term personal **Q&A Frontend Interview Handbook + Coding Practice Repository** for Frontend Developer / Frontend Engineer positions, primarily Mid → Senior. The handbook itself contains the interview questions and their teaching answers; a separate Question Bank is not a reading step.

The user has about five years of commercial frontend experience with JavaScript, TypeScript, React, React Native, Next.js, HTML/CSS, accessibility, performance and large production codebases. The main problem is reduced active recall after less hands-on coding and heavy AI/Copilot use—not lack of professional experience.

The target transformation is:

`recognize → recall → explain → implement → debug → review → design`

## Primary principles

- Breadth and realistic interview coverage first; then appropriate depth.
- Fundamentals remain mandatory for experienced candidates.
- Frequency controls priority and depth, but is not a hard exclusion filter.
- Use both real interview research and engineering gap analysis.
- Modern recommendations and legacy/interview knowledge must be clearly separated.
- Prefer learning material quality over repository infrastructure.
- Keep explanations conversational and interview-oriented: plain Russian first, canonical English terms alongside it, and precise specification details as an optional second layer.
- Maintain one compact summary per domain for pre-interview refresh; summaries may condense only already-authored handbook sections.

## Fixed research and curriculum results

- Stage 0: 510 normalized question groups across 19 domains.
- Stage 1: complete curriculum with 147 numbered sections.
- Coverage result: 510/510 mapped, 0 unmapped.
- Current ecosystem baseline at the time of research: September 2026.

The inventory is the unit of coverage auditing. The curriculum is the canonical educational scope. Neither may be silently reduced or renumbered.

## Active-recall protocol

Teaching questions reveal their answers immediately because they are the structure of the learning material. For separate active-recall exercises:

1. show only the task first;
2. do not reveal the solution adjacent to the prompt;
3. let the user reason and make mistakes;
4. evaluate conceptual understanding, terminology recall, implementation and communication separately;
5. explain errors and the correct mental model after the attempt;
6. show an idiomatic solution only when appropriate;
7. do not treat a forgotten term as automatic evidence of missing understanding.

## Non-goals

Do not build a web application, dashboard, backend, database, AI-agent system, elaborate automation or separate progress tracker. Git history and Markdown checkboxes are sufficient.

## Source-of-truth precedence

1. Explicit current user instruction.
2. `ROADMAP.md` stage gate.
3. `CURRICULUM.md` educational scope.
4. `research/MASTER_QUESTION_INVENTORY.md` canonical coverage items.
5. `coverage/coverage-map.tsv` traceability.
6. `docs/CONTENT_CONVENTIONS.md` authoring rules.
7. `PROGRESS.md` actual completion state.

## Conditional role tracks

React Native, Angular/Vue/Svelte, deep Node/BFF, WebRTC and graphics-heavy frontend are not part of the current 510-group core. Add them only when a target vacancy justifies a dedicated track.
